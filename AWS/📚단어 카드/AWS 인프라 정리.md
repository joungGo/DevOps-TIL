## 1. AWS 글로벌 인프라란?

AWS는 전 세계에 서버를 두고 클라우드 서비스를 제공합니다. 이 서버들이 어디에, 어떻게 배치되어 있는지를 이해하는 것이 AWS를 제대로 사용하는 첫걸음이에요. 인프라는 크게 5가지 단위로 구성됩니다.

---
## 2. 리전 (Region)

지리적으로 완전히 분리된 AWS 서버 집합입니다. 나라나 도시 단위로 구분되며, 각 리전은 독립적으로 운영돼요.

- 리전 간 자동 복제는 없습니다. 필요하면 직접 설정해야 해요.
- 리전 선택 기준: 고객과의 거리(응답 속도), 법규(데이터 보관 위치), 서비스 가용성
- CLI나 API로 EC2를 조작할 때는 반드시 해당 리전의 엔드포인트를 지정해야 합니다.

---

## 4. 로컬 존 (Local Zone)

리전의 확장으로, 대도시 근처에 AWS 자원을 배치해 사용자와의 거리를 좁히는 구조입니다. 자체 인터넷 연결과 Direct Connect(전용선)를 지원하고, 사용하려면 먼저 활성화(enable) 후 서브넷을 생성해야 합니다. 미디어 스트리밍, 게임, AR/VR처럼 지연이 민감한 서비스에 주로 활용합니다.

---

## 5. 웨이브렝스 존 (Wavelength Zone)

5G 통신사 기지국 바로 옆에 AWS 서버를 배치하여 5G 기기에 초저지연 서비스를 제공하는 구조입니다. 자율주행 자동차, 스마트 공장 실시간 제어, AR 앱처럼 수십 밀리초의 지연도 허용되지 않는 서비스에 활용합니다.

---

## 6. AWS Outposts — 폼 팩터와 두 가지 형태

**폼 팩터(Form Factor)**란 장비의 물리적 크기와 모양을 뜻하는 IT 용어입니다. AWS Outposts는 AWS 물리 장비를 고객 건물에 직접 설치하는 서비스로, 두 가지 폼 팩터로 제공됩니다.

![[Pasted image 20260314221336.png]]
Outposts의 운영·모니터링·관리는 모두 AWS가 전담하고, 인스턴스는 사설 IP로 리전의 VPC와 통신합니다. 주로 법규상 데이터가 외부로 나갈 수 없는 경우(금융, 의료, 공공기관), 또는 공장·연구소처럼 초저지연이 필요한 현장에서 사용합니다.

## 핵심 교훈 한 줄 정리

서버는 반드시 **여러 가용 영역에 분산 배포**하세요. 하나의 AZ에 몰아두면 그 AZ에 장애가 생기는 순간 서비스 전체가 멈춥니다. 이것이 AWS가 말하는 **고가용성(High Availability)** 설계의 핵심입니다. 그리고 영구 보존이 필요한 데이터는 반드시 **EBS 볼륨**에, 빠른 임시 처리는 **인스턴스 스토어**를 활용하세요.
