### S3

- 파일 저장소 (객체 스토리지)
    
- 이미지, 로그, 백업 저장
    
- 디렉토리 개념 없음 (bucket / object)
    

예:

- 업로드 파일 저장
    
- 로그 아카이브
    
- 정적 웹 파일
    

👉 쉽게: **AWS에 있는 파일 서버**

---

### DynamoDB

- NoSQL Key-Value DB
    
- 빠른 조회 (Primary Key 기반)
    
- 서버 관리 없음
    

예:

- 세션 저장
    
- 사용자 설정 저장
    
- 캐시 대체
    

👉 쉽게: **AWS에 있는 빠른 JSON DB**

---

### 주로 어떨 때 사용할까?

대표적으로 **파일 + 메타데이터** 같이 관리할 때  
Amazon S3 + Amazon DynamoDB 조합을 사용합니다.

## 기본 패턴

```
파일 내용 → S3
파일 정보 → DynamoDB
```

예:

```
이미지 파일 → S3
이미지 제목/작성자/시간 → DynamoDB
```

---

## 파일 내용과 파일 정보를 분리하는 이유

1. 저장 비용 최적화
    

- S3: 대용량 파일 저장에 저렴
    
- DynamoDB: 용량 기반 과금 → 파일 저장 시 비용 증가  
    → 파일은 S3에 저장하는 것이 비용 효율적
    

2. 조회 성능 개선
    

- DynamoDB: Key 기반 빠른 조회 가능
    
- S3: 검색/필터 기능 제한적  
    → 메타데이터만 DynamoDB에 저장하면 빠르게 검색 가능
    

3. 역할 분리
    

- S3: 파일 저장 전용
    
- DynamoDB: 인덱스/검색 전용  
    → 각 서비스의 장점만 사용
    

4. 확장성
    

- 파일은 계속 증가
    
- 메타데이터는 비교적 작음  
    → 분리하면 시스템 확장 쉬움

## 사용 케이스

#### 1. 파일 업로드 서비스

- S3 → 이미지 저장
    
- DynamoDB → 사용자ID, 파일URL
    

#### 2. 로그 저장 시스템

- S3 → 로그 원본 파일
    
- DynamoDB → 시간, 서비스명 인덱스
    

#### 3. 문서 관리 시스템

- S3 → PDF 파일
    
- DynamoDB → 제목, 태그, 작성자
    

#### 4. 동영상/이미지 서비스

- S3 → 영상 파일
    
- DynamoDB → 썸네일, 설명, 업로드 시간

### 실제 흐름

```
업로드
User → API → S3 저장
              → DynamoDB 메타 저장

조회
User → API → DynamoDB 조회
            → S3 URL 반환
```

한 줄 정리  
파일은 S3, 검색용 정보는 DynamoDB에 저장하기 위해 분리한다.
