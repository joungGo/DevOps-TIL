> [!note] 면접 답변
> Pod는 IP가 자주 변경되는 리소스이기 때문에 직접 통신하지 않고, 고정된 Virtual IP와 로드밸런싱 기능을 제공하는 Service를 통해 안정적으로 통신합니다.

---
### 왜 Pod끼리는 직접 통신하지 않고 Service를 거칠까

Pod를 직접 호출하지 않는 이유는 크게 3가지다.

1. Pod IP가 계속 바뀐다  
    Pod는 재시작되거나 스케줄링이 변경되면 **IP가 바뀐다.**
    

예

```
Pod A (10.244.1.3)
Pod B (10.244.1.4)
```

Pod A가 죽고 다시 생성되면

```
Pod A (10.244.2.7)
```

이렇게 **IP가 변경된다.**

따라서 다른 서비스가 직접 IP로 호출하면 **연결이 깨진다.**

그래서 **Service가 고정된 주소 역할**을 한다.

---

2. Pod가 여러 개일 수 있다 (로드밸런싱)
    

보통 하나의 서비스는 여러 Pod로 운영된다.

```
Payment Pod 1
Payment Pod 2
Payment Pod 3
```

이때 Service가 요청을 분산한다.

```
Order Pod
   ↓
payment-service
   ↓
Payment Pod 1 / 2 / 3
```

Pod로 직접 접근하면 **로드밸런싱이 불가능하다.**

---

3. Pod 교체와 스케일링이 쉬워진다
    

Pod 수가 변할 수 있다.

예

```
3개 → 10개 (오토스케일링)
```

Service는 **selector로 Pod를 자동으로 찾는다.**

따라서 서비스는 항상 같은 주소로 접근 가능하다.

---

정리

|이유|설명|
|---|---|
|Pod IP 변경|재시작 시 IP 변경|
|로드밸런싱|여러 Pod에 트래픽 분산|
|스케일링|Pod 개수 변화 자동 대응|
