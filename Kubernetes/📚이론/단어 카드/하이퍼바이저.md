## 하이퍼바이저란?

> **하이퍼바이저는 하나의 물리 서버에서 여러 개의 가상 머신(VM)을 실행할 수 있도록  
> 하드웨어 자원을 관리·분배하는 가상화 소프트웨어**이다.

쉽게 말해,  
👉 **물리 하드웨어와 가상 머신 사이의 관리자** 역할을 합니다.

---

## 왜 하이퍼바이저가 필요한가?

물리 서버의 CPU, 메모리, 디스크는 **원래 하나의 OS만 사용**하도록 설계되어 있음  
→ 여러 OS를 동시에 실행하려면 **중간에서 조율하는 계층**이 필요  
→ 그 역할을 하는 것이 **하이퍼바이저**

---

## 하이퍼바이저의 역할

하이퍼바이저는 다음 일을 담당합니다.

### 1️⃣ 자원 가상화

- 물리 CPU → 여러 개의 **가상 CPU**
    
- 물리 메모리 → VM별 **가상 메모리**
    
- 물리 디스크 → **가상 디스크**
    
- 물리 네트워크 → **가상 네트워크**
    

---

### 2️⃣ 자원 분배 및 스케줄링

- 어떤 VM이 CPU를 언제 얼마나 쓸지 결정
    
- 메모리 사용량 관리
    
- 과도한 자원 사용 방지
    

---

### 3️⃣ 격리(Isolation)

- 한 VM에서 장애가 발생해도 다른 VM에는 영향 없음
    
- 보안적으로 VM 간 접근 차단
    

---

### 4️⃣ 하드웨어 제어 대행

- VM은 실제 하드웨어를 직접 제어하지 않음
    
- 하이퍼바이저가 대신 하드웨어와 통신
    

---

## 하이퍼바이저 동작 구조

```
[ 가상 머신 1 ]  [ 가상 머신 2 ]  [ 가상 머신 3 ]
   OS + App        OS + App        OS + App
---------------------------------------------
            하이퍼바이저
---------------------------------------------
          물리 서버 (HW)
```

각 VM은 **자기만의 서버**라고 착각하고 실행됨  
→ 실제 제어는 모두 하이퍼바이저가 수행

---

## 하이퍼바이저의 종류 (매우 중요)

### 🔹 타입 1 하이퍼바이저 native (Bare Metal)

> **하드웨어 위에 직접 설치되는 하이퍼바이저**

- 중간에 호스트 OS 없음
    
- 성능 좋고 안정성 높음
    
- **클라우드, 데이터센터에서 사용**
    

📌 예:

- VMware ESXi
    
- KVM
    
- Xen
    
- Hyper-V (Server)
    

구조:

```
VM
VM
VM
---------
Hypervisor
---------
Hardware
```

---

### 🔹 타입 2 하이퍼바이저 (Hosted)

> **기존 운영체제 위에서 실행되는 하이퍼바이저**

- 개인 PC, 개발·테스트 용도
    
- 성능은 타입 1보다 낮음
    

📌 예:

- VirtualBox
    
- VMware Workstation
    
- Parallels
    

구조:

```
VM
VM
---------
Hypervisor
---------
Host OS
---------
Hardware
```

---

## 클라우드에서 하이퍼바이저는?

- AWS, Azure, GCP 같은 클라우드는
    
    - **타입 1 하이퍼바이저** 사용
        
- 사용자는 하이퍼바이저를 직접 보지 않음
    
- VM 생성 버튼 클릭 → 내부적으로 하이퍼바이저가 VM 생성
    

---

## 한 문장 요약

> **하이퍼바이저는 하나의 물리 서버에서 여러 운영체제를 동시에 실행할 수 있게 해주는  
> 가상화의 핵심 관리자 소프트웨어이다.**
