### 오케스트레이션 (Orchestration)

오케스트레이션은 **여러 개의 서비스, 컨테이너, 서버 자원을 자동으로 배치·실행·확장·복구하도록 관리하는 기술**을 의미합니다.  
특히 MSA와 컨테이너 환경에서 매우 중요한 개념입니다.

---

### 1. 왜 오케스트레이션이 필요한가

예를 들어 MSA 환경에서:

- User Service
    
- Order Service
    
- Payment Service
    
- Product Service
    

각각이 컨테이너로 실행된다고 가정하면 다음 문제가 발생합니다.

- 어떤 서버에 배치할 것인가?
    
- 컨테이너가 죽으면 누가 다시 띄울 것인가?
    
- 트래픽이 증가하면 어떻게 자동 확장할 것인가?
    
- 서비스 간 통신은 어떻게 연결할 것인가?
    

이 문제를 자동으로 해결하는 것이 오케스트레이션입니다.

---

### 2. 대표적인 오케스트레이션 도구

가장 널리 사용되는 도구는 Kubernetes입니다.

- Kubernetes
    
- Google에서 시작되어 CNCF에 기증됨
    

클라우드 환경에서는 다음과 같은 관리형 서비스가 제공됩니다.

- Amazon Web Services EKS
    
- Google Cloud GKE
    
- Microsoft Azure AKS
    

---

### 3. 오케스트레이션이 하는 일

#### 1) 배포 자동화

- 원하는 개수의 컨테이너 실행
    
- 특정 서버에 자동 배치
    

#### 2) 자동 복구 (Self-healing)

- 컨테이너 장애 발생 시 자동 재시작
    
- 노드 장애 시 다른 노드로 재배치
    

#### 3) 자동 확장 (Auto Scaling)

- CPU, 메모리 사용량 기준으로 인스턴스 자동 증가/감소
    

#### 4) 서비스 디스커버리

- 서비스 이름 기반으로 자동 연결
    
- IP 변경에도 자동 추적
    

#### 5) 롤링 업데이트

- 서비스 중단 없이 점진적 배포
    

---

### 4. 단순 비유

- 컨테이너 = 연주자
    
- 서비스 = 악기 파트
    
- 오케스트레이션 = 지휘자
    

각 연주자가 언제 들어오고, 몇 명이 연주하고, 누가 빠졌는지 자동으로 조율합니다.

---

### 5. 오케스트레이션 vs 단순 컨테이너 실행

Docker만 사용하는 경우:

- 컨테이너 실행은 가능
    
- 하지만 확장, 장애 복구, 네트워크 관리 등은 수동 처리
    

Kubernetes 같은 오케스트레이터를 사용하면:

- 전체 시스템을 자동 관리
    
- 대규모 MSA 운영 가능
    

---

### 6. 한 줄 정리

오케스트레이션은 **분산된 컨테이너 기반 시스템을 자동으로 관리하고 조율하는 기술**입니다.  
MSA 환경에서는 사실상 필수 요소로 간주됩니다.

원하시면 Kubernetes 내부 개념(Pod, Service, Deployment 등)까지 구조적으로 설명해 드리겠습니다.
