## 기본 개념

Docker 이미지는 **레이어(layer)** 구조다.

Dockerfile 예:

```dockerfile
FROM python:3.11
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
```

이 명령 하나하나가 **레이어**가 된다.

---

## 캐시는 어떻게 동작하나?

Docker는 빌드할 때:

> 이전에 동일한 명령이 실행된 적이 있으면  
> 그 결과 레이어를 재사용한다.

즉,

- `requirements.txt`가 바뀌지 않으면
    
- `pip install` 레이어는 다시 실행하지 않음
    

그래서 빌드가 빨라진다.

---

## 캐시가 깨지는 경우

- COPY 대상 파일 변경
    
- 명령어 변경
    
- 이전 레이어 변경
    

예:

```dockerfile
COPY . .
RUN pip install -r requirements.txt
```

이렇게 쓰면 코드 한 줄 바뀌어도 `pip install`이 다시 실행된다.

그래서 실무에서는 이렇게 쓴다:

```dockerfile
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
```

이게 이미지 캐시를 고려한 설계다.

---

## 캐시 강제 무시

```bash
docker build --no-cache .
```

# 핵심 차이 요약

|구분|설명|
|---|---|
|도커 엔진|컨테이너 실행하는 런타임|
|이미지 캐시|빌드 속도를 빠르게 하는 레이어 재사용 메커니즘|

---

## 실무 관점에서 중요한 포인트

1. 도커 엔진은 "실행 담당"
    
2. 이미지 캐시는 "빌드 최적화 담당"
    
3. Dockerfile 설계를 잘못하면 빌드 시간이 폭발한다
