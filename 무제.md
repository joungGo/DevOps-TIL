## 메트릭 수집 전체 흐름 (상세)

```
┌─────────────────────────────────────────────────────────────────────┐
│  url-shortener Pod                                                  │
│                                                                     │
│  ┌─────────────────────┐    metrics.py에서 정의한 Counter/Histogram  │
│  │  FastAPI 앱          │ → http_request_total, cache_hit_total 등   │
│  │  + 미들웨어          │                                            │
│  └──────────┬──────────┘                                            │
│             │ prometheus_client가 메모리에 보관                       │
│  ┌──────────▼──────────┐                                            │
│  │  GET /metrics/       │ ← Prometheus가 30초마다 여기를 호출         │
│  └─────────────────────┘                                            │
└─────────────────────────────────────────────────────────────────────┘
          ▲ scrape (HTTP GET)
          │
          │  "어디를 수집해야 하는지" 알려주는 게 ServiceMonitor
          │
┌─────────┴──────────────────────────────────────────────────────────┐
│  ServiceMonitor (url-shortener namespace)                          │
│                                                                    │
│  spec:                                                             │
│    selector:                                                       │
│      matchLabels:                                                  │
│        app: url-shortener-api   ← 이 라벨을 가진 Service를 찾음    │
│    endpoints:                                                      │
│      - port: http               ← Service의 'http' 포트 사용       │
│        path: /metrics           ← 이 경로를 scrape                 │
│        interval: 30s            ← 30초마다                         │
│    namespaceSelector:                                              │
│      matchNames: [url-shortener]                                   │
└─────────┬──────────────────────────────────────────────────────────┘
          │ Prometheus Operator가 감지
          │
┌─────────▼──────────────────────────────────────────────────────────┐
│  Prometheus Operator (monitoring namespace)                        │
│                                                                    │
│  - 클러스터의 ServiceMonitor를 watch                               │
│  - ServiceMonitor 발견 → Prometheus 설정 자동 업데이트             │
│  - prometheus/values.yaml의 이 설정으로 모든 namespace 감지:       │
│      serviceMonitorSelector: {}          ← 라벨 무관 전체 선택     │
│      serviceMonitorNamespaceSelector: {} ← 모든 namespace 허용     │
└─────────┬──────────────────────────────────────────────────────────┘
          │ 설정 반영
          │
┌─────────▼──────────────────────────────────────────────────────────┐
│  Prometheus (StatefulSet)                                          │
│                                                                    │
│  - ServiceMonitor 기반으로 scrape target 목록 관리                 │
│  - 30초마다 url-shortener Pod의 /metrics/ 호출                     │
│  - 수집 시 target 레이블 자동 추가:                                │
│      namespace="url-shortener"   ← 이게 자동으로 붙음             │
│      pod="url-shortener-api-xxx"                                   │
│      job="url-shortener-svc"                                       │
│  - 데이터를 시계열 DB에 저장                                       │
└─────────┬──────────────────────────────────────────────────────────┘
          │ PromQL 쿼리
          │
┌─────────▼──────────────────────────────────────────────────────────┐
│  Grafana                                                           │
│  sum(rate(http_request_total{namespace="url-shortener"}[5m]))      │
└────────────────────────────────────────────────────────────────────┘
```

## 오늘 발생했던 문제들

**문제 1: namespace 레이블로 필터링이 안 됨**

```
# 앱이 노출하는 메트릭 (app 자체 레이블)
http_request_total{method="GET", path="/items", status_code="200"}

# Prometheus가 scrape 시 자동으로 추가하는 레이블
+ namespace="url-shortener"
+ pod="url-shortener-api-xxx"
+ job="url-shortener-svc"

# 최종적으로 저장되는 형태
http_request_total{method="GET", path="/items", status_code="200",
                   namespace="url-shortener", pod="...", job="..."}
```

→ `namespace` 레이블은 앱이 아니라 **Prometheus가 scrape 시 붙여주는 것**. 근데 실제 조회해보니 Target은 UP이고 레이블도 붙어 있었는데 결과가 비어있었던 건 **문제 2** 때문.

---

**문제 2: 500 에러가 메트릭에 안 잡힘**

FastAPI 미들웨어 실행 순서:

```
[요청 들어옴]
       ↓
ServerErrorMiddleware   ← 맨 바깥 (Starlette가 자동 추가)
       ↓
record_http_metrics     ← @app.middleware("http")로 추가한 것
       ↓
ExceptionMiddleware     ← FastAPI 예외 핸들러
       ↓
Router → /error-test → raise Exception("...")
```

```
[예외 발생 시 흐름]
raise Exception
       ↑ 전파
ExceptionMiddleware → 처리 못 함, 재전파
       ↑ 전파
record_http_metrics의 call_next()에서 예외 발생
→ response를 못 받음 → 500 카운트 불가
       ↑ 전파
ServerErrorMiddleware → 500 응답 반환

[HTTPException(500) 발생 시 흐름]
raise HTTPException(status_code=500)
       ↑ 전파
ExceptionMiddleware → 처리함 → 500 response 반환
       ↑ response 반환
record_http_metrics → response.status_code == 500 → 카운트 ✅
```

→ **`raise Exception`은 미들웨어를 우회하고, `raise HTTPException`은 미들웨어가 잡는다.**

## 전체 구성 요소 한눈에

| 구성 요소                 | 역할                                      | 위치                      |
| --------------------- | --------------------------------------- | ----------------------- |
| `metrics.py`          | Counter/Histogram 정의                    | url-shortener 앱 코드      |
| `main.py middleware`  | 모든 요청마다 카운터 증가                          | url-shortener 앱 코드      |
| `/metrics/` 엔드포인트     | 현재 메트릭 값 HTTP로 노출                       | url-shortener Pod       |
| `ServiceMonitor`      | "이 Service를 수집해라" 선언                    | url-shortener namespace |
| `Prometheus Operator` | ServiceMonitor 감지 → Prometheus 설정 자동 반영 | monitoring namespace    |
| `Prometheus`          | 30초마다 pull, 시계열 저장                      | monitoring namespace    |
| `Grafana`             | PromQL로 시각화                             | monitoring namespace    |
