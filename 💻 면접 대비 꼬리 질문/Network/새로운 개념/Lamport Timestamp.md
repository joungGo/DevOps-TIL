## 1️⃣ 왜 이런 게 필요할까?

분산 시스템에서는

- 전역 시계 ❌
    
- 각 노드의 실제 시간도 안 맞음 ❌
    

그래서 **시간(time)** 대신 **논리적 순서(order)** 로 이벤트를 정해야 해.

👉 목표

> “이 이벤트가 다른 이벤트보다 **원인적으로 먼저(happened-before)** 발생했는가?”

---

## 2️⃣ Lamport Timestamp (논리 시계)

### 🔹 핵심 아이디어

> **숫자 하나로 이벤트의 순서를 표현**

각 프로세스는 **정수 카운터 하나**만 들고 있음.

---

### 🔹 규칙

각 프로세스 Pi 는 `Li`라는 카운터를 가짐.

1. **로컬 이벤트 발생**
    
    ```
    Li = Li + 1
    ```
    
2. **메시지 전송**
    
    - 현재 `Li` 값을 메시지에 실어서 보냄
        
3. **메시지 수신**
    
    ```
    Li = max(Li, Lmsg) + 1
    ```
    

---

### 🔹 예시

- P1에서 이벤트 A 발생 → `L=1`
    
- P1이 메시지 전송 → 메시지에 `1`
    
- P2가 메시지 수신 (자기 값 0)
    
    ```
    L2 = max(0, 1) + 1 = 2
    ```
    

➡ **A → 메시지 수신** 순서 보장됨

---

### 🔹 장점

- 구현 매우 쉬움
    
- 메시지 크기 작음 (정수 1개)
    
- **happened-before 관계를 보존**
    
    ```
    a → b  ⇒  L(a) < L(b)
    ```
    

---

### 🔹 한계 (중요 ❗)

❌ **동시성(concurrency)을 구분 못함**

[[분산 시스템에서의 동시성이란]]

- `L(a) < L(b)` 라고 해서  
    👉 **a가 b의 원인이라고는 말할 수 없음**
    

즉,

```
L(a) < L(b)
BUT a || b (서로 독립)
```

그래서 **“순서만 강제로 만들 뿐, 정확한 인과관계는 모름”**

---

## 3️⃣ Vector Clock (벡터 시계)

### 🔹 핵심 아이디어

> **각 프로세스의 시간을 전부 기록해서 인과관계를 정확히 표현**

프로세스 수가 N이면  
👉 시계는 **N차원 벡터**

```
VC = [v1, v2, ..., vN]
```

---

### 🔹 규칙

프로세스 Pi 기준

1. **로컬 이벤트**
    
    ```
    VC[i]++
    ```
    
2. **메시지 전송**
    
    - VC 전체를 메시지에 포함
        
3. **메시지 수신**
    
    ```
    VC[j] = max(VC[j], VCmsg[j]) for all j
    VC[i]++
    ```
    

---

### 🔹 예시 (P1, P2)

초기 상태

```
P1: [0,0]
P2: [0,0]
```

P1에서 이벤트 A

```
P1: [1,0]
```

P1 → P2 메시지 전송

P2 수신

```
max([0,0], [1,0]) = [1,0]
P2 증가 → [1,1]
```

➡ **정확히 A → 수신 이벤트**

---

### 🔹 이벤트 비교 방법

두 이벤트 a, b의 벡터 Va, Vb

- **a → b**
    
    ```
    Va ≤ Vb  AND  ∃j: Va[j] < Vb[j]
    ```
    
- **동시(concurrent)**
    
    ```
    Va ≰ Vb  AND  Vb ≰ Va
    ```
    

👉 이게 Lamport와의 결정적 차이

---

### 🔹 장점

✅ **정확한 인과관계 표현**  
✅ **동시성 판별 가능**

---

### 🔹 단점

❌ 메시지 크기 큼 (노드 수만큼)  
❌ 노드 수가 많아지면 부담 ↑

---

## 4️⃣ Lamport vs Vector Clock 한눈에 비교

|항목|Lamport Timestamp|Vector Clock|
|---|---|---|
|시계 형태|정수 1개|N차원 벡터|
|구현 난이도|매우 쉬움|상대적으로 복잡|
|메시지 크기|작음|큼|
|happened-before 보존|O|O|
|동시성 판별|❌ 불가|✅ 가능|
|인과관계 정확성|약함|강함|

---

## 5️⃣ 언제 뭘 쓰나?

### ✔ Lamport Timestamp

- **총순서(total order)** 가 필요할 때
    
- 분산 로그 정렬
    
- 분산 락, 이벤트 정렬
    

### ✔ Vector Clock

- **충돌 감지**
    
- 분산 DB 버전 관리
    
- Git, Dynamo-style 시스템
    
- “누가 누구에 의해 발생했는지”가 중요한 경우
    

---

## 6️⃣ 한 문장 요약

- **Lamport Timestamp**  
    👉 “순서는 만든다, 하지만 이유는 모른다”
    
- **Vector Clock**  
    👉 “순서 + 인과관계 + 동시성까지 정확히 안다”
    

원하면 다음으로

- happened-before 관계를 그림으로 설명
    
- 분산 DB에서 실제로 어떻게 쓰이는지
    
- Lamport로 total order 만드는 트릭
    

이 중 하나 골라줘 👀
