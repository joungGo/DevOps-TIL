### 답변
멀티스레딩과 멀티프로세싱의 차이는 **주소 공간 공유 여부**에서 시작됩니다.

먼저, **멀티스레딩**입니다.

- 하나의 프로세스 내에서 여러 스레드가 실행됩니다.
    
- **코드, 힙, 전역 변수 영역을 공유**합니다.
    
- 각 스레드는 **자기만의 스택만 독립적으로** 가집니다.
    

메모리 관리 특징은  
공유 메모리 기반이므로 데이터 전달이 빠르고, 컨텍스트 스위칭 비용이 낮습니다.  
하지만 동기화가 필요하며, 레이스 컨디션과 데드락 위험이 존재합니다.

장애 전파 특성은  
한 스레드에서 세그먼트 폴트나 힙 오염이 발생하면  
**프로세스 전체가 종료됩니다.**  
즉, 격리가 없습니다.

다음은 **멀티프로세싱**입니다.

- 각 프로세스는 **독립된 주소 공간**을 가집니다.
    
- 페이지 테이블도 완전히 분리됩니다.
    
- 메모리 공유가 필요하면 IPC나 공유 메모리(`mmap`, shm)를 사용합니다.
    

메모리 관리 특징은  
주소 공간이 격리되어 안정성이 높습니다.  
하지만 IPC 비용과 컨텍스트 스위칭 비용이 더 큽니다.

장애 전파 특성은  
한 프로세스가 크래시해도 다른 프로세스에는 직접 영향이 없습니다.  
운영체제가 격리를 보장합니다.

### 꼬리질문: 멀티스레딩 환경에서 발생할 수 있는 레이스 컨디션과 데드락의 구체적인 예시를 들어 설명해주세요.
먼저 **레이스 컨디션**입니다.

예를 들어, 두 개의 스레드가 동시에 하나의 전역 변수 `count`를 증가시킨다고 가정하겠습니다.

`count++` 연산은 실제로는

1. 값 읽기
    
2. 1 증가
    
3. 다시 저장  
    의 세 단계로 이루어집니다.
    

두 스레드가 동시에 실행되면,  
둘 다 같은 값을 읽고 각각 1을 더한 뒤 저장할 수 있습니다.  
그 결과 증가가 한 번만 반영됩니다.

즉, 실행 순서에 따라 결과가 달라지는 상태가 레이스 컨디션입니다.  
해결 방법은 mutex, atomic 연산 등으로 임계 구역을 보호하는 것입니다.

다음은 **데드락**입니다.

예를 들어,

- 스레드 A는 Lock1을 획득한 뒤 Lock2를 기다리고,
    
- 스레드 B는 Lock2를 획득한 뒤 Lock1을 기다리는 상황입니다.
    

서로 상대가 가진 락을 기다리면서  
영원히 진행하지 못하는 상태가 됩니다.

이는

1. 상호 배제
    
2. 점유 대기
    
3. 비선점
    
4. 순환 대기  
    조건이 모두 충족될 때 발생합니다.
    

해결 방법은  
락 획득 순서를 통일하거나,  
타임아웃이나 데드락 탐지 기법을 사용하는 것입니다.

정리하면,

- 레이스 컨디션은 동기화 부족으로 인한 데이터 불일치 문제이고,
    
- 데드락은 잘못된 자원 획득 순서로 인한 무한 대기 상태입니다.
