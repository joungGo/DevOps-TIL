### 멀티스레딩 vs 멀티프로세싱

- 현대 하드웨어 환경에서는 프로세스 단위 관리가 운영 측면에서 더 유리함
- 디버깅이 쉽고 안정성이 높음
- 스레드 직접 관리는 디버깅이 매우 어려움

### 프로세스 개념 복습

- **Fork 시스템콜**: 자식 프로세스를 생성하는 함수
- **Copy-on-Write**: 초기에는 부모와 자식이 물리 메모리를 read-only로 공유하다가, 쓰기 작업 시 페이지 폴트 발생하여 해당 데이터만 복사
- **Pthread**: 스레드 생성 시 동일 프로세스 내에서 메모리 공유, fork보다 오버헤드가 적음

### Linux 시스템 이해

- **PS 커맨드**: `/proc` 가상 디렉토리에서 프로세스 정보를 가져옴
- **메모리 구조**: 코드, 데이터(전역변수), 스택(함수 지역변수, 리턴값), 힙(동적 할당) 영역으로 구성
- 이 부분은 면접 단골 질문이므로 복습 필요

### Java 가비지 컬렉션

- **Young Generation**: Eden 영역에 새 객체 생성, Minor GC 실행 시 Survivor 0/1 영역으로 이동하며 age bit 증가
- **Old Generation**: age bit가 특정 횟수(기본 15회)를 초과하면 이동
- **GC Root**: JVM Stack의 로컬 변수, 활성 스레드, static 변수 등을 기준으로 참조 여부 판단
- Mark and Sweep 방식으로 살아있는 객체 구별

### 메모리 관련 이슈

- **Stack Overflow**: 무한 재귀 호출 시 발생
- **메모리 누수**: 자식 프로세스 종료 후 부모가 회수하지 않으면 발생, OOM으로 이어질 수 있음
- **고아 프로세스**: 부모가 먼저 종료되어 회수되지 못한 자식 프로세스, init 프로세스가 주기적으로 정리
- **Linux 메모리 캐싱**: 남는 메모리를 캐시로 사용하여 성능 향상, 정상적인 동작

### 모니터링 및 운영

- **Prometheus**: 메트릭 수집 및 저장 시스템
- 여러 서버에서 Exporter가 메트릭을 수집하여 중앙 Prometheus에 전송
- **Threshold**: 알람 기준선 설정, 가용성 목표(99.9% 등)에 따라 결정
- 메모리보다 CPU 지표로 부하 및 장애를 모니터링하는 것이 일반적
