## Aurora vs 일반 RDS 스토리지 구조

---

### 일반 RDS 구조

```
Primary 인스턴스
  └─ 전용 EBS 볼륨 (예: 100GB)

Replica 인스턴스
  └─ 전용 EBS 볼륨 (예: 100GB)   ← Primary와 별도 디스크
       ↑
       WAL 스트리밍으로 계속 동기화
```

- 각 인스턴스가 **각자의 디스크**를 가짐
- Primary가 쓴 데이터를 WAL로 Replica에 전송 → Replica가 자기 디스크에 재실행
- Replica 수만큼 **스토리지 비용 곱하기**
- Replication Lag 존재 (네트워크 + 재실행 시간)

---

### Aurora 구조

```
Primary 인스턴스 ─────────────────────────────────────────┐
Replica 인스턴스 1 ───────────────────────────────────────┤
Replica 인스턴스 2 ───────────────────────────────────────┤→ 공유 분산 스토리지 (Aurora Storage)
Replica 인스턴스 3 ───────────────────────────────────────┘
                                      │
                        3개 AZ × 2개 복사본 = 6중 복제
```

- 모든 인스턴스가 **하나의 스토리지를 공유**
- Primary가 쓰면 → Replica는 같은 스토리지를 읽기만 함
- WAL 전송/재실행 없음 → **Replication Lag 거의 0** (수 ms)
- 스토리지는 인스턴스 수와 무관하게 **1벌만 과금**

---

### 차이 비교

|항목|일반 RDS|Aurora|
|---|---|---|
|스토리지 구조|인스턴스별 독립 EBS|전체 공유 분산 스토리지|
|Replica 동기화 방식|WAL 스트리밍 + 재실행|공유 스토리지 직접 읽기|
|Replication Lag|수 ms ~ 수백 ms|수 ms 이하|
|최대 Replica 수|5개|15개|
|스토리지 비용|Replica 수만큼 증가|인스턴스 수 무관, 1벌|
|스토리지 자동 확장|수동 설정 필요|자동 (10GB 단위 증가)|
|가격|상대적으로 저렴|일반 RDS 대비 약 20% 비쌈|

---

### 한 줄 요약

> **일반 RDS는 데이터를 복사해서 각자 보관, Aurora는 하나의 데이터를 다같이 바라봄.**
