
**1. Terraform apply**

```bash

```

**2. kubeconfig 업데이트**

EKS 클러스터가 새로 생성되면 API Endpoint 주소가 새로 바뀜. 그래서 아래 명령어를 통해 이전 주소를 가리키고 있는 kubeconfig 내용을 업데이트 해야 함.

```bash
aws eks update-kubeconfig --region ap-northeast-2 --name urlshortener
```

**3. ALB Controller 설치**

ALB Controller의 **IRSA 역할(IAM Role)**은 Terraform으로 생성되지만, **ALB Controller 자체 설치(Helm)**는 Terraform으로 하지 않고 직접 합니다.

```bash
kubectl apply -f cluster-addons/alb-controller/application.yaml

# Pod 재시작 확인 (1-2분 소요)
kubectl get pods -n kube-system -l app.kubernetes.io/name=aws-load-balancer-controller -w
```


```bash
helm repo add eks https://aws.github.io/eks-charts
helm repo update

CLUSTER_NAME=$(cd /Users/jounghyeon/개발/Url-Shortener-EKS-Platform/terraform && terraform output -raw eks_cluster_name)
ALB_ROLE_ARN=$(cd /Users/jounghyeon/개발/Url-Shortener-EKS-Platform/terraform && terraform output -raw alb_controller_role_arn)

helm upgrade aws-load-balancer-controller eks/aws-load-balancer-controller \
  -n kube-system \
  --set clusterName=urlshortener \
  --set serviceAccount.create=true \
  --set serviceAccount.name=aws-load-balancer-controller \
  --set "serviceAccount.annotations.eks\.amazonaws\.com/role-arn=$(cd terraform && terraform output -raw alb_controller_role_arn)" \
  --set region=ap-northeast-2 \
  --set vpcId=$(cd terraform && terraform output -raw vpc_id)
```

**9. Karpenter 설치** (eksctl로 노드 Role 등록 후)

```bash
eksctl create iamidentitymapping \
  --cluster urlshortener \
  --region ap-northeast-2 \
  --arn "$(cd terraform && terraform output -raw karpenter_node_role_arn)" \
  --group system:bootstrappers,system:nodes \
  --username system:node:{{EC2PrivateDNSName}}

kubectl apply -f cluster-addons/karpenter/application.yaml

# ARN 조회 명령어
terraform -chdir=/Users/jounghyeon/개발/Url-Shortener-EKS-Platform/terraform output -raw karpenter_controller_role_arn
```

# 전체 인프라 정리

## 1단계: Karpenter 노드 정리

```
# Karpenter가 만든 노드 먼저 제거 (안하면 terraform destroy 시 꼬임)kubectl delete nodepool defaultkubectl delete ec2nodeclass default
```

## 2단계: ArgoCD Application 삭제

```
# ArgoCD가 리소스를 재생성하지 못하도록 먼저 삭제kubectl delete -f url-shortener/k8s/argocd/application.yamlkubectl delete -f cluster-addons/karpenter/application.yamlkubectl delete -f cluster-addons/metric-server/application.yaml
```

## 3단계: ALB (Ingress) 삭제

```
# ALB Controller가 만든 로드밸런서 삭제 (terraform destroy 전에 해야 함)kubectl delete ingress -n url-shortener --allkubectl delete ingress -n argocd --all
# ALB가 실제로 삭제될 때까지 대기 (30초~1분)sleep 30
```

## 4단계: ALB Controller 삭제

```
helm uninstall aws-load-balancer-controller -n kube-system
```

## 5단계: terraform destroy

```
cd terraformterraform destroy -auto-approve
```

---

> **주의**: 3단계(Ingress 삭제)를 건너뛰면 AWS에 ALB가 남아서 과금이 계속됩니다. terraform destroy로도 안 지워집니다.
