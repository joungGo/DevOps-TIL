## 🔹 전체 구조 핵심 문장

> **가상 머신은 안에서만 존재하고,  
> 밖으로 나갈 때는 반드시 “호스트 + NAT”를 거친다**

여기서 “안”은:

- VMware 가상 네트워크
    
- 192.168.111.0/24 대역
    

---

## 🔹 ① 가상 머신 내부 통신 흐름 (VM ↔ VM)

예:

`Server(A) → Server(B) 192.168.111.100 → 192.168.111.200`

처리 흐름:

```md
[Server A]
   ↓
[VMware 가상 스위치]
   ↓
[Server B]
```

✔ 특징

- 게이트웨이 ❌
    
- NAT ❌
    
- 호스트 ❌
    
- **완전 내부 통신**
    
- 실제 네트워크 카드 사용 ❌
    

👉 진짜 스위치처럼 동작

---

## 🔹 ② 가상 머신 → 게이트웨이 (외부 통신 시작)

예:

`ping 8.8.8.8`

VM 판단:

- 목적지 IP가 `192.168.111.0/24` 밖이다
    
- → 게이트웨이로 보낸다
    

```md
[VM]
   ↓
[게이트웨이 / DNS 192.168.111.2]
```

---

## 🔹 ③ NAT 처리 (가장 핵심)

게이트웨이(192.168.111.2)의 역할:

### NAT 변환 전

```md
출발지: 192.168.111.101 
목적지: 8.8.8.8
```

### NAT 변환 후

```md
출발지: 호스트의 실제 IP (예: 10.0.0.5)
목적지: 8.8.8.8
```

✔ 외부에서는:

- 가상 머신 IP **전혀 모름**
    
- 호스트 PC가 요청한 것처럼 보임
    

👉 이것이 **“안에서만 존재”**의 진짜 의미

---

## 🔹 ④ 호스트 네트워크 카드 → 인터넷

```md
[VMware NAT]
   ↓
[호스트 OS 192.168.111.1]
   ↓
[실제 네트워크 카드]
   ↓
[인터넷]
```

- 회사 네트워크
    
- 집 공유기
    
- 공공 Wi-Fi
    

어디든 동일하게 동작

---

## 🔹 ⑤ 응답이 돌아오는 흐름

```
[인터넷 서버]
   ↓
[호스트 실제 IP]
   ↓
[NAT 테이블 확인]
   ↓
[192.168.111.101 VM]
```

✔ VMware는:

- “이 응답은 어느 VM 요청이었지?”
    
- NAT 테이블로 정확히 되돌려줌
    

---

## 🔹 그림 기준 핵심 요약

|구분|의미|
|---|---|
|192.168.111.1|호스트 OS|
|192.168.111.2|VMware 가상 게이트웨이 + DNS|
|192.168.111.254|VMware DHCP 서버|
|VM IP들|**안에서만 존재**|
|외부 인터넷|VM 존재 모름|
