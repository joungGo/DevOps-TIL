# MMIO (Memory-Mapped I/O)

MMIO는 **장치 레지스터를 메모리 주소 공간에 매핑해서 접근하는 방식**이다.

>MMIO 구조를 사용해서 다비이스 레지스터에 접근

즉,

```
장치 레지스터 ↔ 메모리 주소
```

처럼 연결해두고,  
CPU가 **일반 메모리 접근(load/store)** 하듯이 장치를 제어한다.

---

# 1. 왜 필요한가?

CPU가 장치와 통신하려면:

- 장치에 명령 전달
    
- 상태 확인
    
- 데이터 읽기/쓰기
    

가 필요하다.

이걸 두 가지 방식으로 할 수 있다:

1. Port-mapped I/O (별도 I/O 명령어 사용)
    
2. MMIO (메모리처럼 접근)
    

리눅스와 대부분의 현대 시스템은 **MMIO 방식이 주류**다.

---

# 2. 동작 구조

예를 들어,

어떤 장치의 제어 레지스터가 물리 주소:

```
0xF0001000
```

에 매핑되어 있다면,

CPU는 그냥 이렇게 접근한다:

```
*(volatile unsigned int*)0xF0001000 = 1;
```

이 코드는:

- 메모리에 쓰는 게 아니라
    
- 장치 레지스터에 명령을 쓰는 것
    

이다.

---

# 3. 구조 흐름

```
프로세스
   ↓
시스템콜
   ↓
커널
   ↓
MMIO 주소 접근
   ↓
장치 레지스터
   ↓
하드웨어 동작
```

---

# 4. MMIO의 핵심 특징

### 1) 일반 메모리 명령어 사용

- load
    
- store
    

→ 별도의 I/O 명령어 필요 없음

---

### 2) 캐시 사용 금지

장치 레지스터는 캐시되면 안 된다.

왜냐하면:

- 장치 상태가 실시간으로 바뀜
    
- 캐시되면 최신 상태를 못 읽음
    

그래서 MMIO 영역은 보통:

- non-cacheable
    
- strongly ordered
    

속성으로 설정한다.

---

### 3) volatile 필수

컴파일러 최적화 방지를 위해:

```
volatile
```

을 사용한다.

안 그러면 컴파일러가:

"값이 안 바뀌네?"  
하고 접근을 제거해버릴 수 있다.

---

# 5. MMIO vs Port-mapped I/O

|구분|MMIO|Port I/O|
|---|---|---|
|접근 방식|메모리처럼 접근|전용 I/O 명령어|
|명령어|load/store|in/out|
|주소 공간|메모리 공간 사용|별도 I/O 공간|
|현대 시스템|대부분 사용|거의 사용 안함|

---

# 6. 멀티코어 환경에서 중요한 점

MMIO는 단순 메모리가 아니다.

따라서:

- 메모리 배리어 필요
    
- 순서 보장 필요
    

예:

```
write command
memory barrier
read status
```

이 순서가 보장되어야 한다.
