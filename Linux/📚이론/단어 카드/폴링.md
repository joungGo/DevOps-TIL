# 폴링 (Polling)

폴링은  
**CPU가 장치의 상태 레지스터를 직접 읽어 완료 여부를 확인하는 방식**이다.

CPU가 능동적으로 상태를 확인한다.

---

# 1. 기본 폴링 (Busy Polling)

가장 단순한 방식은 **연속적으로 상태를 확인**하는 것이다.

```
while (status_register != DONE) {
    계속 읽기
}
```

구조:

```
CPU
  ↓ (반복적으로 상태 읽기)
장치 상태 레지스터
  ↓
완료되면 루프 탈출
```

### 특징

- CPU가 루프를 빠져나가지 않고 계속 확인
    
- 가장 빠르게 완료를 감지 가능
    
- CPU 자원을 계속 점유함
    

이를 **Busy Waiting** 또는 **Busy Polling**이라고 한다.

---

# 2. 주기적 폴링 (Interval / Timed Polling)

CPU가 무한 루프 대신  
**일정한 간격을 두고 상태를 확인하는 방식**이다.

예:

```
while (status_register != DONE) {
    sleep(1ms);
}
```

또는

```
타이머 발생 → 상태 확인 → 다시 대기
```

### 동작 구조

```
CPU
  ↓
일정 시간 대기
  ↓
상태 레지스터 확인
  ↓
완료 여부 판단
```

---

# 3. 왜 복합 폴링을 쓰는가?

기본 폴링은 CPU를 계속 점유한다는 단점이 있다.

주기적 폴링은 다음을 개선한다:

- CPU 점유율 감소
    
- 전력 소모 감소
    
- 다른 작업 수행 가능
    

하지만 단점도 있다:

- 확인 주기가 길면 지연 발생
    
- 너무 짧으면 Busy Polling과 차이 없음
    

즉, **응답 속도와 CPU 사용률 사이의 트레이드오프**가 존재한다.

---

# 4. 두 방식 비교

|구분|Busy Polling|주기적 Polling|
|---|---|---|
|확인 방식|계속 반복|일정 간격|
|CPU 사용률|매우 높음|조절 가능|
|응답 속도|가장 빠름|주기에 따라 달라짐|
|구현 난이도|단순|약간 복잡|

---

# 5. 언제 사용되는가?

- 매우 짧은 작업 (마이크로초 단위)
    
- 지연(latency)이 중요한 상황
    
- 고성능 네트워크 처리
    
- 커널 내부 동기화 구간
    

주기적 폴링은:

- 센서 확인
    
- 임베디드 시스템
    
- 타이머 기반 상태 점검
    

같은 상황에서 자주 사용된다.

---

# 6. 한 줄 요약

폴링은 CPU가 장치 상태를 직접 확인하는 방식이며,  
연속적으로 확인하는 Busy Polling과 일정 간격을 두는 주기적 Polling 방식이 있다.
