# Btrfs가 제공하는 파일 시스템 고급 기능

ext4, XFS는 기본적인 기능을 제공하는 전통적인 파일 시스템이고,  
**Btrfs는 추가적인 고급 기능을 제공하는 파일 시스템**입니다.

대표적인 기능이 바로 **스냅샷(Snapshot)** 입니다.

---

# 스냅샷(Snapshot)이란?

Btrfs는 파일 시스템의 특정 시점 상태를 그대로 보존하는  
**스냅샷 기능을 제공**합니다.

### 🔹 특징

- 파일 시스템 전체를 복사하지 않음
    
- **데이터와 메타데이터를 참조만 공유**
    
- Copy-on-Write 방식 사용
    
- 생성 속도가 매우 빠름
    
- 저장 공간을 적게 사용
    

즉, 일반적인 복사보다 훨씬 효율적입니다.

---

# 스냅샷의 동작 원리

스냅샷은

- 기존 파일 시스템과 데이터를 공유
    
- 변경이 발생할 때만 새로운 블록을 기록
    

즉,

- 기존 데이터는 그대로 유지
    
- 변경된 데이터만 새로 저장
    

→ 공간 효율 극대화

---

# 스냅샷 ≠ 백업

사진에서 가장 강조하는 부분입니다.

스냅샷은 백업 목적의 기능이 아닙니다.

왜냐하면:

- 스냅샷은 **같은 파일 시스템 내부에 존재**
    
- 원본 파일 시스템에 문제가 생기면
    
- 스냅샷 데이터도 함께 영향을 받을 수 있음
    

즉,

> 스냅샷은 보호 기능이 아니라 “시점 보존 기능”

---
# 스냅샷에서의 백업

스냅샷을 작성하는 짧은 시간 동안만 입출력을 멈추고 그후에는 스냅샷을 사용해서 백업을 만든다면 파일 시스템 본체의 입출력을 멈추지 않아도 되므로 더 빠른 백업이 가능합니다.

---
# 백업과 스냅샷의 차이

## 1️⃣ 백업

- 데이터를 **다른 저장 위치에 복사**
    
- 원본과 완전히 독립
    
- 장애 발생 시 복구 목적
    
- 파일 시스템 입출력을 멈추고 작업해야 하는 경우가 많음
    

---

## 2️⃣ 스냅샷

- 같은 파일 시스템 내부에서 생성
    
- 데이터 공유
    
- 입출력을 멈추지 않고 생성 가능
    
- 빠르고 공간 효율적
    
- 파일 시스템 기능의 일부
    

---

# 백업 vs 스냅샷 핵심 비교

|구분|스냅샷|백업|
|---|---|---|
|저장 위치|동일 파일 시스템|별도 저장소|
|공간 사용|변경분만 저장|전체 복사|
|생성 속도|매우 빠름|상대적으로 느림|
|목적|시점 상태 보존|장애 복구|
|안전성|파일 시스템 장애 시 함께 손상 가능|독립적이라 안전|

---

# 결론

- 스냅샷은 파일 시스템 수준 기능
    
- Copy-on-Write 기반
    
- 빠른 시점 보존에 적합
    
- 백업을 대체하지 못함
    
- 안전한 복구를 위해서는 **별도의 백업이 반드시 필요**
