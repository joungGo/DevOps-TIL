리눅스 애플리케이션 공급망은  
**소스 코드가 작성되어 사용자 시스템에 설치·실행되기까지의 전체 경로**를 의미한다.

즉,

```text
개발 → 빌드 → 패키징 → 저장소 → 배포 → 설치 → 실행
```

이 모든 과정이 공급망이다.

---

# 1. 개발 단계

- 개발자가 코드 작성
    
- Git 저장소에 관리 (GitHub, GitLab 등)
    
- 외부 라이브러리 의존성 포함
    

이 시점부터 공급망 위험이 시작된다.

---

# 2. 빌드 단계

- 컴파일
    
- 바이너리 생성
    
- 의존성 링크
    

자동화 도구:

- Make
    
- CMake
    
- CI/CD 파이프라인
    

여기서 악성 코드가 삽입될 가능성 존재.

---

# 3. 패키징 단계

리눅스는 보통 패키지 형태로 배포된다.

대표 형식:

- `.deb` (Debian, Ubuntu)
    
- `.rpm` (RHEL, Fedora)
    

패키지에는 다음이 포함된다:

- 실행 파일
    
- 설정 파일
    
- 의존성 정보
    
- 설치 스크립트
    

---

# 4. 패키지 저장소

배포판 공식 저장소에 업로드된다.

예:

- Ubuntu apt repository
    
- Red Hat yum/dnf repository
    

사용자는 여기서 설치한다.

```bash
apt install nginx
```

---

# 5. 배포 및 설치

- 패키지 매니저가 다운로드
    
- 서명 검증
    
- 의존성 해결
    
- 파일 배치
    

이 단계에서 신뢰 체인이 중요하다.

---

# 6. 실행 및 업데이트

- systemd가 서비스 실행
    
- 보안 업데이트 제공
    
- 패치 배포
    

---

# 7. 왜 공급망이 중요한가

최근 보안 위협은:

- 개발 단계 침해
    
- 의존성 패키지 오염
    
- 빌드 서버 공격
    
- 저장소 위변조
    

즉,

> 사용자가 직접 악성 코드를 설치하지 않아도 감염될 수 있다.

---

# 8. 리눅스 공급망의 신뢰 구조

리눅스는 다음으로 신뢰를 유지한다.

- GPG 서명
    
- 패키지 무결성 검증
    
- 공식 저장소 운영
    
- 재현 가능한 빌드
    

---

# 한 줄 정리

리눅스 애플리케이션 공급망은 개발부터 빌드, 패키징, 저장소 배포, 사용자 설치까지 이어지는 전체 유통 경로이며, 이 모든 단계가 보안적으로 신뢰되어야 시스템 안전이 보장된다.
