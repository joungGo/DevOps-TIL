# 프로세스 생성과 프로그램 실행: fork()와 execve(), 그리고 시스템 콜 래퍼 함수

## 1. 프로세스 생성: fork()

### fork()의 역할

`fork()`는 **새로운 프로세스를 생성하는 시스템 콜**이다.  
호출한 프로세스(부모 프로세스)를 **거의 동일한 상태로 복제한 자식 프로세스**를 만든다.

- 프로세스 개수 증가
    
- 부모와 자식은 **서로 다른 PID**
    
- 실행 중인 프로그램은 동일
    

### fork()의 반환값

```text
부모 프로세스  → 자식 PID (> 0)
자식 프로세스  → 0
오류 발생      → -1
```

이 반환값을 기준으로 부모와 자식의 실행 흐름을 분기한다.

---

### fork() 이후의 메모리 상태

```text
부모 프로세스 메모리        자식 프로세스 메모리
+------------------+       +------------------+
| 코드             |       | 코드             |
| 데이터           |       | 데이터           |
| 힙               |       | 힙               |
| 스택             |       | 스택             |
+------------------+       +------------------+
```

- 논리적으로는 완전 복제
    
- 실제로는 **Copy-on-Write** 방식으로 효율적으로 관리됨
    

---

## 2. fork()만으로는 충분하지 않은 이유

fork()로 생성된 자식 프로세스는 **부모와 같은 프로그램을 실행 중**이다.

하지만 쉘(shell)이나 서버는 다음과 같은 동작을 원한다.

- 새로운 프로세스를 만들고
    
- 그 프로세스에서 **전혀 다른 프로그램을 실행**
    

이 문제를 해결하는 것이 `execve()`이다.

---

## 3. 프로그램 실행(치환): execve()

### execve()의 핵심 개념

`execve()`는 **새 프로세스를 생성하지 않는다.**

대신,

- 현재 프로세스를 유지한 채
    
- **프로세스의 메모리 이미지 전체를**
    
- 지정한 실행 파일의 내용으로 교체한다
    

즉,

> 프로세스는 그대로, 프로그램만 바뀐다

---

### execve() 호출 전후의 변화

#### execve() 호출 전

```text
프로세스 (PID = 1234)
+------------------+
| 기존 프로그램   |
| 코드 / 데이터   |
| 힙 / 스택       |
+------------------+
```

#### execve() 호출 후

```text
프로세스 (PID = 1234)
+------------------+
| 새로운 프로그램 |
| 코드 / 데이터   |
| 힙 / 스택       |
+------------------+
```

- PID 유지
    
- 기존 코드, 데이터, 스택 전부 제거
    
- 새로운 실행 파일로 완전 교체
    

---

## 4. fork() + execve()의 결합 구조

### 일반적인 실행 흐름

```text
부모 프로세스
    |
    v
fork()
    |
    +--------------------+
    |                    |
부모 프로세스         자식 프로세스
(기존 프로그램)       (기존 프로그램)
                          |
                          v
                      execve()
                          |
                          v
                   새로운 프로그램 실행
```

이 패턴은 쉘이 외부 명령을 실행할 때 사용하는 **표준 구조**다.

---
## 5. execve() 내부에서 커널이 수행하는 작업

```text
1. 실행 파일 열기
2. ELF 헤더 분석
3. 코드 / 데이터 영역 정보 확인
4. 기존 메모리 공간 제거
5. 새로운 메모리 매핑
6. 엔트리 포인트 설정
7. 사용자 모드로 복귀 후 실행 시작
```

이때 실행은 `main()`이 아니라 `_start`부터 시작된다.

---

## 6. 핵심 요약

- fork(): 프로세스를 복제하여 생성
    
- execve(): 현재 프로세스를 다른 프로그램으로 치환
    
- fork는 개수 증가, execve는 내용 교체
    
- 시스템 콜은 glibc의 래퍼 함수를 통해 호출
    
- 커널 모드 전환은 래퍼 함수 내부의 어셈블리 코드에서 발생
    

---

## 한 문장 요약

프로세스는 fork()로 생성되고, execve()로 프로그램이 교체되며, 이 모든 과정에서 시스템 콜은 glibc가 제공하는 래퍼 함수와 어셈블리 코드를 통해 사용자 모드에서 커널 모드로 안전하게 전달된다.
