# 1. SSD 등장에 따른 변화

HDD 시대에는:

- 랜덤 접근이 매우 느림
    
- 순차 I/O 최적화가 핵심
    
- I/O 스케줄러가 매우 중요
    

SSD 등장 이후:

- 랜덤 접근 속도 급상승
    
- 병렬 I/O 활용 가능
    
- 큐 깊이 증가가 곧 성능 향상
    

즉,

```
"정렬해서 순차로 만들기" → "병렬로 많이 던지기"
```

로 패러다임이 바뀜.

---

# 2. SSD의 특징

## 1) 기계 부품 없음

- Seek time 없음
    
- 회전 지연 없음
    

## 2) NAND 플래시 기반

- 블록 단위 삭제
    
- 페이지 단위 읽기/쓰기
    
- Wear leveling 필요
    

## 3) 내부 병렬 구조

- 채널(Channel)
    
- 다이(Die)
    
- 플레인(Plane)
    

→ 내부적으로 여러 작업 동시 수행 가능

---

# 3. SSD의 무작위 접근 성능

HDD:

- 랜덤 접근 = 헤드 이동
    
- 레이턴시 급증
    

SSD:

- 주소 기반 접근
    
- 랜덤 읽기 거의 순차와 비슷한 속도
    
- IOPS 수십만~백만 단위 가능
    

결과:

랜덤 I/O 중심 워크로드(DB, VM)에 매우 유리

---

# 4. SSD 접속 방식 3가지

## 1) SATA SSD

- SATA 인터페이스 사용
    
- AHCI 프로토콜
    
- 기존 HDD와 호환
    
- 대략 500MB/s 한계
    

---

## 2) SAS SSD

- 서버용 인터페이스
    
- 안정성 높음
    
- 듀얼 포트 지원
    

---

## 3) NVMe SSD

- PCIe 기반
    
- NVMe 프로토콜
    
- 다중 큐 지원
    
- 매우 높은 IOPS/Throughput
    

현재 성능 중심 구조

---

# 5. HDD vs SSD 장단점

## HDD

장점:

- 저렴함
    
- 대용량 저장에 유리
    

단점:

- 느린 랜덤 접근
    
- 기계적 고장 가능
    
- 전력 소모 큼
    

---

## SSD

장점:

- 빠른 랜덤 접근
    
- 낮은 레이턴시
    
- 낮은 전력 소모
    
- 무소음
    

단점:

- 가격 높음
    
- 쓰기 수명 제한
    
- 대용량 대비 비용 부담
    

---

# 6. CPU 멀티코어화와 멀티 큐

SSD 등장 시기와 함께 CPU도 변화:

## 과거

- 싱글 코어
    
- 블록 계층도 단일 큐 구조
    

문제:

- 여러 코어가 하나의 I/O 큐를 공유
    
- 락 경합 발생
    
- 확장성 한계
    

---

## 현재

- 멀티코어 CPU
    
- NVMe 다중 큐 지원
    

구조:

```
코어별 I/O 큐
→ 장치 내부 다중 큐
→ 병렬 처리
```

결과:

- 락 경합 감소
    
- 코어 수만큼 IOPS 확장 가능
    
- 고성능 서버 환경에 적합
    

---

# 전체 흐름 정리

HDD 시대:

- 순차 최적화
    
- 단일 큐
    
- I/O 스케줄링 중요
    

SSD 시대:

- 랜덤 I/O 고속
    
- 병렬 I/O 중심
    
- 멀티코어 + 멀티큐 구조
    

---

# 한 줄 핵심

SSD는 랜덤 접근 병목을 제거했고, 멀티코어 CPU와 멀티 큐 구조를 통해 I/O를 병렬화하는 방향으로 시스템 설계를 바꾸었다.
