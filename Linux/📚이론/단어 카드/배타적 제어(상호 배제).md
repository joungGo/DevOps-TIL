# 배타적 제어 (상호배제, Mutual Exclusion)

## 1. 개념

> 여러 실행 흐름(프로세스/스레드)이 동시에 공유 자원에 접근할 때  
> **한 번에 하나만 접근하도록 보장하는 것**

목적은 **race condition 방지**다.

---

## 2. 크리티컬 섹션 (Critical Section)

### 개념

> 공유 자원에 접근하는 코드 영역

예시:

```c
counter++;
```

여러 스레드가 동시에 실행하면:

1. 값 읽기
    
2. 증가
    
3. 저장
    

과정이 겹쳐서 값이 꼬일 수 있다.

### 핵심

- 크리티컬 섹션에는
    
    - 동시에 하나의 실행 흐름만 들어가야 함
        
- 이를 위해
    
    - mutex
        
    - semaphore
        
    - spinlock  
        등을 사용
        

---

## 3. 아토믹 처리 (Atomic Operation)

### 개념

> 더 이상 쪼갤 수 없는, **하나의 연산처럼 보장되는 작업**

즉,

- 중간에 인터럽트되지 않음
    
- 다른 스레드가 끼어들 수 없음
    

예:

```c
atomic_inc(&counter);
```

이 연산은:

- 읽기
    
- 증가
    
- 저장
    

이 모두가 **한 번에 수행되는 것처럼 보장됨**

---

## 4. 크리티컬 섹션 vs 아토믹 처리

|구분|크리티컬 섹션|아토믹 처리|
|---|---|---|
|범위|코드 블록|단일 연산|
|구현 방식|락 사용|CPU 원자 명령어|
|오버헤드|비교적 큼|작음|
|사용 목적|복잡한 공유 자원 보호|단순 카운터 등|

---

## 한 문장 정리

- 크리티컬 섹션은 **공유 자원 접근 코드 영역**
    
- 아토믹 처리는 **연산 단위를 원자적으로 보장하는 방법**
    
- 둘 다 상호배제를 달성하기 위한 수단이다.
