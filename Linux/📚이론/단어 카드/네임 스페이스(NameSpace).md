# 컨테이너에서의 네임스페이스(namespace)

컨테이너에서 네임스페이스는

> 프로세스가 보는 시스템 자원을 분리하여, 서로 다른 환경처럼 보이게 만드는 커널 기능

이다.

핵심은:

```text
격리 = 새로운 가상 인식 공간을 만드는 것
```

컨테이너는 별도의 커널을 가지지 않는다.  
대신 **같은 커널 안에서 네임스페이스로 격리**한다.

---

# 1. 왜 필요한가

리눅스는 기본적으로 하나의 시스템이다.

- PID도 하나의 공간
    
- 네트워크도 하나
    
- 파일 시스템도 하나
    

이 상태에서는:

- 모든 프로세스가 서로 보임
    
- 포트 충돌 발생
    
- 자원 격리 불가
    

그래서 커널이 “보이는 범위”를 나눠준다.

---

# 2. 주요 네임스페이스 종류

## 1) PID namespace

- 프로세스 ID 격리
    
- 컨테이너 안에서는 자기 프로세스만 보임
    
- 컨테이너 내부 PID 1은 실제로는 다른 PID일 수 있음
    

---

## 2) Mount namespace

- 파일 시스템 마운트 격리
    
- 컨테이너마다 다른 루트 파일 시스템 사용 가능
    

---

## 3) Network namespace

- 네트워크 스택 격리
    
- 각 컨테이너는 독립적인:
    
    - IP 주소
        
    - 포트 공간
        
    - 라우팅 테이블
        
    - 인터페이스
        

---

## 4) UTS namespace

- hostname 격리
    

---

## 5) IPC namespace

- 공유 메모리, 세마포어 격리
    

---

## 6) User namespace

- UID/GID 매핑 격리
    
- 컨테이너 안의 root가  
    호스트에서는 일반 사용자일 수 있음
    

---

# 3. 컨테이너 구조에서의 역할

컨테이너는 다음 조합으로 구성된다.

```text
namespace → 자원 격리
cgroup → 리소스 제한
capability → 특권 분리
```

즉,

> 컨테이너는 네임스페이스 기반 격리된 프로세스 집합이다.

---

# 4. 왜 가상 머신보다 가벼운가

- 커널은 하나만 사용
    
- 하드웨어 가상화 없음
    
- 네임스페이스로 “보이는 것만” 분리
    

따라서:

```text
VM → OS 통째로 복제
컨테이너 → 커널 내부에서 격리
```

---

# 한 줄 정리

컨테이너에서 네임스페이스는 동일한 리눅스 커널 안에서 프로세스가 보는 PID, 네트워크, 파일 시스템 등의 자원 범위를 분리해 서로 다른 독립 시스템처럼 보이게 만드는 격리 메커니즘이다.
