여러 서버의 계정을 각각 관리하지 않고,  
하나의 중앙 시스템에서 사용자와 권한을 통합 관리하는 방식이다.

목적:

- 계정 일관성 유지
    
- 권한 관리 단순화
    
- 보안 강화
    
- 대규모 환경 운영 효율 향상
    

---

# 1. 디렉터리 기반

중앙 디렉터리 서버에 사용자 정보를 저장하고  
각 시스템과 애플리케이션이 이를 조회하는 방식.

예:

- Keycloak
    
- Microsoft Azure Active Directory
    

## 언제 사용하나?

- 사내 여러 웹 서비스에 **SSO(싱글 사인온)** 적용할 때
    
- 클라우드 + 온프레미스 환경을 함께 운영할 때
    
- 조직 단위 사용자/그룹/역할 기반 권한 관리가 필요할 때
    

즉, **기업 단위 통합 계정 관리**에 적합하다.

---

# 2. 네트워크 기반 인증

중앙 인증 서버가 네트워크를 통해 사용자 신원을 검증하는 방식.

예:

- Kerberos
    

## 언제 사용하나?

- 리눅스 서버 다수를 하나의 인증 체계로 묶을 때
    
- 패스워드 노출 없이 안전한 인증이 필요할 때
    
- 내부망 기반 기업 환경에서 서버 로그인 통합이 필요할 때
    

즉, **서버 로그인 통합 및 보안 인증 체계 구축**에 적합하다.

---

# 3. 구성 관리 시스템 활용

각 서버의 사용자 계정과 권한을 자동화 도구로 일괄 관리하는 방식.

예:

- Ansible
    
- Chef
    
- Puppet
    
- SaltStack
    

## 언제 사용하나?

- 서버 수십~수백 대에 동일한 계정을 배포해야 할 때
    
- DevOps 환경에서 인프라를 코드로 관리할 때
    
- 계정 생성/삭제/권한 변경을 자동화해야 할 때
    

즉, **대규모 서버 운영 자동화 환경**에 적합하다.

---

# 핵심 비교

|방식|초점|적합한 환경|
|---|---|---|
|디렉터리 기반|사용자 정보 중앙 저장|기업 통합 계정 관리, SSO|
|네트워크 기반|인증 중앙화|서버 로그인 통합|
|구성 관리 기반|설정 자동화|대규모 인프라 운영|

---

# 한 줄 정리

디렉터리 기반은 사용자 정보를 중앙에서 관리하고, 네트워크 기반은 인증을 중앙화하며, 구성 관리 시스템은 여러 서버의 계정 설정을 자동화하는 방식이다.
