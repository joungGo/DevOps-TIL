파일 시스템을 생성한 이후의 과제는  
디스크 안의 데이터를 어떻게 구조적으로 배치할 것인가이다.

디스크는 단순한 블록의 집합이기 때문에,  
파일의 위치·속성·빈 공간을 체계적으로 관리할 구조가 필요하다.

---

# 1. 왜 구조화가 필요한가

디스크는 다음과 같은 단순한 블록 배열이다.

```text
[블록][블록][블록][블록]...
```

이 상태에서는:

- 파일이 어디에 있는지 알 수 없음
    
- 파일 이름과 데이터 연결 불가
    
- 빈 공간 추적 불가
    

따라서 메타데이터와 데이터의 배치 구조가 필요하다.

---

# 2. 범용 파일 시스템의 기본 구조

대부분의 파일 시스템(ext4, xfs 등)은 다음과 같은 레이아웃을 가진다.

```text
[부트 영역]
[슈퍼블록]
[메타데이터 영역]
  └ 아이노드 테이블
[데이터 블록 영역]
```

---

## 슈퍼블록

- 파일 시스템 전체 정보 저장
    
- 전체 블록 수
    
- 아이노드 수
    
- 상태 정보
    

파일 시스템의 전반적인 구조 정보를 담는다.

---

## 아이노드 테이블

- 각 파일의 메타데이터 저장
    
- 파일 크기
    
- 권한
    
- UID/GID
    
- 데이터 블록 위치
    

파일 이름은 포함하지 않는다.

---

## 데이터 블록

- 실제 파일 내용 저장
    
- 디렉토리 내용도 저장
    

실제 데이터가 위치하는 영역이다.

---

# 3. 파일 접근의 기본 흐름

파일 시스템은 다음 문제를 해결해야 한다.

1. 파일 이름을 통해 아이노드 찾기
    
2. 아이노드를 통해 데이터 블록 찾기
    
3. 빈 공간 관리
    

접근 흐름은 다음과 같다.

```text
경로 탐색 → 아이노드 조회 → 데이터 블록 읽기
```

---

# 4. 설계 목표

- 빠른 접근
    
- 공간 효율성
    
- 단편화 최소화
    
- 장애 복구 가능성 (저널링 등)
    

---

# 한 줄 정리

범용 파일 시스템 레이아웃은 디스크 블록을 슈퍼블록, 아이노드, 데이터 블록 등으로 구조화하여 파일의 위치와 속성, 실제 데이터를 체계적으로 관리하는 설계 방식이다.
