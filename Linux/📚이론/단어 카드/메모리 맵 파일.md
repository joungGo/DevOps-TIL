# 메모리 맵 파일 (Memory-Mapped File)

메모리 맵 파일은

> 파일의 내용을 프로세스의 가상 주소 공간에 매핑하여  
> 메모리처럼 접근할 수 있게 하는 방식이다.

즉,

```
read()/write()로 접근하는 것이 아니라
포인터로 직접 접근
```

---

# 1. 사용 방법

리눅스에서는 `mmap()` 시스템 콜을 사용한다.

```c
void *addr = mmap(NULL, length, PROT_READ | PROT_WRITE,
                  MAP_SHARED, fd, 0);
```

이 호출은:

- 파일의 일부 또는 전체를
    
- 프로세스의 가상 주소 공간에 연결한다.
    

---

# 2. 내부 동작 원리

## 1단계: 가상 주소 공간 확보

커널은:

- 프로세스의 가상 주소 공간에
    
- 지정한 크기만큼 영역을 할당
    

이 시점에는 **물리 메모리 없음**

---

## 2단계: 페이지 테이블 설정

페이지 테이블에:

```
가상 주소 → 파일과 연결된 페이지
```

형태로 등록한다.

하지만 실제 물리 메모리는 아직 없음.

---

## 3단계: Demand Paging 발생

프로세스가 해당 주소에 처음 접근하면:

- 페이지 폴트 발생
    
- 커널이 파일 내용을 디스크에서 읽음
    
- 물리 페이지 할당
    
- 페이지 테이블에 매핑
    

즉,

```
VA 접근
   ↓
Page Fault
   ↓
디스크 → 메모리 로드
   ↓
VA → PA 연결
```

---

# 3. MAP_SHARED vs MAP_PRIVATE

## 1. MAP_SHARED

- 변경 내용이 파일에 반영됨
    
- 여러 프로세스가 같은 파일을 매핑하면  
    동일 물리 페이지를 공유 가능
    

→ 공유 메모리 IPC 용도로 사용 가능

---

## 2. MAP_PRIVATE

- 변경 내용이 파일에 반영되지 않음
    
- 쓰기 시 Copy-on-Write 발생
    

```
처음엔 공유
쓰기 시점에 물리 페이지 복사
```

---

# 4. 기존 read/write 방식과 차이

## 일반 파일 I/O

```
디스크 → 커널 버퍼(page cache) → 사용자 버퍼
```

데이터 복사가 발생한다.

---

## mmap 방식

```
디스크 → page cache
           ↑
     프로세스가 직접 접근
```

중간 복사가 줄어든다.

---

# 5. 장점

1. 불필요한 데이터 복사 감소
    
2. 대용량 파일 처리에 효율적
    
3. 파일을 배열처럼 접근 가능
    
4. 프로세스 간 공유 메모리로 사용 가능
    

---

# 6. 단점

1. 페이지 폴트 오버헤드
    
2. 랜덤 접근 시 성능 예측 어려움
    
3. 동기화 문제 (MAP_SHARED 사용 시)
    
4. 파일 크기 변경 시 주의 필요
    

---

# 7. 저장장치까지의 흐름 연결

mmap 접근 시 실제 흐름은:

```
프로세스 VA 접근
   ↓
페이지 폴트
   ↓
VFS
   ↓
파일 시스템
   ↓
블록 계층
   ↓
디바이스 드라이버
   ↓
저장장치
```

이후 물리 페이지가 매핑되면:

- 다시 접근할 때는 디스크 접근 없음
    
- 메모리 접근처럼 동작
    

---

# 8. 한 문장 정리

> 메모리 맵 파일은 파일을 가상 주소 공간에 직접 매핑하여  
> 페이지 폴트를 통해 필요할 때만 디스크에서 읽어오는 방식의 파일 접근 기법이다.
