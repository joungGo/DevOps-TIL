블록 장치 성능은 보통 다음 3가지로 본다:

- **Throughput (스루풋)**: 초당 전송 데이터량 (MB/s, GB/s)
    
- **Latency (레이턴시)**: 요청 1개가 완료되기까지 걸리는 시간 (ms, μs)
    
- **IOPS**: 초당 처리 가능한 I/O 요청 수
    

---

# 1. 하나의 프로세스가 I/O를 호출하는 경우

## 특징

- 요청이 순차적으로 발생
    
- 큐 깊이(Queue Depth)가 낮음 (보통 1)
    

## 성능 특성

- **Latency가 직접 성능을 결정**
    
- IOPS ≈ 1 / 평균 레이턴시
    
- Throughput = IOPS × 블록 크기
    

## 예시

레이턴시 1ms라면:

- IOPS ≈ 1000
    
- 4KB 블록이면 → 약 4MB/s
    

→ 병렬성이 없으면 장치 성능을 충분히 못 씀

---

# 2. 여러 프로세스가 병렬로 I/O 호출하는 경우

큐 깊이 증가 → 여러 요청이 동시에 대기

여기서 장치 특성에 따라 달라짐.

---

# (1) 병렬 처리 불가능한 경우

### 예: HDD

- 물리적으로 헤드 1개
    
- 동시에 여러 요청 처리 불가
    
- 결국 순차 처리
    

결과:

- IOPS 거의 증가하지 않음
    
- 오히려 랜덤 접근 증가로 레이턴시 상승
    
- Throughput 감소 가능
    

예:

랜덤 요청 10개 동시 발생  
→ 헤드 계속 이동  
→ 평균 레이턴시 증가

---

# (2) 병렬 처리 가능한 경우

### 예: NVMe SSD

- 내부 채널 다수
    
- 다중 큐 구조
    
- 여러 요청 동시 처리 가능
    

결과:

- 큐 깊이 증가 → IOPS 증가
    
- Throughput 크게 증가
    
- 평균 레이턴시 크게 늘지 않음
    

예:

Queue Depth 1 → 50k IOPS  
Queue Depth 32 → 400k IOPS

→ 병렬성 활용 가능

---

# 정리

## 단일 프로세스

- 성능은 거의 **레이턴시 의존**
    
- 병렬성 없음
    
- IOPS 낮음
    

## 다중 프로세스

- HDD: 병렬 불가 → 성능 향상 제한
    
- NVMe SSD: 병렬 가능 → IOPS, Throughput 크게 증가
    

---

# 한 줄 핵심

단일 I/O는 레이턴시가 성능을 결정하고,  
다중 I/O에서는 장치가 병렬 처리를 지원하느냐가 성능을 좌우한다.
