# 프로세스 권한 (UID 종류)

리눅스 프로세스는 단순히 하나의 UID만 가지는 것이 아니라,  
권한 판단을 위해 여러 종류의 UID를 가진다.

---

# 1. RUID (Real UID)

**실제 사용자 ID**

- 이 프로세스를 실행한 “원래 사용자”의 UID
    
- 로그인한 사용자의 UID
    
- 신원(identity)을 나타냄
    

예:

```text
사용자 A가 프로그램 실행
→ RUID = A
```

주 용도:

- 프로세스 소유자 확인
    
- 시그널 전송 권한 판단
    

---

# 2. EUID (Effective UID)

**실질 권한 판단에 사용되는 UID**

- 파일 접근, 시스템 콜 권한 검사 시 사용
    
- 커널이 실제로 권한 체크할 때 참고하는 값
    

가장 중요하다.

예:

- 일반 사용자가 `passwd` 실행
    
- 해당 파일이 setuid root라면
    

```text
RUID = 일반 사용자
EUID = root
```

→ root 권한으로 실행 가능

---

# 3. Saved SUID (Saved Set-user-ID)

**이전의 EUID를 저장해 두는 값**

목적:

- 일시적으로 권한을 낮췄다가
    
- 다시 원래 권한으로 복구하기 위해 사용
    

예:

1. setuid root 프로그램 실행
    
2. EUID = root
    
3. 권한을 일반 사용자로 낮춤
    
4. 필요 시 다시 root로 복구
    

이때 복구 기준이 Saved SUID다.

---

# 4. FSUID (File System UID)

**파일 시스템 접근에만 사용되는 UID**

- 파일 접근 권한 체크 전용
    
- 보통은 EUID와 동일
    
- NFS 같은 네트워크 파일 시스템에서 사용
    

즉:

```text
파일 접근 판단 → FSUID 사용
```

일반적인 경우에는 거의 EUID와 같아서 잘 의식하지 않는다.

---

# 5. 관계 정리

|종류|의미|사용 목적|
|---|---|---|
|RUID|실제 사용자|신원|
|EUID|권한 판단|접근 제어 핵심|
|Saved SUID|이전 권한 저장|권한 복구|
|FSUID|파일 접근 전용|파일 시스템 권한 검사|

---

# 6. 핵심 흐름

파일 접근 시 커널은:

```text
FSUID → (보통 EUID와 동일)
```

을 기준으로 권한을 판단한다.

---

# 한 줄 정리

RUID는 실제 사용자 신원이고, EUID는 실제 권한 판단에 사용되며, Saved SUID는 권한 복구용 저장값이고, FSUID는 파일 시스템 접근 권한 판단에 사용된다.
