## 1. 캐시 메모리 필요성

### 해결하려는 기존 문제

CPU 속도는 매우 빠름  
메모리(RAM)는 상대적으로 느림

→ **CPU가 메모리를 기다리느라 멈추는 문제 (메모리 병목)** 발생

기호로 표현하면:

CPU 속도 >> RAM 속도

따라서

CPU → RAM 직접 접근 반복  
→ 대기 시간 증가  
→ 전체 성능 저하

이 문제를 줄이기 위해 **중간에 매우 빠른 저장 공간**이 필요  
→ 그것이 캐시 메모리

---

## 2. 캐시 메모리란?

- CPU 내부에 존재하는 고속 기억장치
    
- 일반 메모리보다 수배~수십 배 빠름
    
- 자주 사용하는 데이터를 임시 저장
    

---

### 캐시라인

메모리에서 데이터를 1바이트씩 가져오지 않음.

RAM → Cache  
는 **캐시라인 단위(예: 64바이트)** 로 읽어옴

그리고

Cache → Register  
로 필요한 데이터만 전달

이 과정은 **하드웨어에서 자동 처리**  
→ 커널은 관여하지 않음

---

## 3. CPU · 캐시 · 메모리 관계 (기호 표현)

구조:

```
[CPU Register]
      ↓
   [L1/L2/L3 Cache]
      ↓
      RAM
```

접근 속도:

Register >> Cache >> RAM

---

## 4. CPU가 메모리 주소 300을 변경하는 과정

예:

M[300] = 10 → 20 으로 변경

동작 흐름:

1. RAM에서 해당 주소가 캐시 메모리에 로딩됨
    
2. CPU가 캐시 데이터를 수정
    
3. 캐시라인에 "Dirty" 표시  
    (RAM과 값이 다름을 의미 = 값이 변경되었음을 의미미)
    

---

## 5. 메모리에 반영하는 방식 2가지

### 1) Write Through

동작:

CPU → Cache 수정  
→ 즉시 RAM에도 기록

구조:

```
CPU → Cache → RAM (즉시 반영)
```

특징:

- 구현 단순
    
- RAM과 항상 일관성 유지
    
- 하지만 RAM 접근이 자주 발생 → 느릴 수 있음
    

---

### 2) Write Back

동작:

CPU → Cache 수정 (Dirty 표시)  
→ RAM에는 나중에 반영

구조:

```
CPU → Cache (Dirty)
        ↓
   (교체 시점에)
        ↓
       RAM
```

특징:

- RAM 접근 횟수 감소
    
- 성능 향상
    
- 구현 복잡
    
- 캐시 일관성 관리 필요
    

---

## 6. "라이트 스루도 바로 메모리에 접근 안 해도 되지 않나?"

좋은 질문.

Write Through는 **논리적으로 즉시 RAM에 기록해야 함**.

하지만 실제 하드웨어에서는:

- **Write Buffer**를 사용함
    

즉,

CPU → Cache → Write Buffer  
→ 이후 RAM에 기록

이 방식은 CPU가 RAM 쓰기를 기다리지 않게 해줌.

하지만 핵심 차이점은:

Write Through는  
"모든 쓰기가 결국 RAM에 즉시 반영되도록 보장"

Write Back은  
"캐시 교체 전까지 RAM에 반영하지 않아도 됨"

즉, RAM 쓰기 횟수 자체가 다름.

---

## 7. 캐시 교체와 클린 과정

상황:

- 캐시가 가득 참
    
- 새로운 데이터 필요
    

→ 기존 캐시라인 하나 제거

### 경우 1: Dirty 아님

그냥 제거

### 경우 2: Dirty 상태

→ RAM에 먼저 기록  
→ 그 다음 제거

이 과정을 **클린(clean)** 이라고 함

---

## 8. 캐시 스래싱

캐시가 계속 교체되는 상황

예:

A → B → C → A → B → C 반복  
(캐시에 모두 못 들어가는 경우)

결과:

- 계속 캐시 미스
    
- Dirty write-back 빈번
    
- RAM 접근 증가
    
- 성능 급격 저하
    

이를 **캐시 스래싱(thrashing)** 이라고 함

---

## 9. 전체 흐름 정리 (기호)

읽기:

```
CPU → Cache 확인
      ↓
  Hit → 바로 사용
  Miss → RAM → Cache → CPU
```

쓰기 (Write Back 기준):

```
CPU → Cache 수정 (Dirty)
        ↓
(교체 시)
Cache → RAM 반영
```

---

## 핵심 요약

1. 캐시는 CPU와 RAM 속도 차이를 줄이기 위한 장치
    
2. 캐시라인 단위로 데이터 이동
    
3. Dirty 비트는 RAM과 값이 다름을 의미
    
4. Write Through는 즉시 RAM 반영
    
5. Write Back은 나중에 RAM 반영
    
6. Dirty 라인 제거 시 클린 과정 필요
    
7. 반복 교체는 스래싱으로 성능 저하
