# 세션(Session) · 단말(Terminal) · ps ajx · 행업(Hangup)

## 1. 단말, 단말 에뮬레이터

### 단말(Terminal)

- **커널이 제공하는 문자 입출력 장치**
    
- 표준 입력(stdin), 출력(stdout), 오류(stderr)의 연결 대상
    
- 예:
    
    - `/dev/tty`
        
    - `/dev/pts/0`
        

과거에는 물리적인 키보드+화면 장치였음.

---

### 단말 에뮬레이터(Terminal Emulator)

- **단말을 소프트웨어로 흉내 낸 프로그램**
    
- 예:
    
    - gnome-terminal
        
    - xterm
        
    - Windows Terminal
        
    - iTerm2
        

단말 에뮬레이터가 실행되면:

- 가상 단말(`/dev/pts/N`) 생성
    
- 쉘(bash 등)이 그 단말에 연결됨
    

---

## 2. 세션(Session)

### 세션이란?

**하나의 로그인 환경 단위**

- 하나의 단말을 중심으로 묶인 프로세스 그룹의 집합
    
- 로그인 쉘이 세션을 생성
    

```text
터미널 열기
  ↓
bash 실행
  ↓
새 세션 생성
```

---

## 3. 세션 ID (SID)

- 세션을 식별하는 고유 ID
    
- **세션 리더의 PID와 동일**
    

예:

```text
bash PID = 3200
→ SID = 3200
```

---

## 4. 세션 리더(Session Leader)

- 세션을 생성한 프로세스
    
- 보통 **로그인 쉘(bash, zsh)**
    

특징:

- PID == SID
    
- 단말의 제어권을 가짐
    

---

## 5. 세션과 단말의 관계

- 하나의 세션은 **하나의 제어 단말(controlling terminal)** 을 가질 수 있음
    
- 단말 종료 → 세션 전체에 영향
    

---

## 6. `ps ajx` 명령어

### 명령 의미

- `a` : 모든 사용자 프로세스
    
- `j` : job control 정보 출력
    
- `x` : 단말 없는 프로세스도 출력
    

---

### 주요 출력 항목 설명

예시 출력 (간략화):

```text
PPID   PID  PGID   SID TTY      STAT   COMMAND
 1    3200  3200  3200 pts/0    Ss     bash
3200  3301  3301  3200 pts/0    R      vim
3200  3400  3400  3200 pts/0    S      sleep 100
```

---

### 항목별 설명

#### PPID (Parent PID)

- 부모 프로세스 ID
    
- 예: bash(3200)가 vim(3301)을 실행
    

---

#### PID

- 프로세스 ID
    

---

#### PGID (Process Group ID)

- 프로세스 그룹 ID
    
- 작업 제어 단위
    
- 예:
    
    - `vim` 실행 → 새로운 PGID 생성
        

---

#### SID (Session ID)

- 세션 ID
    
- 세션 리더의 PID와 동일
    
- 같은 터미널에서 실행한 프로세스는 SID가 동일
    

---

#### TTY

- 연결된 단말
    
- `pts/0` → 가상 터미널
    
- `?` → 단말 없음 (데몬 등)
    

---

#### STAT

- 프로세스 상태
    
- 예:
    
    - `R` : 실행 중
        
    - `S` : 슬립
        
    - `T` : 정지
        
    - `Z` : 좀비
        
    - `s` : 세션 리더
        

---

#### COMMAND

- 실행 명령어
    

---

## 7. 행업(Hangup, SIGHUP)

### 행업이란?

- **제어 단말이 사라졌을 때 발생하는 시그널**
    
- 시그널 이름: `SIGHUP`
    

발생 상황:

- 터미널 창 종료
    
- SSH 연결 종료
    

---

### 행업의 기본 동작

- 세션 리더(bash)가 SIGHUP 수신
    
- bash가 자식 프로세스들에게 SIGHUP 전달
    
- 대부분의 프로세스 종료
    

---

## 8. nohup

### nohup이란?

- **SIGHUP을 무시하도록 설정한 채 프로그램 실행**
    

```bash
nohup long_task &
```

효과:

- 터미널 종료해도 프로세스 계속 실행
    
- 출력은 `nohup.out`으로 리다이렉션
    

---

## 9. disown

### disown이란?

- **이미 실행 중인 작업을 쉘의 관리 대상에서 제거**
    

```bash
long_task &
disown
```

효과:

- 쉘 종료 시 SIGHUP 전달되지 않음
    
- 쉘과의 관계만 끊음
    

---

## 10. nohup vs disown 차이

|항목|nohup|disown|
|---|---|---|
|사용 시점|실행 전|실행 후|
|SIGHUP|무시|전달 안 함|
|쉘 관리|계속 관리|관리 대상 제거|
|출력 처리|파일로 리다이렉션|기존 설정 유지|

---

## 11. 전체 구조 요약

```text
단말 에뮬레이터
   ↓
가상 단말 (/dev/pts/N)
   ↓
세션 리더 (bash)
   ↓
세션 (SID)
   ↓
프로세스 그룹들 (PGID)
   ↓
개별 프로세스들
```

---

## 핵심 요약

- 단말 에뮬레이터는 단말을 흉내 내는 프로그램
    
- 세션은 로그인 단위
    
- SID는 세션 리더 PID
    
- `ps ajx`는 세션/그룹 구조를 한눈에 보여줌
    
- 행업은 단말 종료 시 발생
    
- nohup과 disown은 행업을 피하기 위한 도구
    

---

이제 이 개념이 잡히면 다음 내용이 아주 잘 연결된다.

- 포그라운드 / 백그라운드 작업
    
- job control (`fg`, `bg`)
    
- 데몬 프로세스가 단말을 가지지 않는 이유
