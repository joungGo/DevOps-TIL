## 라이브러리의 종류

- **정적 라이브러리 (Static Library)**
    
- **동적 라이브러리 (Dynamic Library)**
    

---

## 라이브러리 개요

리눅스 시스템에는 **표준 C 라이브러리(Standard C Library)** 가 존재하며,  
리눅스 환경에서 가장 널리 사용되는 구현체가 **glibc(GNU C Library)** 이다.

C 언어로 작성된 대부분의 프로그램은 문자열 처리, 메모리 할당, 파일 입출력과 같은 기본 기능을 직접 구현하지 않고, **libc를 링크(link)** 하여 사용한다.

---

## 정적 라이브러리

정적 라이브러리는 **컴파일 시점에 라이브러리 코드가 실행 파일에 포함**되는 방식이다.

### 특징

- 실행 파일 하나에 필요한 코드가 모두 포함됨
    
- 실행 시 외부 라이브러리에 의존하지 않음
    
- 실행 파일 크기가 커짐
    
- 동일 라이브러리를 사용하는 여러 프로그램이 있어도 각각 복사본을 가짐
    

### 파일 형태

- `.a` 파일  
    예: `libc.a`
    

---

## 동적 라이브러리

동적 라이브러리는 **프로그램 실행 시점에 메모리에 로드되어 연결**되는 방식이다.

### 특징

- 실행 파일 크기가 작음
    
- 여러 프로세스가 하나의 라이브러리를 메모리에서 공유 가능
    
- 라이브러리가 없거나 버전이 맞지 않으면 실행 오류 발생 가능
    
- 라이브러리 업데이트 시 재컴파일 없이 효과 반영 가능
    

### 파일 형태

- `.so` 파일  
    예: `libc.so.6`
    

---

## glibc와 시스템 콜의 관계 (추가 설명)

glibc는 **커널 자체가 아니다**.  
glibc는 사용자 공간 라이브러리이며, 내부적으로 **시스템 콜을 호출하여 커널 기능을 사용**한다.

예를 들어:

- `printf()` → 내부적으로 `write()` 호출
    
- `malloc()` → 내부적으로 `brk()` 또는 `mmap()` 시스템 콜 사용
    

즉,

- 애플리케이션 → glibc 함수 호출
    
- glibc → 시스템 콜 수행
    
- 커널 → 실제 자원 처리
    

라는 구조로 동작한다.

## 한 문장 요약

리눅스에서 C 프로그램은 glibc를 통해 표준 기능을 사용하며, 이 라이브러리는 정적 또는 동적 방식으로 링크되어 커널의 시스템 콜을 간접적으로 호출한다.
