# 스레드 구현 방식

스레드는 구현 위치에 따라 크게 두 가지로 나뉜다.

- 커널 스레드 (Kernel-Level Thread)
    
- 사용자 스레드 (User-Level Thread)
    

---

# 1. 커널 스레드 (Kernel-Level Thread)

## 개념

> 커널이 직접 관리하는 스레드

- 각 스레드는 커널에 의해 독립적인 실행 단위로 인식됨
    
- 스케줄링을 커널이 수행
    
- 리눅스의 pthread는 내부적으로 커널 스레드 기반 (1:1 모델)
    

---

## 동작 구조

```
User Thread 1 ──┐
User Thread 2 ──┼─→ Kernel Thread 1, 2 ...
User Thread 3 ──┘
```

- 사용자 스레드 1개당 커널 스레드 1개
    
- 커널이 직접 CPU에 할당
    

---

## 장점

1. 하나의 스레드가 블로킹되어도  
    → 다른 스레드는 계속 실행 가능
    
2. 멀티코어 활용 가능  
    → 여러 스레드를 서로 다른 CPU 코어에서 병렬 실행
    
3. OS 차원의 안정적인 스케줄링
    

---

## 단점

1. 생성 비용이 상대적으로 큼  
    → 커널 모드 전환 필요
    
2. 컨텍스트 스위칭 비용이 큼  
    → 커널 개입
    

---

# 2. 사용자 스레드 (User-Level Thread)

## 개념

> 커널이 아닌 사용자 라이브러리에서 관리하는 스레드

- 커널은 프로세스 하나만 인식
    
- 스레드 스케줄링은 사용자 공간에서 처리
    

---

## 동작 구조

```
User Thread 1 ──┐
User Thread 2 ──┼─→ Kernel sees 1 Process only
User Thread 3 ──┘
```

- 여러 사용자 스레드가
    
- 하나의 커널 실행 단위에 매핑됨 (N:1 모델)
    

---

## 장점

1. 생성 및 전환 속도가 매우 빠름  
    → 커널 모드 전환 없음
    
2. 구현이 단순하고 오버헤드 적음
    

---

## 단점

1. 하나의 스레드가 블로킹되면  
    → 전체 프로세스가 블로킹
    
2. 멀티코어 병렬 실행 불가  
    → 커널은 프로세스 하나만 인식
    
3. 커널이 스레드 단위로 스케줄링 불가
    

---

# 차이점 정리

|구분|커널 스레드|사용자 스레드|
|---|---|---|
|관리 주체|커널|사용자 라이브러리|
|스케줄링|커널|사용자 공간|
|블로킹 영향|해당 스레드만|전체 프로세스|
|멀티코어 활용|가능|불가능 (N:1)|
|생성 비용|상대적으로 큼|매우 작음|
|컨텍스트 스위칭|커널 개입|사용자 공간|

---

# 추가 개념: 혼합 모델 (M:N)

일부 운영체제는:

- 사용자 스레드 여러 개를
    
- 커널 스레드 여러 개에 매핑
    

하는 M:N 모델을 사용하기도 한다.

리눅스는 현재 **1:1 커널 스레드 모델**을 사용한다.

---

# 한 문장 정리

> 커널 스레드는 운영체제가 직접 관리하여 병렬성과 안정성이 높지만 비용이 크고, 사용자 스레드는 빠르고 가볍지만 블로킹과 병렬성에 제약이 있다.
