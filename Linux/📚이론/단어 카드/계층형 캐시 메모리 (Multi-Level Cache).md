
CPU와 메모리 사이의 속도 차이를 줄이기 위해  
캐시를 **여러 단계(L1, L2, L3)** 로 구성한 구조

---

## 왜 계층이 필요한가?

- 캐시는 빠르지만 비쌈
    
- 크게 만들수록 느려짐
    
- 작게 만들수록 빠르지만 저장 공간이 부족
    

→ **빠름 + 용량 확보**를 동시에 만족시키기 위해 단계적으로 구성

---

## 기본 구조

```
CPU
 ↓
L1 Cache  (가장 빠름, 가장 작음)
 ↓
L2 Cache  (중간 속도, 중간 크기)
 ↓
L3 Cache  (느리지만 큼, 여러 코어가 공유)
 ↓
Main Memory (DRAM)
```

---

## 각 단계 특징

### 1. L1 Cache

- CPU 코어 내부에 존재
    
- 가장 빠름
    
- 용량 매우 작음 (수십 KB 수준)
    
- 보통 명령어 캐시 / 데이터 캐시 분리
    

---

### 2. L2 Cache

- L1보다 크고 느림
    
- 보통 코어별로 존재
    
- 수백 KB ~ 수 MB
    

---

### 3. L3 Cache

- 여러 코어가 공유
    
- L2보다 크고 느림
    
- 수 MB ~ 수십 MB
    

---

## 동작 흐름

CPU가 데이터 요청

```
1. L1 확인
2. 없으면 L2 확인
3. 없으면 L3 확인
4. 없으면 메모리 접근 (Cache Miss)
```

→ 아래로 갈수록 느려짐

---

## 핵심 목적

- 평균 메모리 접근 시간을 줄이기 위함
    
- 참조 지역성(시간적, 공간적)을 활용
    

---

## 한 줄 정리

계층형 캐시는  
**작고 빠른 캐시를 CPU 가까이에 두고,  
아래로 갈수록 크고 느린 캐시를 배치하여  
속도와 용량을 동시에 확보하는 구조**이다.
