리눅스에서 파일, 디렉토리, 프로세스 등의 자원 접근을 통제하는 대표적인 방식은 DAC와 MAC이다.

---

# 1. DAC (Discretionary Access Control)

임의적 접근 통제

객체(파일 등)의 소유자가 접근 권한을 결정하는 방식이다.

## 특징

- 파일 소유자가 권한을 설정
    
- `chmod`, `chown`으로 제어
    
- 사용자(owner) / 그룹(group) / 기타(others) 권한 구조
    
- 리눅스의 기본 권한 모델
    

예:

```bash
chmod 644 file.txt
```

권한 구조:

```text
rwx r-x r--
│   │   └── others
│   └────── group
└────────── owner
```

## 장점

- 단순하고 이해하기 쉬움
    
- 유연함
    
- 관리가 비교적 쉬움
    

## 단점

- 소유자가 권한을 자유롭게 변경 가능
    
- root 권한이면 대부분 접근 가능
    
- 보안 강도가 상대적으로 낮음
    

---

# 2. MAC (Mandatory Access Control)

강제적 접근 통제

시스템 정책이 접근을 강제로 통제하는 방식이다.  
사용자가 임의로 정책을 변경할 수 없다.

## 특징

- 중앙 정책 기반 통제
    
- 보안 레이블(label) 사용
    
- 관리자라도 정책 위반 시 차단 가능
    
- DAC보다 강한 보안 모델
    

대표 구현:

- SELinux
    
- AppArmor
    

예를 들어, 파일 권한이 777이어도  
MAC 정책에서 허용하지 않으면 접근이 차단된다.

---

# 3. 핵심 차이 비교

|구분|DAC|MAC|
|---|---|---|
|통제 주체|파일 소유자|시스템 정책|
|권한 변경|소유자 가능|사용자 불가|
|보안 강도|상대적으로 낮음|높음|
|대표 예|chmod 기반 권한|SELinux, AppArmor|

---

# 4. 동작 관계

리눅스에서는 일반적으로 다음 순서로 검사한다.

1. DAC 검사
    
2. MAC 검사
    

즉,

- DAC에서 거부되면 즉시 접근 불가
    
- DAC를 통과해도 MAC에서 거부될 수 있음
    

MAC은 DAC 위에 추가된 보안 계층이라고 볼 수 있다.

---

# 한 줄 정리

DAC는 사용자가 파일 권한을 결정하는 방식이고, MAC은 시스템 정책이 강제로 접근을 통제하는 방식이며, MAC이 더 강한 보안을 제공한다.
