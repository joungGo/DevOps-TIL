리눅스에서 링크는 **하나의 파일을 여러 이름으로 참조하는 방법**이다.  
두 종류가 있다:

- 하드 링크 (Hard Link)
    
- 심볼릭 링크 (Symbolic Link)
    

---

# 1. 하드 링크 (Hard Link)

> 같은 inode를 공유하는 또 다른 파일 이름

파일 시스템 내부에서 **같은 inode 번호를 가리킨다.**

## 특징

- 원본과 동일한 inode 사용
    
- 구분되는 “원본” 개념이 없음
    
- 하나를 삭제해도 다른 링크가 남아있으면 데이터 유지
    
- 다른 파일 시스템으로는 생성 불가
    
- 디렉토리에는 일반적으로 생성 불가
    

## 생성

```bash
ln original.txt hardlink.txt
```

## 구조 개념

```text
inode 1234
 ├─ original.txt
 └─ hardlink.txt
```

두 파일은 완전히 동일한 데이터 블록을 공유한다.

---

# 2. 심볼릭 링크 (Symbolic Link, Soft Link)

> 다른 파일을 가리키는 “경로 기반 포인터”

일종의 바로가기 파일이다.

## 특징

- 별도의 inode 가짐
    
- 원본 파일의 경로를 저장
    
- 다른 파일 시스템에도 생성 가능
    
- 디렉토리에도 생성 가능
    
- 원본 삭제 시 깨진 링크가 됨 (dangling link)
    

## 생성

```bash
ln -s original.txt symlink.txt
```

## 구조 개념

```text
symlink.txt → "original.txt"
```

---

# 3. 핵심 차이 비교

|구분|하드 링크|심볼릭 링크|
|---|---|---|
|기준|inode 공유|경로 참조|
|inode 번호|동일|다름|
|파일 시스템|동일 FS만 가능|다른 FS 가능|
|원본 삭제 시|데이터 유지|깨짐|
|디렉토리 링크|보통 불가|가능|

---

# 4. 삭제 시 동작 차이

## 하드 링크

```text
파일 A 삭제 → 링크 B 남아있으면 데이터 유지
```

inode의 link count가 0이 될 때까지 데이터 유지.

## 심볼릭 링크

```text
원본 삭제 → 링크는 남지만 접근 불가
```

---

# 한 줄 정리

하드 링크는 같은 inode를 공유하는 또 다른 이름이고, 심볼릭 링크는 파일 경로를 가리키는 별도의 참조 파일이다.
