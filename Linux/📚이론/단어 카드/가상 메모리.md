## 가상 메모리가 없을 때 발생하는 문제점

### 1. 메모리 단편화 문제

가상 메모리가 없는 경우, 프로세스는 **연속된 물리 메모리 공간**을 직접 할당받아야 한다.

예를 들어,

- 사용 가능한 메모리 총량이 300바이트이더라도
    
- 실제 물리 메모리가 100바이트씩 3개 영역으로 단편화되어 있다면
    

→ 100바이트를 초과하는 연속 메모리 할당은 불가능하다.

이로 인해 발생하는 문제는 다음과 같다.

- 프로그램은 메모리 할당 시  
    연속된 물리 메모리 영역이 존재하는지 직접 확인해야 함
    
- 메모리 관리 로직이 복잡해지고
    
- 단편화가 심해질수록 메모리 활용 효율이 급격히 떨어짐
    

---

### 2. 멀티 프로세스 구현의 어려움

가상 메모리가 없다면, 실행 파일의 코드와 데이터는 **물리 메모리의 특정 주소**에 직접 적재된다.

- 실행 파일을 실행하여 프로세스 A가 생성되면  
    코드와 데이터가 물리 메모리의 특정 영역에 배치됨
    
- 동일한 실행 파일로 프로세스 B를 생성하면  
    같은 물리 주소를 사용하려 하여 충돌이 발생
    

즉,

- 하나의 실행 파일을 동시에 여러 번 실행하는 것이 불가능하거나
    
- 강제로 서로 다른 물리 주소를 수동으로 관리해야 하는 문제가 발생
    

이는 현대 운영체제에서 필수적인 **멀티 프로세스 환경을 사실상 불가능하게 만든다**.

---

### 3. 비정상적인 메모리 영역 접근 가능

물리 메모리를 직접 사용하는 환경에서는 다음 문제가 발생한다.

- 한 프로세스가
    
    - 다른 프로세스의 메모리 영역
        
    - 심지어 커널이 사용하는 메모리 영역까지
        
- 접근하거나 수정할 수 있음
    

이로 인해

- 데이터 유출
    
- 데이터 손상
    
- 시스템 전체 불안정
    

과 같은 **치명적인 보안 및 안정성 문제**가 발생한다.

---

## 가상 메모리 개념

시스템에 실제로 장착된 메모리의 주소를 **물리 주소(Physical Address)** 라고 한다.  
물리 주소를 통해 접근 가능한 전체 범위를 **물리 주소 공간**이라고 한다.

하지만 프로세스는 **물리 주소 공간에 직접 접근할 수 없다**.

프로세스가 사용하는 주소는 모두 **가상 주소(Virtual Address)** 이며,  
이 주소들의 집합을 **가상 주소 공간**이라고 한다.

> [!Tip]
> 가상 주소 공간은 프로세스마다 생성된다.


---

## 가상 주소 → 물리 주소 변환

프로세스가 사용하는 가상 주소는 반드시  
실제 메모리 주소인 물리 주소로 변환되어야 한다.

이를 가능하게 하는 핵심 구조가 **페이지 테이블(Page Table)** 이다.

- 페이지 테이블은  
    가상 주소 공간의 페이지와  
    물리 메모리의 페이지(프레임)를 매핑한 정보
    
- 이 매핑 정보의 한 항목을 **페이지 테이블 엔트리(PTE)** 라고 한다
    
- CPU는 메모리를 **페이지 단위**로 관리하며  
    주소 변환 역시 페이지 단위로 수행한다
    

역할 분담은 다음과 같다.

- 페이지 테이블 생성 및 관리: **커널**
    
- 가상 주소 → 물리 주소 변환: **CPU(MMU)**

## 페이지 폴트(Page Fault)와 예외 처리

가상 주소 공간은 논리적으로는 고정되어 있지만,  
모든 가상 주소가 항상 물리 메모리와 매핑되어 있는 것은 아니다.

다음과 같은 상황에서 문제가 발생한다.

- 매핑되지 않은 가상 주소에 접근
    
- 접근 권한이 없는 페이지에 접근
    

이때 발생하는 예외를 **페이지 폴트(Page Fault)** 라고 한다.

- 페이지 폴트는 **예외(Exception)** 의 일종
    
- CPU가 이를 감지하면
    
- 커널의 **페이지 폴트 핸들러**가 실행된다
    

>페이지 폴트를 “감지”하는 주체는 CPU이고,  
  페이지 폴트 핸들러는 CPU가 감지한 예외를 “처리”하는 커널 코드다.

>감지한 예외를 처리 
>= 이 상황에서 프로그램을 계속 실행할 수 있는지 판단하고,  가능하면 복구하고, 
>    아니면 정리하고 끝내는 과정

처리 결과로,

- 정상적인 경우: 페이지를 할당하거나 매핑을 수정
    
- 비정상적인 경우: `SIGSEGV` 시그널을 프로세스에 전달하여 강제 종료

## 가상 메모리를 통한 문제 해결

가상 메모리는 앞서 언급한 모든 문제를 해결한다.

- **메모리 단편화 해결**
    
    - 물리 메모리가 단편화되어 있어도 가상 주소는 연속적으로 보이게 할 수 있음
        
- **멀티 프로세스 지원**
    
    - 모든 프로세스는 고유한 가상 주소를 가지므로 독립적인 가상 주소 공간을 보유
        
    - 동일한 실행 파일을 여러 번 실행 가능
        
- **메모리 보호**
    
    - 프로세스는 자신의 가상 주소 공간만 접근 가능
        
    - 커널 및 다른 프로세스 메모리 보호
        

---

### 핵심 요약

가상 메모리는  
**물리 메모리를 직접 사용하는 데서 발생하는 단편화, 충돌, 보안 문제를 해결하기 위해**  
가상 주소 공간과 페이지 테이블을 이용해 메모리 접근을 추상화하고 보호하는 핵심 운영체제 기술이다.
