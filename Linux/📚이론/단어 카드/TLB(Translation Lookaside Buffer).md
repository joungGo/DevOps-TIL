**TLB**는 가상 주소 → 물리 주소 변환 결과를 **캐시하는 작은 고속 메모리**다.

CPU 안에 있으며, 메모리 접근 속도를 크게 좌우한다.

---

# 1. 왜 필요한가?

프로세스는 **가상 주소**를 사용한다.  
하지만 실제 메모리는 **물리 주소**로 접근한다.

주소 변환 과정:

```
가상 주소
→ 페이지 테이블 조회
→ 물리 주소
→ 메모리 접근
```

문제는:

- 페이지 테이블은 메모리에 있음
    
- 즉, 주소 변환하려고 또 메모리를 읽어야 함
    

→ 매우 느려진다.

그래서 등장한 것이 TLB.

---

# 2. TLB의 역할

TLB는 최근 사용한:

```
가상 페이지 번호(VPN) → 물리 페이지 번호(PPN)
```

를 저장해 둔다.

동작 흐름:

1. CPU가 가상 주소 생성
    
2. TLB 먼저 조회
    
3. 있으면 → 바로 물리 주소 계산 (TLB hit)
    
4. 없으면 → 페이지 테이블 조회 (TLB miss)
    

---

# 3. 성능 영향

### TLB hit

- 매우 빠름 (CPU 내부 캐시 수준)
    

### TLB miss

- 페이지 테이블 접근 필요
    
- 메모리 접근 여러 번 발생
    
- 성능 급격히 저하
    

따라서:

> TLB hit율이 전체 메모리 성능을 결정한다.

---

# 4. TLB와 컨텍스트 스위칭

프로세스가 바뀌면:

- 각 프로세스는 서로 다른 페이지 테이블 사용
    
- 기존 TLB 엔트리는 무효화 필요 (TLB flush)
    

→ 컨텍스트 스위칭 비용 증가 원인 중 하나

이를 줄이기 위해:

- ASID(Address Space ID) 사용
    
- 프로세스별 TLB 엔트리 구분
    

---

# 5. Huge Page와 TLB

페이지 크기가 크면:

- 하나의 TLB 엔트리가 더 많은 메모리 커버
    
- TLB miss 감소
    

그래서 대용량 메모리 시스템에서는 Huge Page 사용.

---

# 핵심 정리

TLB는 가상 주소를 물리 주소로 변환한 결과를 캐시해 두는 CPU 내부 캐시이며, TLB miss가 발생하면 성능이 크게 떨어진다.
