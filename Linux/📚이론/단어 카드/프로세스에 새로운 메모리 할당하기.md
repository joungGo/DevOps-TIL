## 프로세스에 새로운 메모리 할당

### 1. 개요

리눅스에서 프로세스가 새로운 메모리를 요청할 때, 커널은 **물리 메모리를 즉시 할당하지 않고**, 먼저 **가상 주소 공간(Virtual Address Space)** 에 메모리 영역을 확보한다.  
실제 물리 메모리는 해당 메모리에 **처음 접근하는 시점**에 할당되며, 이 방식이 **Demand Paging(요구 페이징)** 이다.

---

### 2. 일반적인 메모리 할당 절차 (개념적 흐름)

1. 프로세스는 `xx` 바이트의 메모리가 필요하다고 **시스템 콜**을 통해 커널에 요청한다.
    
2. 커널은 요청을 처리하며, 즉시 물리 메모리를 할당하지 않고  
    프로세스의 **가상 주소 공간에서 연속된 메모리 영역**을 확보한다.
    
3. 확보된 가상 메모리 영역을 **프로세스의 가상 주소 공간에 매핑**한다.
    
4. 해당 가상 메모리 영역의 **시작 가상 주소**를 프로세스에게 반환한다.
    

중요한 점은, 이 시점에서는 **물리 메모리 할당이 완료되지 않았을 수 있다**는 것이다.

---

### 3. 메모리 영역 할당과 실제 메모리 할당의 분리

추가적인 메모리 할당을 위해 커널에 요청할 때,  
리눅스는 **물리 주소 공간부터 확보하지 않는다**.

대신 다음 두 단계를 분리해서 처리한다.

#### 1단계: 메모리 영역 할당 (Virtual Memory Area 확보)

- 프로세스의 **가상 주소 공간**에 새로운 메모리 영역(VMA)을 생성
    
- 아직 물리 메모리와는 연결되지 않음
    

#### 2단계: 메모리 할당 (물리 메모리 할당)

- 해당 가상 메모리에 실제로 접근할 때 수행
    
- 페이지 단위로 물리 메모리를 할당
    

---

### 4. `mmap()` 시스템 콜과 가상 메모리 매핑

- `mmap()` 시스템 콜은 대표적인 메모리 매핑 방식이다.
    
- 인자로 **매핑할 메모리 영역의 크기**를 지정할 수 있다.
    

`mmap()` 호출 시 내부 동작 흐름은 다음과 같다.

1. 시스템 콜 호출로 인해 CPU가 **커널 모드**로 전환된다.
    
2. 커널의 메모리 관리 서브시스템이
    
    - 프로세스의 **페이지 테이블** 및
        
    - 가상 메모리 영역(VMA) 정보를 수정한다.
        
3. 요청된 크기만큼의 **가상 주소 영역을 페이지 테이블에 등록**한다.
    
4. 해당 가상 메모리 영역의 **시작 가상 주소**를 프로세스에게 반환한다.
    

이 시점에서 중요한 특징은 다음과 같다.

- 페이지 테이블에는 **가상 주소에 대한 엔트리만 존재**
    
- **물리 주소는 아직 매핑되지 않음**
    

---

### 5. Demand Paging (요구 페이징)

`mmap()` 호출 직후의 상태는 다음과 같다.

- 가상 주소 공간은 확보되어 있음
    
- 페이지 테이블 엔트리는 존재함
    
- 하지만 해당 페이지에 대응되는 **물리 메모리는 할당되지 않음**
    

이후 동작 과정은 다음과 같다.

1. 프로세스가 새롭게 확보한 메모리 영역 내부의 페이지에 **처음 접근**
    
2. 페이지 테이블을 확인했을 때
    
    - 가상 주소는 존재
        
    - 하지만 물리 주소가 매핑되지 않은 상태
        
3. 이 경우 **페이지 폴트(Page Fault)** 가 발생
    
4. 커널은 페이지 폴트 핸들러에서
    
    - 새로운 물리 페이지(Frame)를 할당
        
    - 가상 주소와 물리 주소를 페이지 테이블에 매핑
        
5. 중단되었던 명령을 다시 실행하여 정상적으로 메모리 접근 수행
    

즉, 페이지 폴트는 항상 오류가 아니라  
**정상적인 메모리 할당 트리거**로 사용된다.

---

### 6. 핵심 정리

- 리눅스는 메모리 요청 시 **가상 주소 공간부터 확보**
    
- 물리 메모리는 **실제 접근 시점에 페이지 단위로 할당**
    
- 이를 통해
    
    - 불필요한 물리 메모리 낭비를 줄이고
        
    - 대규모 메모리 요청도 효율적으로 처리 가능
        
- 이 구조의 핵심 개념이 **Demand Paging** 이다.
