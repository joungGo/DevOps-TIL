# 1. 랜덤 접근 병목

## 1) HDD에서의 랜덤 접근 병목

HDD는 기계식 장치다.

랜덤 I/O가 발생하면:

1. 스윙 암 이동 (Seek)
    
2. 플래터 회전 대기
    
3. 데이터 읽기/쓰기
    

이 과정이 **매 요청마다 반복**된다.

결과:

- 레이턴시 급증
    
- IOPS 급감
    
- 스루풋 저하
    

즉,

```
랜덤 I/O ↑ → 헤드 이동 ↑ → 성능 급락
```

이것이 HDD의 랜덤 접근 병목이다.

---

## 2) SSD에서는?

SSD는:

- 기계 이동 없음
    
- 주소 기반 접근
    

따라서 랜덤 읽기 병목은 거의 사라진다.

하지만:

- 쓰기 증폭
    
- 가비지 컬렉션
    
- 내부 블록 삭제
    

같은 다른 형태의 병목은 존재할 수 있다.

---

# 2. 락 경합 (Lock Contention)

## 1) 발생 배경

과거 블록 계층은 **단일 요청 큐** 구조였다.

```
여러 CPU 코어
      ↓
   하나의 I/O 큐
```

이 큐를 보호하기 위해 **스핀락** 사용.

---

## 2) 멀티코어 환경 문제

CPU 코어가 증가하면:

- 여러 코어가 동시에 I/O 요청
    
- 같은 큐에 접근
    
- 같은 락을 획득하려고 경쟁
    

결과:

```
락 대기 시간 증가
→ CPU 낭비
→ 확장성 저하
```

이것이 락 경합 문제.

---

# 3. 실제 병목 상황 예시

## (1) HDD + 단일 큐

- 랜덤 접근 병목 (물리적 한계)
    
- 락 경합도 존재
    
- 병목이 장치 + 커널 양쪽에서 발생
    

---

## (2) SSD + 단일 큐

- 장치는 빠름
    
- 하지만 큐 락이 병목
    

즉:

```
디스크는 빠른데
커널에서 막힘
```

이 상황이 실제로 발생했다.

---

# 4. 해결: 멀티 큐 (Multi-Queue)

NVMe + blk-mq 도입

구조:

```
코어별 I/O 큐
→ 장치 내부 다중 큐
```

효과:

- 큐당 락 분산
    
- 락 경합 감소
    
- 코어 수에 비례해 IOPS 확장
    

---

# 정리

## 랜덤 접근 병목

- HDD의 물리적 한계
    
- 랜덤 I/O 시 헤드 이동 때문에 성능 급락
    

## 락 경합

- 단일 I/O 큐 보호를 위한 락 경쟁
    
- 멀티코어 환경에서 확장성 저하 원인
    

---

# 핵심 한 줄

HDD 시대의 병목은 물리적 랜덤 접근이었고, SSD 시대의 병목은 커널 단일 큐에서 발생하는 락 경합이었다.
