웹 애플리케이션이 **고객 정보를 저장장치에서 읽어오는 전체 흐름**과  
각 단계에서 성능에 영향을 주는 요소를 정리한다.

---

# 전체 처리 흐름

```
사용자 요청
→ 웹 서버
→ 애플리케이션 서버
→ DB 서버
→ 파일 시스템
→ 페이지 캐시
→ 블록 계층
→ 저장 장치 (SSD/HDD)
→ 다시 역순으로 응답
```

---

# 단계별 성능 영향 요소

## 1. 네트워크 구간

### 영향 요소

- RTT (왕복 지연)
    
- 대역폭
    
- TLS 처리 비용
    
- 로드밸런서
    

네트워크 지연이 크면  
디스크가 빨라도 전체 응답 시간은 느려진다.

---

## 2. 웹/애플리케이션 서버

### 영향 요소

- 스레드/이벤트 모델
    
- CPU 사용률
    
- GC (Java 등)
    
- 동시성 처리 능력
    

CPU 병목이 발생하면  
디스크 접근 전 단계에서 이미 지연 발생.

---

## 3. DB 처리 단계

가장 중요한 구간 중 하나.

### 영향 요소

- 인덱스 존재 여부
    
- 쿼리 실행 계획
    
- 조인 방식
    
- 버퍼 캐시 적중률
    
- 락 경합
    

예:

- 인덱스 있음 → 랜덤 소수 블록 읽기
    
- 인덱스 없음 → 테이블 풀 스캔 (대량 I/O)
    

---

## 4. 페이지 캐시 (OS 메모리)

DB가 요청한 블록이 이미 메모리에 있다면:

```
디스크 접근 없이 RAM에서 반환
```

→ 매우 빠름

### 성능 결정 요소

- 메모리 크기
    
- 캐시 적중률
    
- 워킹셋 크기
    

캐시 히트면 μs 단위  
미스면 디스크 접근 → ms 단위

---

## 5. 페이지 테이블 / 메모리 접근

- TLB 히트 여부
    
- 캐시 계층(L1/L2/L3)
    

이 구간은 보통 디스크보다 훨씬 빠르지만  
고부하 환경에서는 영향 존재.

---

## 6. 블록 계층

### 영향 요소

- I/O 스케줄링
    
- 큐 깊이
    
- 멀티 큐 여부
    
- 락 경합
    

특히 고동시성 환경에서 중요.

---

## 7. 저장 장치

### HDD인 경우

- 랜덤 접근 병목
    
- Seek time
    
- IOPS 낮음
    

### SSD인 경우

- 랜덤 접근 빠름
    
- 큐 깊이에 따라 IOPS 증가
    
- 내부 병렬성
    

NVMe는 고부하 환경에서 특히 유리.

---

# 병목이 발생하는 대표 상황

## 1. 캐시 미스 + HDD

→ 디스크 랜덤 접근 병목  
→ 응답 시간 급증

---

## 2. 동시 요청 많음 + 단일 큐

→ 락 경합  
→ CPU 대기

---

## 3. 인덱스 없음

→ 불필요한 대량 블록 읽기  
→ I/O 폭증

---

## 4. 메모리 부족

→ 페이지 캐시 감소  
→ 디스크 접근 증가

---

# 결국 성능을 좌우하는 핵심 5가지

1. 네트워크 지연
    
2. 애플리케이션 동시성 처리 능력
    
3. DB 인덱스/쿼리 설계
    
4. 메모리 캐시 적중률
    
5. 저장장치 IOPS 및 병렬성
    

---

# 가장 큰 차이를 만드는 요소

실무에서 체감 성능을 가장 크게 좌우하는 것은:

1. 인덱스 설계
    
2. 캐시 히트율
    
3. SSD vs HDD 차이
    

이다.

# 한 줄 정리

웹 애플리케이션의 디스크 접근 성능은 단순히 저장장치 속도 문제가 아니라, 캐시 적중률·쿼리 설계·동시성 처리·블록 계층 구조까지 포함한 전체 시스템 경로에서 결정된다.
