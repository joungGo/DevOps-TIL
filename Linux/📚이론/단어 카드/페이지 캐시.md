## 페이지 캐시 (Page Cache)

디스크 I/O 성능을 향상시키기 위해  
**파일 데이터를 메모리(DRAM)에 캐시해두는 커널 내부 캐시**

---

## 왜 필요한가?

디스크는 메모리보다 매우 느림.

대략적인 속도 차이:

```
CPU 캐시  <<  DRAM  <<  SSD  <<  HDD
```

파일을 매번 디스크에서 읽으면 성능이 크게 저하됨.

→ 자주 사용하는 파일 데이터를 메모리에 저장해두고 재사용

---

## 무엇을 캐시하는가?

페이지 캐시는 **파일의 데이터 블록**을  
페이지 단위(보통 4KB)로 메모리에 저장함.

```
파일 데이터 (디스크)
        ↓
페이지 캐시 (메모리)
        ↓
프로세스에 전달
```

---

## 읽기 동작 흐름

1. 프로세스가 read() 호출
    
2. 커널이 페이지 캐시 확인
    
    - 있으면 → 메모리에서 바로 반환 (Cache Hit)
        
    - 없으면 → 디스크에서 읽고 캐시에 저장 후 반환 (Cache Miss)
        

---

## 쓰기 동작 흐름

1. 프로세스가 write() 호출
    
2. 디스크에 즉시 쓰지 않고
    
3. 페이지 캐시에 먼저 기록
    
4. 나중에 디스크에 반영 (비동기)
    

→ 이때 변경된 페이지는 **Dirty Page**

---

## 특징

- 커널이 자동 관리
    
- LRU 기반으로 교체
    
- 메모리가 부족하면 일부 페이지를 디스크에 반영 후 제거
    

---

## 메모리와 관계

페이지 캐시는 **물리 메모리(DRAM)** 의 일부를 사용함.

```
물리 메모리
 ├─ 사용자 프로세스 메모리
 └─ 페이지 캐시
```

---

## mmap()과의 관계

mmap()으로 파일을 매핑하면  
실제 데이터는 페이지 캐시를 통해 관리됨.

즉,

- read()도 페이지 캐시 사용
    
- mmap()도 페이지 캐시 사용
    

---

## 한 줄 정리

페이지 캐시는 파일 데이터를 디스크 대신 메모리에 저장해  
디스크 I/O를 줄이고 성능을 향상시키는 커널의 파일 캐시이다.
