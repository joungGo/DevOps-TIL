# 시그널(Signal) 종합 정리

## 1. 시그널이란 무엇인가

시그널은 **프로세스의 정상적인 실행 흐름에 비동기적으로 개입하여 상태 변화를 유도하는 메커니즘**이다.

프로세스는 기본적으로 자신의 코드 흐름(명령 실행 순서)에 따라 동작하지만,  
시그널을 통해 다음과 같은 일이 가능해진다.

- 프로세스 중단 / 종료
    
- 실행 재개
    
- 이벤트 알림 (자식 프로세스 종료 등)
    

시그널은 **커널 또는 다른 프로세스가 특정 프로세스에게 전달**한다.

---

## 2. 시그널은 언제 발생하는가 (generate)

시그널은 다음과 같은 상황에서 **발생**한다.

- 키보드 입력
    
    - `Ctrl + C` → SIGINT
        
- 다른 프로세스가 시그널 전송
    
    - `kill(pid, SIGTERM)`
        
- 자식 프로세스 상태 변경
    
    - 종료 시 → SIGCHLD
        
- 예외 상황
    
    - 잘못된 메모리 접근 → SIGSEGV
        
- 타이머 만료
    
    - SIGALRM
        

이 시점에서 커널은:

- 해당 프로세스에 **pending signal(대기 중 시그널)** 을 기록
    
- **아직 프로세스 실행 흐름에는 영향을 주지 않음**
    

중요한 점은,

> 시그널 발생과 시그널 수신은 같은 시점이 아니다.

---

## 3. 시그널은 언제 수신되는가 (delivery)

시그널은 **아무 때나 즉시 수신되지 않는다**.  
커널이 정한 **안전한 시점**에서만 전달된다.

대표적인 시점:

- 시스템 콜이 끝나고 사용자 모드로 복귀하기 직전
    
- 인터럽트 처리 후 사용자 모드로 복귀하기 직전
    
- 슬립 상태였던 프로세스가 깨어나 실행되기 직전
    

이 시점에서 커널은:

1. pending signal 확인
    
2. 시그널 마스크 확인
    
3. 전달 가능한 시그널이면 **수신 처리**
    

---

## 4. “시그널 처리는 동기적이다”의 의미

시그널은 **비동기적으로 발생**한다.  
즉, 프로세스 실행 흐름과 무관하게 언제든 발생할 수 있다.

하지만 **처리는 동기적으로 이루어진다**.

여기서 “동기적”이라는 말의 정확한 의미는 다음과 같다.

- CPU 명령어 한가운데에서 갑자기 끼어들지 않는다
    
- 커널이 **컨텍스트가 안정적인 지점**에서만 처리한다
    
- 주로 커널 → 사용자 모드 전환 시점
    

정리하면:

- 발생: 비동기
    
- 처리: 동기 (안전한 지점에서만)
    

---

## 5. 시그널을 수신했을 때의 처리 방식

프로세스는 각 시그널에 대해 다음 중 하나를 선택한다.

1. 기본 동작 (default action)
    
2. 무시 (ignore)
    
3. 시그널 핸들러 실행 (signal handler)
    

---

### 5-1. 시그널 핸들러가 등록된 경우

시그널 수신 시 흐름:

```
기존 사용자 코드 실행
        ↓
시그널 수신
        ↓
커널이 실행 상태 저장 (PC, 레지스터 등)
        ↓
시그널 핸들러 실행
        ↓
핸들러 종료
        ↓
원래 실행 지점으로 복귀
```

즉, 함수 호출처럼 보이지만  
실제로는 **커널이 강제로 실행 흐름을 변경**한 것이다.

---

### 5-2. 즉시 종료되는 것처럼 보이는 이유

SIGINT, SIGTERM 등의 기본 동작은 **프로세스 종료**다.

그래서 사용자는:

- “시그널을 받자마자 종료됐다”고 느끼지만
    
- 실제로는 **다음 시그널 처리 지점에서 종료**된 것이다.
    

---

## 6. 예외적인 시그널: SIGKILL, SIGSTOP

|시그널|특징|
|---|---|
|SIGKILL|무조건 종료, 핸들러 불가|
|SIGSTOP|무조건 정지, 핸들러 불가|

이 시그널들은:

- 사용자 코드가 개입할 수 없음
    
- 커널이 강제로 상태 변경
    

다만 이것도 **CPU 명령어 중간을 자르는 것은 아니고**,  
역시 커널이 개입 가능한 지점에서 처리된다.

---

## 7. 주요 시그널 정리 표

|시그널|의미|설명|
|---|---|---|
|SIGINT|Interrupt|Ctrl+C, 사용자 인터럽트|
|SIGTERM|Terminate|정상 종료 요청 (kill 기본)|
|SIGCHLD|Child|자식 프로세스 상태 변경|
|SIGSTOP|Stop|강제 정지|
|SIGCONT|Continue|정지된 프로세스 재개|
|SIGKILL|Kill|강제 종료|

---

## 8. 시그널과 시스템 콜의 관계

시스템 콜 수행 중 시그널이 수신되면:

- 시스템 콜이 중단될 수 있음
    
- 이 경우 `EINTR` 오류 반환
    
- 필요하면 시스템 콜을 재시도해야 함
    

이 특징은 서버/시스템 프로그래밍에서 매우 중요하다.

---

## 9. 시그널과 프로세스 상태 변화

시그널은 다음과 같은 상태 변화를 유발할 수 있다.

- 실행(Running) → 정지(Stopped) : SIGSTOP
    
- 정지 → 실행 가능(Runnable) : SIGCONT
    
- 실행 중 → 종료(Zombie) : SIGINT, SIGTERM 등
    

좀비 프로세스는 부모가 `wait()` 계열 시스템 콜로 회수해야 완전히 소멸한다.

---

## 10. 핵심 요약

- 시그널은 프로세스 흐름에 비동기적으로 개입하는 메커니즘이다
    
- 발생과 수신 시점은 다르다
    
- 처리는 안전한 지점에서 동기적으로 이루어진다
    
- SIGKILL, SIGSTOP은 예외적으로 강제적이다
    
- 시그널은 프로세스 제어와 상태 관리의 핵심 수단이다
    

---

이제 이 수준이면  
**프로세스 / 스케줄링 / 시스템 콜 / 시그널**이 하나의 큰 그림으로 연결된 상태야.

다음으로 이어서 정리하면 아주 좋은 주제는:

- 시그널 마스크와 pending signal
    
- `sigaction()`과 기존 `signal()`의 차이
    
- 시그널과 스레드의 관계
