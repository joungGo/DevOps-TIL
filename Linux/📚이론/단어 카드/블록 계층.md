# 1. 블록 계층이 등장한 배경

초기 리눅스가 설계되던 시점의 주요 저장 장치는 **하드 디스크(HDD)** 였다.

HDD는 **기계식 장치**이기 때문에:

- 탐색(Seek) 시간 발생
    
- 회전 지연(Rotational Latency) 발생
    
- 랜덤 접근이 매우 느림
    

따라서 운영체제는:

- 요청을 모아서
    
- 정렬하고
    
- 병합하고
    
- 순차적으로 접근하도록 조정할 필요가 있었음
    

이 역할을 담당하는 것이 **블록 계층(Block Layer)** 이다.

---

# 2. 하드 디스크 구조

HDD는 다음 요소로 구성된다.

---

## 1) 플래터 (Platter)

- 원판 형태의 자기 디스크
    
- 여러 장이 겹쳐 있음
    
- 실제 데이터가 기록되는 부분
    

데이터는 자기적으로 기록된다.

---

## 2) 섹터 (Sector)

- 데이터를 저장하는 최소 단위
    
- 보통 512B 또는 4KB
    

플래터는

```
Track(트랙) → Sector(섹터)
```

구조로 나뉜다.

---

## 3) 자기 헤드 (Read/Write Head)

- 데이터를 읽고 쓰는 장치
    
- 플래터 표면 가까이에 위치
    
- 직접 접촉하지 않음 (공기층 위에 떠 있음)
    

---

## 4) 스윙 암 (Swing Arm)

- 자기 헤드를 움직이는 기계 팔
    
- 원하는 트랙으로 이동시킴
    

이 이동 시간이 바로 **Seek Time**

---

# 3. HDD의 핵심 특성

## 1) 순차 접근이 빠름

연속된 섹터에 데이터가 있다면:

```
한 번 회전하면서 연속적으로 읽기 가능
```

→ 매우 빠름

---

## 2) 랜덤 접근이 느림

다른 위치의 데이터 요청 시:

```
1. 스윙 암 이동 (Seek)
2. 플래터 회전 대기
3. 데이터 읽기
```

→ 큰 지연 발생

---

# 4. 그래서 OS는 어떻게 했는가?

블록 계층에서:

- 요청 병합 (Request Merging)
    
- I/O 스케줄링 (엘리베이터 알고리즘 등)
    
- 인접 블록 정렬
    

목표:

```
랜덤 I/O → 순차 I/O처럼 만들기
```

이것이 HDD 시대 설계 철학이다.

---

# 5. SSD 등장 이후

SSD는 기계 부품이 없음.

- Seek time 없음
    
- 회전 지연 없음
    
- 랜덤 접근 빠름
    

따라서:

- I/O 스케줄러 중요도 감소
    
- 병합 효과 감소
    
- 병렬 큐(NVMe) 구조 등장
    

---

# 6. NVMe SSD의 차이

NVMe는:

- PCIe 기반
    
- 다중 큐 지원
    
- 높은 병렬성
    

HDD 시절의 “순차 배치 최적화” 중심 설계와는 다른 방향.

---

# 핵심 정리

HDD는 기계식 장치라

- 연속된 섹터 배치가 매우 중요
    
- 랜덤 접근이 느림
    
- 그래서 블록 계층과 I/O 스케줄링이 중요했음
    

SSD/NVMe는

- 기계 이동이 없음
    
- 랜덤 접근 빠름
    
- 병렬 처리 중심 구조
    

---

한 줄 정리:

블록 계층은 HDD의 기계적 한계를 보완하기 위해 등장했으며, 연속된 섹터에 데이터를 배치해 순차 접근을 극대화하는 것이 핵심 전략이었다.
