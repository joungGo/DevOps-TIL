# 프로세스 간 통신 (IPC, Inter-Process Communication)

리눅스에서 프로세스는 **서로 독립된 가상 주소 공간**을 가지므로  
기본적으로는 서로의 메모리에 접근할 수 없다.  
따라서 커널이 제공하는 **IPC 메커니즘**을 통해서만 통신이 가능하다.

대표적인 IPC 방식은 다음과 같다.

- 공유 메모리 (Shared Memory)
    
- 소켓 (Socket)
    
- 파이프 (Pipe)
    
- 시그널 (Signal)
    

---

## 1. 공유 메모리 (Shared Memory)

### 개념

- **여러 프로세스가 동일한 물리 메모리 영역을 공유**
    
- 각 프로세스의 가상 주소 공간에
    
    - 같은 물리 페이지를 매핑
        
- 커널 개입 없이 **메모리를 직접 읽고 쓰기 때문에 가장 빠른 IPC**
    

---

### 특징

- 장점
    
    - IPC 중 **가장 빠름**
        
    - 대용량 데이터 전송에 유리
        
- 단점
    
    - 동기화 문제 발생 가능
        
    - race condition 방지를 위해
        
        - 세마포어
            
        - 뮤텍스
            
        - 스핀락  
            등의 동기화 도구 필요
            

---

### 동작 흐름

1. 한 프로세스가 공유 메모리 생성
    
2. 다른 프로세스가 해당 공유 메모리에 attach
    
3. 두 프로세스는 동일한 메모리 영역에 접근
    
4. 데이터 읽기/쓰기 시 커널 개입 없음
    

---

### 예제 개념 (POSIX Shared Memory)

```
프로세스 A VA ──┐
                 ├─→ 공유 물리 페이지
프로세스 B VA ──┘
```

---

### 코드 예제 (개념 중심)

```c
int fd = shm_open("/myshm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);

void *addr = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
```

- `shm_open` : 공유 메모리 객체 생성
    
- `mmap` : 공유 물리 페이지를 가상 주소 공간에 매핑
    
- 이후 `addr`를 통해 메모리에 직접 접근
    

---

### 언제 사용하나

- 고성능 서버
    
- 멀티프로세스 캐시
    
- 대량 데이터 처리
    
- DB 엔진 내부 통신
    

---

## 2. 소켓 (Socket)

### 개념

- **프로세스 간 데이터 통신을 위한 통신 엔드포인트**
    
- 로컬 IPC뿐 아니라 **네트워크 통신까지 동일한 인터페이스 제공**
    
- 커널을 통해 데이터가 전달됨
    

---

### 특징

- 장점
    
    - 로컬 / 원격 통신 모두 가능
        
    - 구조화된 통신 (프로토콜 기반)
        
- 단점
    
    - 공유 메모리보다 느림
        
    - 커널 버퍼 복사 비용 존재
        

---

### 소켓 종류

- UNIX Domain Socket
    
    - 같은 머신 내 IPC
        
    - TCP/IP보다 빠름
        
- TCP/UDP Socket
    
    - 네트워크 통신
        

---

### 동작 흐름 (UNIX Domain Socket 기준)

1. 서버 프로세스가 소켓 생성 및 bind
    
2. 클라이언트 프로세스가 connect
    
3. 데이터 송수신
    
4. 커널이 버퍼를 통해 중계
    

---

### 예제 개념

```
프로세스 A
  ↓ write()
[ 커널 소켓 버퍼 ]
  ↑ read()
프로세스 B
```

---

### 언제 사용하나

- 마이크로서비스
    
- 클라이언트-서버 구조
    
- IPC + 네트워크 통신을 동일 코드로 처리하고 싶을 때
    

---

## 3. 공유 메모리 vs 소켓 비교

|항목|공유 메모리|소켓|
|---|---|---|
|성능|매우 빠름|상대적으로 느림|
|커널 개입|초기 설정만|매 송수신마다|
|데이터 복사|없음|있음|
|동기화|직접 처리 필요|비교적 단순|
|사용 난이도|높음|낮음|
|확장성|로컬 한정|네트워크 가능|

---

## 4. 파이프 (Pipe)

### 개념

- **단방향 데이터 스트림**
    
- 부모-자식 프로세스 간 통신에 주로 사용
    

---

### 특징

- 커널이 제공하는 버퍼를 통해 통신
    
- 파일 디스크립터 기반
    
- 읽기/쓰기 순서 보장
    

---

### 예시

```bash
ls | grep txt
```

- `ls` 출력이 파이프를 통해 `grep` 입력으로 전달됨
    

---

### 한계

- 단방향
    
- 관계 없는 프로세스 간 사용 어려움
    
- 대용량 데이터에 부적합
    

---

## 5. 시그널 (Signal)

### 개념

- **프로세스에 이벤트를 알리는 메커니즘**
    
- 데이터 전달이 목적이 아님
    

---

### 특징

- 매우 가볍고 빠름
    
- 전달 가능한 정보는 매우 제한적
    

---

### 예시

- `SIGKILL` : 프로세스 강제 종료
    
- `SIGINT` : Ctrl + C
    
- `SIGCHLD` : 자식 프로세스 종료 알림
    

---

## 최종 정리 한 문장

> 공유 메모리는 최고 성능의 IPC이지만 동기화 책임이 있고,  
> 소켓은 성능은 다소 낮지만 구조적이고 확장성이 뛰어나며,  
> 파이프와 시그널은 단순한 제어 및 데이터 전달에 사용된다.

---

원하면 다음 단계로:

- 공유 메모리에서 race condition 예제
    
- 소켓에서 zero-copy와의 관계
    
- IPC와 컨텍스트 스위칭 비용
    

이제 IPC 쪽도 커널 관점으로 거의 정복한 상태야.
