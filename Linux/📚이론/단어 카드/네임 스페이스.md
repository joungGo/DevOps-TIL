# 네임스페이스 종류 (4가지)

## 1) 프로세스 네임스페이스 (PID Namespace)

- 프로세스 ID 공간 분리
    
- 컨테이너 안에서는 자기 프로세스만 보임
    
- 컨테이너 내부에서 PID 1 존재
    

왜 필요한가?  
→ 다른 컨테이너나 호스트의 프로세스를 보지 못하게 하기 위해.

---

## 2) 사용자 네임스페이스 (User Namespace)

- UID/GID 분리
    
- 컨테이너 안의 root(UID 0)가  
    호스트에서는 일반 사용자일 수 있음
    

왜 필요한가?  
→ 보안 강화를 위해 (root 권한 격리).

---

## 3) 마운트 네임스페이스 (Mount Namespace)

- 파일 시스템 마운트 테이블 분리
    
- 컨테이너마다 다른 디렉토리 구조 가능
    

왜 필요한가?  
→ 컨테이너마다 독립된 파일 시스템을 제공하기 위해.

---

## 4) 루트 네임스페이스 (chroot 기반 개념)

- 프로세스의 루트 디렉토리(/)를 변경
    
- 특정 디렉토리를 루트처럼 사용
    

왜 필요한가?  
→ 파일 접근 범위를 제한하기 위해.

(실제로는 Mount Namespace + chroot 조합으로 구현됨)

---

# 한 줄 정리

프로세스, 사용자, 마운트, 루트 네임스페이스는 각각 프로세스 공간, 권한, 파일 시스템, 루트 경로를 분리해 컨테이너를 독립된 환경처럼 보이게 만든다.

---
# 전제

루트 PID 네임스페이스(호스트)가 있고,  
그 안에 새로운 PID 네임스페이스를 생성했다고 가정하자.

```
[루트 PID NS]
    └── [자식 PID NS]
```

---

# 1. 기본 원칙

**부모는 자식을 볼 수 있고,  
자식은 부모를 볼 수 없다.**

---

# 2. 누가 누구를 볼 수 있는가?

## ① 루트 네임스페이스 (부모)

- 자기 프로세스 보임
    
- 자식 PID 네임스페이스의 프로세스도 보임
    

즉:

```
호스트 → 컨테이너 프로세스 보임
```

예:

- 호스트에서 `ps` 실행하면
    
- 컨테이너 프로세스도 확인 가능
    

---

## ② 자식 PID 네임스페이스

- 자기 네임스페이스 내부 프로세스만 보임
    
- 부모(루트)의 프로세스는 보이지 않음
    

즉:

```
컨테이너 → 호스트 프로세스 안 보임
```

---

# 3. 왜 이런 구조인가?

PID 네임스페이스는 **트리 구조**다.

- 부모가 상위
    
- 자식은 하위
    

보안과 관리 목적 때문에:

- 상위는 하위를 관리 가능
    
- 하위는 상위에 접근 불가
    

---

# 4. PID 번호는 어떻게 되는가?

같은 프로세스라도:

- 부모 NS에서 보는 PID
    
- 자식 NS에서 보는 PID
    

가 다를 수 있다.

예:

```
호스트에서 PID 1234
컨테이너 안에서는 PID 1
```

하나의 프로세스가 여러 PID를 가질 수 있다  
(네임스페이스마다 다름)

---

# 5. 정리 표

|위치|부모 NS 프로세스|자식 NS 프로세스|
|---|---|---|
|부모 NS|보임|보임|
|자식 NS|안 보임|보임|

---

# 핵심 한 줄

PID 네임스페이스는 계층 구조이며, 부모는 자식을 볼 수 있지만 자식은 부모를 볼 수 없다.
