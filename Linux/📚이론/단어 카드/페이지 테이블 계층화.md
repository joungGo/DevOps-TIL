## 페이지 테이블 계층화 (Multi-level Page Table)

### 1. 왜 페이지 테이블을 계층화하는가

가상 메모리를 사용하는 시스템에서 프로세스는 매우 큰 가상 주소 공간을 가진다.  
예를 들어 64비트 시스템에서 이론적인 가상 주소 공간은 매우 크며, 이를 **단일 레벨 페이지 테이블**로 표현하면 다음과 같은 문제가 발생한다.

- 사용하지 않는 가상 주소 영역까지 포함한 거대한 페이지 테이블 필요
    
- 프로세스 하나당 페이지 테이블 크기가 과도하게 커짐
    
- 메모리 낭비 심화
    

이 문제를 해결하기 위해 페이지 테이블을 **계층 구조로 분할**하는 방식이 도입되었다.

---

### 2. 계층형 페이지 테이블의 기본 아이디어

페이지 테이블을 하나의 큰 배열로 관리하지 않고,  
**여러 단계의 테이블로 나누어 필요한 부분만 생성**한다.

- 상위 레벨 페이지 테이블
    
    - 하위 페이지 테이블의 위치를 가리킴
        
- 하위 레벨 페이지 테이블
    
    - 실제 가상 페이지와 물리 페이지의 매핑 정보를 저장
        

즉, 실제로 사용하는 가상 주소 영역에 대해서만  
하위 페이지 테이블이 동적으로 생성된다.

---

### 3. 가상 주소와 페이지 테이블 계층 분해

가상 주소는 다음과 같이 여러 필드로 나뉜다.

```
[ Level1 Index | Level2 Index | ... | Page Offset ]
```

- 각 Index는 해당 레벨의 페이지 테이블에서 사용할 인덱스
    
- Page Offset은 페이지 내부의 실제 바이트 위치
    

CPU의 **MMU(Memory Management Unit)** 는  
이 인덱스들을 이용해 상위 → 하위 페이지 테이블 순서로 접근한다.

---

### 4. 주소 변환 과정 (계층형 페이지 테이블)

1. CPU가 가상 주소를 생성
    
2. MMU가 가상 주소를 레벨별 인덱스로 분해
    
3. 최상위 페이지 테이블부터 순차적으로 탐색
    
4. 최하위 페이지 테이블에서
    
    - 대응되는 물리 페이지 번호(PFN) 확인
        
5. PFN + Page Offset을 결합하여 물리 주소 생성
    

만약 탐색 도중

- 해당 레벨의 엔트리가 존재하지 않거나
    
- 접근 권한이 맞지 않다면
    

페이지 폴트가 발생하고 커널이 개입한다.

---

### 5. 리눅스에서의 페이지 테이블 계층 구조

리눅스는 아키텍처에 따라 페이지 테이블 계층 수가 다르다.

대표적인 x86-64 구조 기준:

- PGD (Page Global Directory)
    
- P4D (Page 4th Directory)
    
- PUD (Page Upper Directory)
    
- PMD (Page Middle Directory)
    
- PTE (Page Table Entry)
    

실제 사용 계층 수는 CPU와 커널 설정에 따라 달라질 수 있지만,  
개념적으로는 **다단계 페이지 테이블**을 사용한다.

---

### 6. 계층화의 장점과 트레이드오프

#### 장점

- 사용하지 않는 가상 주소 영역에 대한 페이지 테이블 생성 불필요
    
- 프로세스당 페이지 테이블 메모리 사용량 감소
    
- 희소한 주소 공간(sparse address space)에 매우 효율적
    

#### 단점

- 주소 변환 시 여러 단계의 메모리 접근 필요
    
- 변환 비용 증가
    

이 단점을 보완하기 위해 CPU는 **[[TLB(Translation Lookaside Buffer)]]** 를 사용하여  
자주 사용하는 주소 변환 결과를 캐싱한다.

---

### 7. Demand Paging과의 관계

- 계층형 페이지 테이블은 **구조적 최적화**
    
- Demand Paging은 **운영 전략**
    

계층화는

- “페이지 테이블 자체를 언제/어떻게 생성할 것인가”에 대한 문제를 해결하고,
    

Demand Paging은

- “물리 메모리를 언제 할당할 것인가”를 해결한다.
    

두 개념은 서로 다른 문제를 다루지만,  
함께 사용될 때 가상 메모리 시스템의 효율이 극대화된다.

---

### 8. 한 문장 요약

페이지 테이블 계층화란, 거대한 가상 주소 공간을 여러 단계의 페이지 테이블로 분할하여, 실제로 사용하는 주소 영역에 대해서만 페이지 테이블을 생성함으로써 메모리 낭비를 줄이는 기법이다.
