# 파일 시스템의 역할

파일 시스템이 없다면, 프로그램은 다음을 직접 관리해야 한다:

* 디스크의 **어느 물리 블록에 데이터를 저장할지 결정**
* 다른 데이터와 겹치지 않도록 **빈 공간 관리**
* 파일의 **위치, 크기, 구조 정보 기억**
* 나중에 다시 읽을 수 있도록 **저장 위치 추적**

이러한 복잡한 관리 작업을 대신 수행하는 것이 **파일 시스템(File System)** 이다.

즉,

> 파일 시스템은 저장 장치를 추상화하여
> 사용자가 “파일”이라는 논리적 단위로 데이터를 다룰 수 있게 해주는 계층이다.

---

# 리눅스 파일 시스템의 구조

## 1. 디렉터리 구조

리눅스에서 디렉터리는 특수한 파일이다.

* 디렉터리는 **파일 이름과 inode 번호의 매핑 정보**를 저장
* 디렉터리 안에 또 다른 디렉터리를 생성 가능
* 전체 구조는 **트리 구조**

```
/
 ├── home/
 │    ├── user/
 │    │     └── file.txt
 └── var/
```

같은 파일 이름이라도 디렉터리가 다르면 공존 가능하다.

```
/home/a/file.txt
/home/b/file.txt
```

# 데이터와 메타데이터

파일 시스템이 관리하는 정보는 두 가지로 나뉜다.

## 1. 데이터 (Data)

실제 사용자 내용:

* 문서
* 이미지
* 동영상
* 실행 파일
* 로그 등

---

## 2. 메타데이터 (Metadata)

파일을 관리하기 위한 정보:

* 파일 크기
* 소유자
* 권한 (rwx)
* 생성/수정 시간
* 블록 위치 정보
* 링크 수
* inode 번호

리눅스에서는 이런 메타데이터를 **inode 구조체**가 관리한다.

---

# POSIX 인터페이스

리눅스는 POSIX 표준을 따르는 시스템 콜을 제공한다.

## 파일 조작

* open()
* close()
* read()
* write()
* unlink()
* stat()

---

## 디렉터리 조작

* mkdir()
* rmdir()
* chdir()
* opendir()
* readdir()

이 함수들은 결국 시스템 콜을 통해 커널로 진입한다.

---

# 파일 저장 시 내부 처리 흐름

예:

```
write(fd, buffer, size)
```

## 1단계: 사용자 공간

* 프로세스가 write() 호출
* 라이브러리가 시스템 콜 발생
* CPU가 커널 모드로 전환

---

## 2단계: VFS 계층

커널 내부에는 **VFS (Virtual File System)** 가 존재한다.

VFS는:

* 파일 시스템을 추상화하는 계층
* ext4, xfs, tmpfs 등 다양한 파일 시스템을 동일 인터페이스로 처리

VFS는:

* 파일 디스크립터 확인
* inode 구조 확인
* 해당 파일 시스템의 구현 함수 호출

---

## 3단계: 파일 시스템 계층 (예: ext4)

파일 시스템은:

* 논리 블록 번호 계산
* 파일 오프셋 계산
* page cache 확인

일반적으로 쓰기는 먼저 **page cache(메모리)** 에 기록된다.

즉,

```
사용자 버퍼 → 커널 버퍼(page cache)
```

이후 write-back 방식으로 디스크에 반영된다.

---

## 4단계: 블록 계층

파일 시스템은 실제 디스크 블록 I/O 요청을 생성한다.

블록 계층은:

* 요청 큐에 등록
* 병합 및 정렬
* 디스크 스케줄링 수행

---

## 5단계: 디바이스 드라이버

블록 계층은 해당 저장 장치 드라이버를 호출한다.

드라이버는:

* I/O 요청을 하드웨어 명령으로 변환
* MMIO 방식으로 장치 레지스터에 기록

---

## 6단계: 저장 장치 동작

저장 장치 내부 컨트롤러가:

* 요청 수신
* 실제 물리 매체에 데이터 기록

---

## 7단계: 완료 처리

* 드라이버가 완료 확인
* 커널이 대기 중인 프로세스 깨움
* 시스템 콜 반환
* 사용자 모드 복귀

---

# 전체 흐름 요약 다이어그램

```
User Process
   ↓ write()
System Call
   ↓
VFS
   ↓
File System (ext4 등)
   ↓
Block Layer
   ↓
Device Driver
   ↓ MMIO
Storage Device
```

---

# 핵심 정리

1. 파일 시스템은 디스크의 물리 구조를 추상화한다.
2. 파일과 디렉터리는 inode 기반으로 관리된다.
3. 모든 파일 접근은 VFS를 거친다.
4. 실제 디스크 접근은 블록 계층과 디바이스 드라이버를 통해 수행된다.
5. 대부분의 쓰기는 먼저 page cache에 기록된다.

---

이제 이 개념까지 연결되면:

* 가상 메모리
* 시스템 콜
* 커널 계층 구조
* 블록 장치
* MMIO
* 저장 장치

가 하나의 흐름으로 연결된다.

원하면 다음 단계로:

* inode 구조 내부
* 저널링 파일 시스템 동작
* page cache와 COW의 관계
* fsync가 실제로 하는 일

까지 이어서 정리해줄 수 있다.
