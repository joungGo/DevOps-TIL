# 1. 파일 시스템 오류 예시

## 초기 상태

```
/
├── foo/
│   ├── hoge
│   └── hyuga
└── bar/
```

여기서 `bar`를 `foo` 아래로 이동한다고 가정한다.

```
mv /bar /foo/bar
```

---

# 2. 이동 작업의 내부 동작 (메타데이터 변경)

파일 이동은 데이터 복사가 아니라  
**디렉터리 엔트리(메타데이터) 수정 작업**이다.

필요한 작업:

```
1. foo 디렉터리 데이터 갱신
   → bar 엔트리 추가

2. 루트 디렉터리 데이터 갱신
   → bar 엔트리 제거
```

이 두 작업은 논리적으로는 하나의 작업처럼 보이지만  
실제로는 **여러 번의 디스크 쓰기**로 나뉜다.

---

# 3. 전원 장애 발생 시 문제

다음 상황을 가정하자.

```
[1단계 완료]
foo 디렉터리 갱신 완료

[2단계 수행 전]
루트 디렉터리 갱신 전
```

이 상태에서 전원이 꺼지면 파일 시스템은 다음과 같은  
**어중간한 상태**가 된다.

가능한 오류 예:

```
/
├── foo/
│   ├── hoge
│   ├── hyuga
│   └── bar
└── bar   (여전히 존재)
```

또는

```
foo에 bar가 추가되었지만
루트에서 bar가 제거되지 않음
```

이처럼 메타데이터 불일치가 발생하면:

- 마운트 실패
    
- 읽기 전용 마운트
    
- fsck 요구
    
- 심하면 커널 패닉
    

이것이 파일 시스템 정합성 오류이다.

# 4. 해결 방법 1 — 저널링 (Journaling)

## 핵심 개념

> 변경 사항을 먼저 "저널 영역"에 기록하고  
> 그 다음 실제 파일 시스템에 반영한다.

---

## 동작 구조

```
1. 저널 로그 기록
   (아토믹 작업 목록 저장)

2. 실제 파일 시스템 반영
```

---

## 예시 흐름

```
저널 영역:
  - foo에 bar 추가
  - 루트에서 bar 제거

↓ 저널 기록 완료

실제 디렉터리 갱신 수행
```

---

## 전원 차단 시

### 1) 저널 기록 중 장애

```
저널 로그 불완전
→ 폐기
→ 실제 파일 시스템은 변경 전 상태
```

### 2) 실제 반영 중 장애

```
저널 로그는 완전
→ 재부팅 시 저널을 보고 재실행
→ 일관성 회복
```

즉,

> 저널은 복구 기준점 역할을 한다.

---

# 5. 해결 방법 2 — Copy-on-Write 파일 시스템

대표 예: btrfs, ZFS

기존 파일 시스템(ext4, xfs):

```
기존 블록 위치 덮어쓰기
```

CoW 파일 시스템:

```
항상 새로운 위치에 기록
```

---

## 기존 방식 (Overwrite)

```
기존 블록 A
   ↓
A에 덮어쓰기
```

중간에 장애 발생 시:

- 블록이 일부만 갱신
    
- 이전 상태도 사라짐
    
- 복구 어려움
    

---

## CoW 방식

```
기존 블록 A (그대로 유지)
새 블록 B 생성
데이터 B에 기록
마지막에 포인터 변경
```

이동 작업 예시:

```
1. 변경된 디렉터리 구조를 새 위치에 생성
2. 마지막에 루트 포인터 갱신
```

---

## 전원 차단 시

- 포인터 변경 전이면 → 기존 상태 유지
    
- 포인터 변경 후면 → 새 상태 완성
    

즉,

> 항상 완전한 구조 중 하나만 존재

중간 상태는 참조되지 않으므로 안전하다.

---

# 6. 복구 방법

## 1. 백업

가장 확실한 방법:

```
정기 백업
→ 장애 시 복원
```

---

## 2. fsck

파일 시스템 검사 도구.

동작:

```
inode 검사
블록 할당 검사
링크 수 검사
불일치 수정
```

---

# 7. fsck의 한계

1. 파일 시스템 전체 검사 → 매우 오래 걸림
    
2. 완전 복구 보장 안 됨
    
3. 사용자가 기대하는 상태로 복구된다는 보장 없음
    
4. 손상 심하면 데이터 일부 삭제될 수 있음

# 전체 구조 비교

|방식|원리|장점|단점|
|---|---|---|---|
|기본 덮어쓰기|기존 블록 갱신|단순|장애 시 중간 상태|
|저널링|먼저 로그 기록|복구 가능|오버헤드 존재|
|CoW|항상 새 블록 생성|구조적으로 안전|공간 사용 증가|

---

# 핵심 정리

파일 이동 같은 작업은 내부적으로 여러 메타데이터 쓰기로 나뉘며,  
중간에 장애가 발생하면 파일 시스템 불일치가 생길 수 있다.

이를 해결하기 위해:

- 저널링은 "기록 후 반영"
    
- CoW는 "새로 쓰고 마지막에 전환"
    

이라는 방식으로 정합성을 보장한다.

---

# 한 문장 요약

파일 시스템 정합성 오류는 여러 단계의 메타데이터 갱신 중 장애로 발생하며, 저널링은 로그 기반 복구를, CoW는 구조적 원자성을 통해 이를 방지한다.
