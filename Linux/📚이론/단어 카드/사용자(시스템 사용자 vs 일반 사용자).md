리눅스에서는 모든 사용자를 **UID(User ID)** 로 구분한다.  
사용자 이름이 아니라, 실제 권한 판단 기준은 UID다.

---

# 1. UID란?

UID는 각 사용자에게 부여되는 **고유한 숫자 식별자**다.

확인:

```bash
id
```

또는

```bash
cat /etc/passwd
```

형식 예:

```text
username:x:UID:GID:...
```

커널은 접근 권한을 판단할 때 사용자 이름이 아니라 **UID 기준으로 검사**한다.

---

# 2. 사용자 유형 구분

## 1) 시스템 사용자 (System User)

운영체제나 서비스 실행을 위해 존재하는 계정이다.

예:

- root
    
- daemon
    
- www-data
    
- mysql
    

### 특징

- 보통 로그인 목적이 아님
    
- 서비스 실행 전용
    
- 낮은 권한으로 동작하도록 설계
    
- 홈 디렉토리 없거나 `/usr/sbin/nologin` 설정
    

### UID 범위 (일반적 기준)

- 0 → root
    
- 1 ~ 999 (또는 1 ~ 499) → 시스템 사용자
    

배포판에 따라 다르지만 보통 1000 미만이 시스템 계정이다.

---

## 2) 일반 사용자 (Regular User)

실제 사람이 로그인해서 사용하는 계정이다.

예:

- 개발자 계정
    
- 서버 운영 계정
    

### 특징

- 로그인 가능
    
- 홈 디렉토리 존재
    
- 셸 할당됨 (/bin/bash 등)
    

### UID 범위 (일반적 기준)

- 1000 이상
    

첫 번째 생성되는 일반 사용자는 보통 UID 1000이다.

---

# 3. 특별 사용자: root

- UID = 0
    
- 모든 접근 권한 보유
    
- DAC 검사 대부분 우회 가능
    

커널은 UID가 0이면 특별 권한을 부여한다.

---

# 4. 왜 구분하는가?

### 보안 이유

서비스는 별도 시스템 사용자로 실행한다.

예:

- 웹 서버는 www-data 사용자로 실행
    
- DB는 mysql 사용자로 실행
    

이렇게 하면:

> 서비스가 침해돼도 전체 시스템 권한을 얻기 어렵다.

최소 권한 원칙(Principle of Least Privilege) 적용이다.

---

# 5. 정리

|구분|시스템 사용자|일반 사용자|
|---|---|---|
|목적|서비스 실행|사람 사용|
|로그인|보통 불가|가능|
|UID 범위|보통 1000 미만|보통 1000 이상|
|예|root, daemon|개인 계정|

---

# 한 줄 정리

리눅스는 UID로 사용자를 구분하며, 시스템 사용자(서비스용 계정)와 일반 사용자(사람이 사용하는 계정)로 나뉘고, 커널은 사용자 이름이 아니라 UID를 기준으로 권한을 판단한다.
