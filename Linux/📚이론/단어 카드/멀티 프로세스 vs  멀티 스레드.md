# 하나의 프로그램을 병렬로 실행하는 방법

프로그램을 병렬로 동작시키는 방법은 크게 두 가지가 있다.

1. 서로 다른 여러 프로그램을 동시에 실행하는 방법
2. 하나의 프로그램을 여러 실행 흐름으로 분할하여 실행하는 방법

여기서는 **하나의 프로그램을 여러 실행 흐름으로 분할하는 방식**을 설명한다.
이 방식은 크게 다음 두 가지로 나뉜다.

* 멀티 프로세스 (Multi-Process)
* 멀티 스레드 (Multi-Thread)

---

# 1. 멀티 프로세스 방식

멀티 프로세스는 하나의 프로그램이 여러 개의 **독립된 프로세스**를 생성하여 병렬로 동작하는 방식이다.

리눅스에서는 일반적으로 다음과 같은 시스템 콜을 사용한다.

* `fork()` : 현재 프로세스를 복제
* `exec()` : 새로운 프로그램으로 교체

생성된 각 프로세스는:

* 독립된 가상 주소 공간을 가지며
* 서로 직접 메모리를 공유할 수 없다

따라서 프로세스 간 통신(IPC)을 사용해야 한다.

예:

* 공유 메모리
* 소켓
* 파이프

> 더 많은 메모리를 스레드에 비해 잡아먹을 수 있다. 

---

## 특징

* 각 프로세스는 완전히 독립된 메모리 공간을 가짐
* 한 프로세스의 장애가 다른 프로세스에 직접적인 영향을 주지 않음
* 생성 및 컨텍스트 스위칭 비용이 비교적 큼

---

# 2. 멀티 스레드 방식

멀티 스레드는 하나의 프로세스 내부에서 여러 실행 흐름(스레드)을 생성하는 방식이다.

각 스레드는 다음을 공유한다.

* code 영역
* data 영역
* heap 영역

하지만 다음은 개별적으로 가진다.

* stack
* CPU 레지스터 상태

---

## 스레드 구현 방식

리눅스에서는 일반적으로 **POSIX Threads (pthread)** API를 사용한다.

* POSIX 표준에서 정의한 스레드 인터페이스
* 리눅스에서는 `libc`가 이를 구현
* 내부적으로는 `clone()` 시스템 콜 기반

---

# 멀티 스레드의 장점

1. 생성 비용이 낮음

   * 새로운 페이지 테이블을 만들 필요가 없음
   * 주소 공간을 공유하므로 초기화 비용이 적음

2. 자원 사용량이 적음

   * 메모리 공간을 공유
   * 파일 디스크립터, 전역 변수 등 공유 가능

3. 협업이 쉬움

   * 동일한 메모리를 직접 접근 가능
   * IPC 없이 데이터 공유 가능

---

# 멀티 스레드의 단점

1. 안정성이 낮음

   * 하나의 스레드에서 발생한 오류가
   * 전체 프로세스를 종료시킬 수 있음

2. 동기화 문제

   * 모든 스레드가 동일한 메모리를 공유하므로
   * race condition 발생 가능

3. 스레드 세이프(Thread-Safe) 고려 필요

---

# 스레드 세이프(Thread-Safe)

> 여러 스레드가 동시에 호출해도 안전하게 동작하는 성질

예를 들어:

* 전역 변수를
* 배타 제어 없이 수정하는 함수는
* 스레드 세이프하지 않다

따라서 다음과 같은 보호가 필요하다.

* mutex
* semaphore
* atomic 연산

---

# 핵심 정리

* 멀티 프로세스는 **독립성과 안정성 중심**
* 멀티 스레드는 **성능과 자원 공유 중심**
* 스레드는 효율적이지만 반드시 동기화와 스레드 세이프를 고려해야 한다

---

면접에서 한 문장으로 정리하면:

> 멀티 프로세스는 독립된 주소 공간을 가지는 여러 실행 단위를 통해 안정성을 확보하는 방식이고, 멀티 스레드는 하나의 주소 공간을 공유하는 여러 실행 흐름을 통해 성능과 자원 효율을 높이는 방식이다.

원하면 여기서 더 깊게 들어가서
리눅스 커널 관점에서 `task_struct`, `clone()` 레벨로도 정리해줄 수 있다.
