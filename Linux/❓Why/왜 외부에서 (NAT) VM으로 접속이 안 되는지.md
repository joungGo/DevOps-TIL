# 왜 외부에서 VM으로 접속이 안 되는가?

## 결론 한 줄

> **외부에서는 VM의 존재 자체를 모르기 때문**입니다.

이유를 단계별로 풀어봅니다.

---

## 1️⃣ VM의 IP는 “가짜 IP”다 (외부 기준)

VM이 가진 IP 예:

```
192.168.111.100
```

이 IP의 정체는:

- 사설 IP
    
- VMware 내부에서만 유효
    
- 인터넷 라우팅 테이블에 존재 ❌
    

### 외부에서 보면

```
192.168.111.0/24 → 경로 없음
```

👉 즉,

> **외부 네트워크는 이 IP로 가는 길 자체를 모른다**

---

## 2️⃣ NAT 구조의 절대 규칙

### NAT는 “나갈 때만” 길이 열린다

VM → 외부 (가능)  
외부 → VM (불가능, 기본 상태)

왜냐하면 NAT는 이렇게 동작합니다.

---

## 3️⃣ NAT 테이블은 “요청 기준”으로만 생성된다

### VM이 먼저 요청한 경우

```
[VM] 192.168.111.100:52341
   ↓
[NAT 변환]
   ↓
[호스트 실제 IP] 10.0.0.5:40001
```

이때 NAT 테이블에 기록:

```
10.0.0.5:40001 ↔ 192.168.111.100:52341
```

✔ 그래서 **응답 패킷은 돌아올 수 있음**

---

### 외부에서 먼저 접속 시도하는 경우

```
[외부 PC] → 10.0.0.5:80
```

NAT 입장:

```
❓ 이 패킷을 어느 VM으로 보내야 하지?
```

- NAT 테이블 ❌
    
- 매핑 정보 ❌
    
- 기본 정책: **드롭(Drop)**
    

👉 그래서 연결 자체가 성립되지 않음

---

## 4️⃣ VMware NAT는 방화벽처럼 동작한다

기본 정책:

```
외부 → 내부 = 차단
내부 → 외부 = 허용
```

이건 보안 목적입니다.

### 만약 기본적으로 열려 있었다면?

- VM이 인터넷에 그대로 노출
    
- 악성 스캔, 공격 대상
    
- 실습용 환경으로 매우 위험
    

---

## 5️⃣ 그림 기준으로 다시 보면

### 외부에서 들어오는 흐름 (막힘)

```
[인터넷]
   ↓
[호스트 네트워크 카드]
   ↓
[VMware NAT]
   ✋ 차단
```

- 목적지 IP: 호스트 IP
    
- NAT는 **어떤 VM인지 모름**
    
- 기본 정책: 버림
    

---

## 6️⃣ 그럼 왜 “내가 먼저 나가면” 연결이 되나?

이건 **상태 기반(Stateful)** NAT이기 때문입니다.

### 흐름 비교

|상황|결과|
|---|---|
|VM → 외부 요청|NAT 테이블 생성 ⭕|
|외부 → VM 먼저|NAT 테이블 없음 ❌|

👉 **항상 내부가 먼저 시작해야 한다**

---

## 7️⃣ 비유 (진짜 직관적인 비유)

### 📦 회사 대표 전화 비유

- 회사 대표 번호: `10.0.0.5`
    
- 직원 내선:
    
    - A: 100번
        
    - B: 200번
        

#### 직원이 먼저 전화하면

```
A → 외부 고객
```

대표 전화 교환원:

```
"아, 이 통화는 A가 시작한 거구나"
```

→ 연결 유지 가능

#### 외부에서 갑자기 전화 오면

```
외부 → 대표번호
```

교환원:

```
"어느 직원에게?"
```

→ 정보 없음 → 끊음

👉 NAT = 교환원

---

## 8️⃣ 그래서 해결 방법은?

### 방법 1️⃣ 포트 포워딩 (정식 해결)

```
호스트 10.0.0.5:8080
        ↓
VM 192.168.111.100:80
```

이건:

- NAT 테이블을 **미리 만들어주는 것**
    
- “이 포트로 오면 이 VM으로 보내라”
    

---

### 방법 2️⃣ Bridged 모드 사용

- VM이 실제 네트워크에 직접 참여
    
- VM이 실제 IP를 가짐
    
- 외부 → VM 접속 가능
    

⚠️ 대신 보안 위험 증가

---

## 9️⃣ 핵심 정리 (시험·면접용 문장)

> **NAT 환경에서는 내부에서 시작한 연결만 허용되며,  
> 외부에서 내부로의 신규 연결은  
> 매핑 정보가 없기 때문에 차단된다.**

---

이제 이 질문을 이해했다면, 다음이 자연스럽게 이어집니다:

- ❓ **포트 포워딩은 NAT 구조의 어디를 어떻게 바꾸는가**
    
- ❓ **Docker 컨테이너도 왜 기본적으로 외부 접근이 안 되는가**
    
- ❓ **클라우드에서 보안 그룹은 이 개념과 어떻게 연결되는가**
