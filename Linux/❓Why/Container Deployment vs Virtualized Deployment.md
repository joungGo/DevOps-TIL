## 1️⃣ 가상머신 (Virtual Machine)

**개념**

- 하나의 물리 서버 위에서 **여러 개의 완전한 컴퓨터**를 가상으로 만드는 기술
    
- 각 VM은 **자기만의 운영체제(Guest OS)** 를 가짐
    

**구성**

```
물리 서버
 └ Host OS
   └ Hypervisor (VMware, Hyper-V 등)
     └ VM
       ├ Guest OS
       ├ Bins / Lib
       └ Application
```

**특징**

- OS까지 포함 → **무겁고 느림**
    
- VM 하나가 장애 나도 다른 VM에 영향 없음 → **격리 수준 높음**
    
- 서로 다른 OS 실행 가능 (Linux + Windows)
    

**장점**

- 강력한 격리
    
- 보안에 유리
    
- OS 단위 실험 가능
    

**단점**

- 부팅 느림
    
- 리소스 사용량 큼
    
- 관리 비용 큼
    

---

## 2️⃣ 컨테이너 (Container)

**개념**

- OS를 가상화하지 않고, **애플리케이션 실행 환경만 격리**
    
- Host OS의 **커널을 공유**
    

**구성**

```
물리 서버
 └ Host OS (Linux)
   └ Container Engine (Docker)
     └ Container
       ├ Bins / Lib
       └ Application
```

**특징**

- OS 미포함 → **가볍고 빠름**
    
- 수 초 내 실행 가능
    
- 마이크로서비스에 적합
    

**장점**

- 빠른 실행 속도
    
- 리소스 효율 좋음
    
- 배포/확장 쉬움
    

**단점**

- Host OS에 의존
    
- VM보다 격리 수준 낮음
    
- 커널 공유 → 보안 설정 중요
    

---

## 3️⃣ 가상머신 vs 컨테이너 차이점 정리

|구분|가상머신(VM)|컨테이너(Container)|
|---|---|---|
|가상화 대상|하드웨어|OS|
|OS 포함 여부|포함 (Guest OS)|미포함|
|실행 속도|느림 (분 단위)|매우 빠름 (초 단위)|
|리소스 사용|큼|적음|
|격리 수준|높음|상대적으로 낮음|
|대표 기술|VMware, Hyper-V|Docker, Kubernetes|
|사용 목적|서버 통째로 분리|앱 단위 배포|

---

## 4️⃣ 언제 무엇을 쓰면 좋을까?

- ✅ **가상머신**
    
    - 서로 다른 OS 필요할 때
        
    - 보안/격리가 매우 중요할 때
        
    - 레거시 시스템 운영
        
- ✅ **컨테이너**
    
    - Spring Boot 같은 백엔드 서비스 배포
        
    - MSA(마이크로서비스)
        
    - CI/CD, 클라우드 환경
        

---

👉 **한 줄 요약**

> 가상머신은 _OS까지 포함한 가상 컴퓨터_,  
> 컨테이너는 _OS 위에서 앱만 가볍게 실행하는 상자_.

원하면 **Spring Boot + Docker**, **VM 위에 Docker 구조**, **Kubernetes까지 확장 설명**도 해줄게!
