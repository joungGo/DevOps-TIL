# 프로세스 상태와 CPU 사용

## 1. 프로세스는 항상 CPU를 사용하고 있을까?

결론부터 말하면 **대부분의 프로세스는 CPU를 사용하지 않는다**.

프로세스는 실행된 이후에도:

- I/O 완료
    
- 타이머 만료
    
- 시그널 도착
    
- 자식 프로세스 종료
    

와 같은 **이벤트가 발생할 때까지 CPU를 사용하지 않고 대기 상태**에 머무는 경우가 훨씬 많다.

---

## 2. ps 명령어와 프로세스 상태 (STAT 필드)

리눅스에서 프로세스의 상태는 `ps` 명령어의 `STAT` 필드를 통해 확인할 수 있다.

### 주요 상태 값

- **R (Running / Runnable)**
    
    - 실행 중이거나
        
    - CPU를 할당받기를 기다리는 실행 가능 상태
        
- **S (Sleeping)**
    
    - 인터럽트 가능한 슬립 상태
        
    - 이벤트를 기다리며 CPU를 사용하지 않음
        
- **D (Uninterruptible Sleep)**
    
    - 디스크 I/O 등으로 대기
        
    - 시그널로도 깨어나지 않음
        
- **Z (Zombie)**
    
    - 실행은 종료되었으나
        
    - 부모가 종료 상태를 회수하지 않은 상태
        

---

## 3. 실행 상태(Running)와 실행 가능 상태(Runnable)의 차이

중요한 점은 **STAT이 R이라고 해서 항상 CPU를 쓰고 있다는 의미는 아니라는 것**이다.

리눅스에서 R 상태는 두 가지를 포함한다.

### 실행 가능 상태 (Runnable)

- CPU를 사용하고 싶어함
    
- 런큐(run queue)에 올라가 있음
    
- 스케줄러가 선택해 주기를 기다리는 상태
    

### 실행 상태 (Running)

- 실제로 CPU를 할당받아
    
- 명령어를 실행 중인 상태
    

---

## 4. 실행 상태와 실행 가능 상태의 전환

[[CPU는 동시에 하나의 프로세스(또는 하나의 스레드)만 실행할 수 있다.]]  
따라서 프로세스는 다음과 같이 상태를 오간다.

### 상태 전이 개념

- 실행 가능 → 실행  
    스케줄러가 해당 프로세스를 선택
    
- 실행 → 실행 가능  
    타임 슬라이스 만료, 선점 발생
    

---

## 5. 프로세스 상태 전이 도표 (기호 + 텍스트)

```text
            ┌────────────┐
            │   생성됨   │
            └─────┬──────┘
                  │
                  v
            ┌────────────┐
            │ 실행 가능  │  (R: Runnable)
            └─────┬──────┘
                  │  스케줄러 선택
                  v
            ┌────────────┐
            │   실행 중  │  (Running)
            └─────┬──────┘
                  │
        ┌─────────┴─────────┐
        │                   │
        v                   v
┌────────────┐       ┌────────────┐
│   슬립     │       │  종료됨    │
│   (S/D)   │       │            │
└─────┬──────┘       └─────┬──────┘
      │ 이벤트 발생               │
      v                           v
┌────────────┐            ┌────────────┐
│ 실행 가능  │            │   좀비     │ (Z)
└────────────┘            └────────────┘
```

## 6. CPU 아이들(idle) 상태와 소비 전력

실행 가능한 프로세스가 하나도 없을 경우, CPU는 **아이들 상태(idle state)** 로 전환된다.

이때 커널은:

- CPU 특수 명령어를 사용해
    
- 논리 CPU를 저전력 대기 상태로 진입시킨다
    
- 인터럽트가 발생할 때까지 대기
    

이 메커니즘 덕분에:

- PC
    
- 노트북
    
- 스마트폰
    

에서 **아무 프로그램도 실행하지 않을 때 배터리가 오래 유지**된다.

즉, 배터리 절약의 핵심 원인은  
👉 **논리 CPU가 아이들 상태로 머무는 시간이 길기 때문**이다.

---

## 7. 프로세스 종료와 exit_group 시스템 콜

프로세스가 종료될 때는 `exit()` 함수를 호출한다.

### exit()의 실제 동작

- `exit()`는 라이브러리 함수
    
- 내부에서 **`exit_group` 시스템 콜**을 호출
    

프로그램이 명시적으로 `exit()`를 호출하지 않더라도:

- `main()`에서 반환
    
- libc 내부 처리
    

를 통해 결국 `exit_group`이 호출된다.

---

## 8. exit_group 내부에서 수행되는 작업

커널은 다음 자원을 정리한다.

- 사용자 메모리 공간
    
- 열린 파일 디스크립터
    
- 커널 자료구조
    
- 스케줄링 정보
    

이 시점에서 프로세스는 **실행을 완전히 종료**한다.

---

## 9. 좀비(Zombie) 상태의 의미

프로세스가 종료되면 즉시 완전히 사라지는 것이 아니라:

- 종료 정보(exit status)를
    
- 부모 프로세스가 회수할 때까지
    

**좀비 상태(Z)** 로 남는다.

이 상태에서는:

- CPU 사용 없음
    
- 메모리 사용 없음
    
- 프로세스 테이블 엔트리만 유지
    

---

## 10. 부모 프로세스와 wait 계열 시스템 콜

부모 프로세스는 다음 시스템 콜을 통해 자식의 종료 정보를 수거한다.

- `wait()`
    
- `waitpid()`
    

이를 통해 얻을 수 있는 정보는 다음과 같다.

### 수거 가능한 정보

- **종료 코드**
    
    - `exit(n)`에서 `n % 256`
        
    - 0~255 범위는 그대로 전달
        
- **종료 원인**
    
    - 정상 종료인지
        
    - 시그널에 의한 종료인지
        
- **자원 사용 정보**
    
    - 종료될 때까지 사용한 CPU 시간 등
        

이 과정이 완료되면 좀비 프로세스는 완전히 소멸한다.

---

## 핵심 요약

- 대부분의 프로세스는 슬립 상태로 CPU를 사용하지 않는다
    
- R 상태는 실행 중 + 실행 가능 상태를 포함한다
    
- CPU가 놀고 있을 때는 아이들 상태로 전력 소비를 최소화한다
    
- 프로세스 종료는 exit_group 시스템 콜로 처리된다
    
- 좀비는 종료 정보 전달을 위한 임시 상태다
    

---

- init(systemd)이 고아/좀비를 정리하는 방식
