## 프로세스 스케줄러란

**프로세스 스케줄러(Process Scheduler)** 는  
리눅스 커널에서 **프로세스의 CPU 자원 사용을 관리하는 핵심 기능**이다.

스케줄러의 기본 역할은 다음과 같다.

- 하나의 **논리 CPU**는 **동시에 하나의 프로세스만 실행**
    
- 실행 가능한 여러 프로세스가 존재할 경우
    
    - **[[타임 슬라이스]]** 단위로 커널이 실행 순서를 결정하여
        
    - 각 프로세스가 번갈아 CPU를 사용하도록 함
        

이러한 방식으로 여러 프로세스가 동시에 실행되는 것처럼 보이게 한다.

---

## 경과 시간과 사용 시간

프로세스의 실행 시간은 크게 두 가지 관점으로 나뉜다.

### 1. 경과 시간 (Elapsed Time)

- 프로세스가 **시작된 시점부터 종료될 때까지 실제로 흐른 시간**
    
- CPU를 사용하지 않고 대기한 시간도 포함
    

### 2. 사용 시간 (CPU Time)

- 프로세스가 **실제로 CPU를 점유하여 실행한 시간**
    
- 사용자 공간과 커널 공간에서 사용한 시간을 포함
    

---

## `time` 명령어의 출력 항목

```bash
$ time command
```

출력되는 주요 항목은 다음과 같다.

|항목|의미|분류|
|---|---|---|
|real|프로세스 시작부터 종료까지의 전체 시간|경과 시간|
|user|사용자 공간에서 실행된 시간|사용 시간|
|sys|시스템 콜로 인해 커널이 실행된 시간|사용 시간|

### 각 항목의 의미

- **real**
    
    - 벽시계 기준 시간(wall-clock time)
        
    - I/O 대기, 스케줄링 대기 시간 포함
        
- **user**
    
    - 사용자 모드에서 실행된 시간
        
- **sys**
    
    - 시스템 콜 처리로 커널 모드에서 실행된 시간
        

---

## 단일 물리 CPU 환경에서의 동작

물리 CPU가 **1개**인 경우:

- 모든 프로세스는 **하나의 논리 CPU**를 공유
    
- 동시에 여러 프로세스가 실행 중이라면:
    
    - 스케줄러가 실행 가능한 프로세스들을 번갈아 실행
        
- 이 경우:
    
    - CPU를 기다리는 시간이 길어질 수 있음
        
    - `real` 값이 상대적으로 커지기 쉬움
        

---

## 다중 물리 / 논리 CPU 환경에서의 동작

물리 CPU 또는 논리 CPU가 **여러 개**인 경우:

- 각 논리 CPU는 **독립적으로 하나의 프로세스를 실행 가능**
    
- 스케줄러는 다음을 수행한다.
    
    - 실행 가능한 프로세스를 여러 CPU에 분산 배치
        
    - 특정 CPU에 부하가 몰리지 않도록 조정
        

---

## 부하 분산 처리 (Load Balancing)

예를 들어:

- 논리 CPU가 2개
    
- 실행 가능한 CPU 부하 작업이 2개인 경우
    

스케줄러는 다음과 같이 동작한다.

- 각 프로세스를 **서로 다른 논리 CPU에 할당**
    
- 결과적으로:
    
    - 두 프로세스가 동시에 실행
        
    - 각 프로세스가 CPU를 독점적으로 사용하는 것처럼 동작
        

이를 **부하 분산 처리(load balancing)** 라고 한다.

부하 분산의 목적은:

- CPU 자원의 효율적 사용
    
- 전체 처리 시간(real) 단축
    
- 특정 CPU에 과도한 부하 집중 방지
    

---

## real < user + sys 가 가능한 이유

일반적으로는 다음과 같이 생각하기 쉽다.

> real ≥ user + sys

하지만 **항상 그렇지는 않다**.

### real이 더 작아지는 대표적인 경우

- 프로세스가 **자식 프로세스를 생성**
    
- 부모와 자식이 **서로 다른 논리 CPU에서 동시에 실행**
    

이 경우:

- `user + sys`  
    → **모든 프로세스의 CPU 사용 시간을 합산**
    
- `real`  
    → **전체 작업이 완료되기까지의 실제 경과 시간**
    

즉,

- CPU 사용 시간은 **병렬로 누적**
    
- 경과 시간은 **병렬 실행으로 단축**
    

결과적으로:

```text
real < user + sys
```

이 현상은 **멀티코어 환경에서 정상적인 동작**이며,  
오히려 시스템이 효율적으로 자원을 활용하고 있다는 의미다.

---

## 핵심 정리

- 스케줄러는 CPU 자원을 프로세스에 배분하는 커널 기능
    
- 하나의 논리 CPU는 동시에 하나의 프로세스만 실행
    
- 다중 CPU 환경에서는 프로세스를 분산 실행
    
- `real`은 경과 시간, `user + sys`는 CPU 사용 시간
    
- 병렬 실행이 발생하면 `real < user + sys`가 가능
