# 프로세스 그룹(Process Group)

## 1. 프로세스 그룹이란?

**프로세스 그룹**은

> **하나의 작업(job)을 구성하는 프로세스들의 묶음**이다.

리눅스/유닉스에서 작업 제어(job control)를 위해 사용하는 단위이며,  
**시그널을 한 번에 전달**하기 위한 대상이기도 하다.

---

## 2. 왜 프로세스 그룹이 필요한가?

### 문제 상황

```bash
ls | grep txt | wc -l
```

이 명령은 사실 여러 프로세스로 이루어진다.

- `ls`
    
- `grep`
    
- `wc`
    

하지만 사용자 입장에서는 **하나의 작업**이다.

→ 이들을 하나로 묶을 단위가 필요  
→ 그것이 **프로세스 그룹**

---

## 3. 프로세스 그룹 ID (PGID)

- 프로세스 그룹을 식별하는 ID
    
- **프로세스 그룹 리더의 PID와 동일**
    

```text
PID = 4100  →  PGID = 4100
```

---

## 4. 프로세스 그룹 리더

- 그룹을 생성한 첫 번째 프로세스
    
- PID == PGID
    
- 반드시 특별한 권한이 있는 것은 아님
    

---

## 5. 프로세스 그룹은 어떻게 만들어지는가?

### 기본 규칙

- 쉘(bash)이 명령을 실행할 때 생성
    
- 파이프(`|`)로 연결된 프로세스들은 **같은 프로세스 그룹**
    

예:

```bash
sleep 100 | cat
```

구조:

```text
bash
 └─ PGID 5000
     ├─ sleep
     └─ cat
```

---

## 6. 세션(Session)과의 관계

- **하나의 세션 안에는 여러 프로세스 그룹**이 존재
    
- 프로세스 그룹은 반드시 어떤 세션에 속함
    

```text
세션(SID)
 ├─ 프로세스 그룹 A (포그라운드)
 ├─ 프로세스 그룹 B (백그라운드)
 └─ 프로세스 그룹 C
```

---

## 7. 단말과의 관계 (핵심)

### 포그라운드 프로세스 그룹

- 제어 단말과 직접 연결됨
    
- 키보드 입력(Ctrl+C, Ctrl+Z)을 받음
    

### 백그라운드 프로세스 그룹

- 단말 입력 불가
    
- 출력만 가능
    

쉘은 **한 번에 하나의 프로세스 그룹만** 포그라운드로 둔다.

---

## 8. 시그널과 프로세스 그룹

시그널은 **프로세스 그룹 단위로 전달**될 수 있다.

### 예시

- `Ctrl + C` → 포그라운드 프로세스 그룹 전체에 SIGINT
    
- `Ctrl + Z` → 포그라운드 프로세스 그룹 전체에 SIGTSTP
    

```text
bash
 └─ (PGID 6000)
     ├─ vim
     └─ helper
```

→ SIGINT는 vim과 helper 모두에게 전달

---

## 9. 프로세스 그룹과 job control 명령어

|명령어|설명|
|---|---|
|`jobs`|프로세스 그룹 목록|
|`fg`|포그라운드로 이동|
|`bg`|백그라운드 재개|
|`kill -<signal> -PGID`|그룹 전체에 시그널|

예:

```bash
kill -SIGTERM -6000
```

---

## 10. `ps ajx`에서 보는 프로세스 그룹

### 예시 출력

```text
PPID   PID  PGID   SID TTY      STAT   COMMAND
3200  4100  4100  3200 pts/0    R      vim
3200  4200  4100  3200 pts/0    S      helper
```

### 해석

- PID 4100과 4200은 같은 PGID
    
- 하나의 작업(job)
    
- 같은 세션(SID)
    
- 같은 단말(pts/0)
    

---

## 11. 포그라운드 ↔ 백그라운드 전환 흐름

```text
백그라운드 실행 (&)
   ↓
새 프로세스 그룹 생성
   ↓
단말 제어권 없음
```

```text
fg
   ↓
해당 프로세스 그룹이 포그라운드
   ↓
단말 제어권 획득
```

---

## 12. 핵심 요약

- 프로세스 그룹은 **작업 단위**
    
- PGID는 그룹 리더 PID
    
- 세션 안에 여러 그룹이 존재
    
- 단말은 한 번에 하나의 그룹만 제어
    
- 시그널은 그룹 단위로 전달 가능
    
- job control의 핵심 개념
    

---

이제 이 개념까지 잡히면  
**세션 → 프로세스 그룹 → 시그널 → 단말 제어**가 한 줄로 연결된다.

다음으로 이어서 보면 좋은 주제:

- 포그라운드/백그라운드 제어의 내부 동작
    
- 데몬 프로세스가 세션과 단말을 가지지 않는 이유
