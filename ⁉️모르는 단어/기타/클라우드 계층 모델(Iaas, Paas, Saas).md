## 1. IaaS (Infrastructure as a Service)

인프라(서버, 스토리지, 네트워크)를 서비스로 제공합니다.

- 가상 서버, 네트워크, 스토리지를 직접 구성
    
- 운영체제, 미들웨어, 애플리케이션은 사용자가 관리
    

예시

- Amazon Web Services (EC2)
    
- Microsoft Azure (Virtual Machines)
    
- Google Cloud (Compute Engine)
    

특징

- 자유도가 높음
    
- 운영 및 관리 부담이 큼
    

---

## 2. PaaS (Platform as a Service)

애플리케이션 개발 및 실행을 위한 플랫폼을 제공합니다.

- 인프라와 OS는 제공자가 관리
    
- 개발자는 코드 작성에 집중
    

예시

- Heroku
    
- Google Cloud (App Engine)
    
- Microsoft Azure (App Service)
    

특징

- 개발 속도가 빠름
    
- 환경 제약이 있을 수 있음
    

---

## 3. SaaS (Software as a Service)

완성된 소프트웨어를 인터넷을 통해 제공합니다.

- 설치 없이 브라우저에서 사용
    
- 유지보수는 제공자가 담당
    

예시

- Google (Gmail)
    
- Microsoft (Microsoft 365)
    
- Salesforce
    

특징

- 가장 사용이 간편
    
- 커스터마이징에 제한이 있음
    

---

## 1. 개념적 차이

|구분|IaaS|PaaS|SaaS|
|---|---|---|---|
|제공 범위|인프라|개발 플랫폼|완성된 소프트웨어|
|사용자 역할|시스템 관리자 + 개발자|개발자|최종 사용자|
|추상화 수준|낮음|중간|높음|

---

## 2. 관리 책임 비교 (가장 중요한 차이)

### IaaS (Infrastructure as a Service)

예: Amazon Web Services EC2

- 클라우드 제공자: 서버 하드웨어, 네트워크, 스토리지, 가상화
    
- 사용자: 운영체제, 미들웨어, 런타임, 애플리케이션, 데이터
    

즉, **서버는 빌려주지만 그 위는 직접 관리**합니다.  
자유도가 높지만 운영 부담이 큽니다.

---

### PaaS (Platform as a Service)

예: Google Cloud App Engine

- 클라우드 제공자: 인프라 + 운영체제 + 런타임
    
- 사용자: 애플리케이션 코드 + 데이터
    

즉, **코드만 작성하면 실행 환경은 자동으로 제공**됩니다.  
운영 부담은 줄지만 환경 제약이 있을 수 있습니다.

---

### SaaS (Software as a Service)

예: Salesforce

- 클라우드 제공자: 인프라부터 애플리케이션까지 전부 관리
    
- 사용자: 설정 및 데이터 입력만 수행
    

즉, **이미 완성된 소프트웨어를 사용하는 모델**입니다.  
가장 간편하지만 제어권은 거의 없습니다.

---

## 3. 비유로 이해하기 (집 개념)

### 1. IaaS로 개발하는 경우

예: Amazon Web Services EC2

#### 개발자가 해야 하는 일

1. 가상 서버 생성
    
2. Linux 설치 및 설정
    
3. Nginx / Apache 설치
    
4. Node.js 또는 Java 설치
    
5. 데이터베이스 직접 설치 (MySQL 등)
    
6. 보안 설정 (방화벽, 포트, SSL)
    
7. 애플리케이션 배포
    
8. 스케일링 및 모니터링 설정
    

#### 실제 흐름

- EC2 인스턴스 생성
    
- SSH로 접속
    
- 서버 환경 세팅
    
- Git pull → 빌드 → 실행
    
- 트래픽 증가 시 서버 직접 추가 및 로드밸런서 구성
    

#### 특징

- 인프라부터 애플리케이션까지 직접 관리
    
- 자유도 매우 높음
    
- DevOps 역량 필요
    

---

### 2. PaaS로 개발하는 경우

예: Google Cloud App Engine

#### 개발자가 해야 하는 일

1. 코드 작성
    
2. 환경 설정 파일 작성
    
3. CLI로 배포 명령 실행
    

#### 실제 흐름

- `gcloud app deploy` 실행
    
- 자동으로 빌드 및 배포
    
- 트래픽 증가 시 자동 확장
    
- OS, 런타임, 서버 관리 불필요
    

#### 특징

- 서버 접속 개념이 거의 없음
    
- 개발 속도 빠름
    
- 특정 언어/환경 제약 가능
    

---

### 3. SaaS를 사용하는 경우

예: Shopify

이 경우는 “개발”이 아니라 “서비스 사용”에 가깝습니다.

#### 해야 하는 일

1. 회원 가입
    
2. 디자인 템플릿 선택
    
3. 상품 등록
    
4. 결제 시스템 설정
    

코드를 거의 작성하지 않습니다.

#### 특징

- 인프라, 서버, 배포 개념 없음
    
- 가장 빠르게 시작 가능
    
- 구조 커스터마이징은 제한적
    

---

### 동일한 쇼핑몰을 만들 때 차이

|구분|IaaS|PaaS|SaaS|
|---|---|---|---|
|서버 세팅|직접|자동|없음|
|OS 관리|직접|제공자|없음|
|코드 작성|필요|필요|거의 없음|
|배포|수동 구성|명령 한 번|개념 없음|
|확장|직접 설정|자동 확장|자동|
|자유도|매우 높음|중간|낮음|

---

### 한 줄 정리

- IaaS: 서버까지 직접 관리하면서 개발
    
- PaaS: 코드에 집중해서 개발
    
- SaaS: 개발 없이 바로 사용

---

## 4. 핵심 차이 요약

- IaaS → 인프라만 제공, 제어권 높음
    
- PaaS → 실행 환경 제공, 개발 집중
    
- SaaS → 완성된 서비스 제공, 사용만 하면 됨
