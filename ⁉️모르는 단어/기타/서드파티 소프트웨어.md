### 서드파티 소프트웨어 (Third-Party Software)

서드파티 소프트웨어는 **내가 직접 개발하지 않은 외부 업체(또는 외부 개발자)가 만든 소프트웨어**를 의미합니다.

여기서

- First-party: 자사(내가 속한 조직)
    
- Second-party: 계약 관계에 있는 파트너
    
- Third-party: 그 외의 외부 독립 개발자 또는 기업
    

즉, 우리 시스템에 **외부에서 만든 프로그램이나 라이브러리를 가져다 쓰는 것**이 서드파티 소프트웨어입니다.

---

### 1. 실제 개발 예시

#### 예시 1: 로그인 기능 구현

직접 OAuth 서버를 만드는 대신

- Google 로그인
    
- Kakao 로그인
    
- Naver 로그인
    

같은 외부 인증 시스템을 사용하면 이것이 서드파티 서비스 사용입니다.

---

#### 예시 2: 결제 시스템

직접 카드 결제 시스템을 구축하지 않고

- Stripe
    
- 토스페이먼츠
    
- PayPal
    

같은 결제 솔루션을 연동하면 서드파티 소프트웨어를 사용하는 것입니다.

---

#### 예시 3: 개발 라이브러리

Java 프로젝트에서

- Spring Framework
    
- Hibernate
    

같은 프레임워크를 사용하는 것도 서드파티 라이브러리 사용입니다.

---

### 2. 왜 사용하는가

1. 개발 시간 단축
    
2. 검증된 기능 활용
    
3. 보안 및 안정성 확보
    
4. 핵심 비즈니스 로직에 집중 가능
    

---

### 3. 장점

- 빠른 개발 가능
    
- 유지보수 부담 감소
    
- 전문 영역(결제, 보안 등)을 신뢰성 있게 해결
    

---

### 4. 단점 및 리스크

1. 벤더 종속 (Vendor Lock-in)
    
2. 라이선스 문제
    
3. 보안 취약점 발생 가능
    
4. 서비스 종료 위험
    
5. 비용 증가 가능성
    

---

### 5. 온프레미스 vs 클라우드 관점

- 라이브러리 형태 → 코드에 포함되는 서드파티
    
- API/SaaS 형태 → 외부 서버와 통신하는 서드파티
    
- SDK 형태 → 특정 플랫폼에 종속되는 경우
    

---

### 6. 한 줄 정리

서드파티 소프트웨어는 **우리 시스템 외부에서 개발된 소프트웨어를 가져다 사용하는 것**이며,  
현대 개발 환경에서는 거의 모든 프로젝트가 다양한 서드파티에 의존합니다.

원하시면 오픈소스 라이선스(GPL, MIT 등) 관점에서의 차이까지 확장해서 설명해 드리겠습니다.
