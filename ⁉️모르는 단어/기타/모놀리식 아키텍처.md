모든 기능이 하나의 애플리케이션으로 구성되는 구조입니다.  
하나의 코드베이스, 하나의 빌드 결과물, 하나의 배포 단위로 동작합니다.

모놀리식이 적합한 경우

- 초기 스타트업
    
- 팀 규모가 작음
    
- 빠른 MVP 개발이 목표

---
#### 구조 특징

- 사용자 관리, 주문, 결제, 상품 관리 등이 모두 하나의 프로젝트 안에 존재
    
- 하나의 DB를 공유하는 경우가 많음
    
- 하나의 서버(또는 동일한 애플리케이션 인스턴스들)로 배포
    

#### 예시 상황

온라인 쇼핑몰을 만든다고 가정하면:

- UserController
    
- OrderService
    
- PaymentService
    
- ProductRepository
    

모두 하나의 애플리케이션 안에 존재  
배포는 단일 WAR/JAR 또는 단일 서버 이미지

#### 장점

- 초기 개발 속도가 빠름
    
- 구조가 단순해 이해하기 쉬움
    
- 테스트 및 디버깅이 비교적 간단
    

#### 단점

- 일부 기능 수정에도 전체 재배포 필요
    
- 코드가 커질수록 복잡도 급증
    
- 특정 기능만 확장(스케일링)하기 어려움
    
- 팀 규모가 커질수록 충돌 증가
