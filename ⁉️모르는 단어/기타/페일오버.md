**페일오버(Failover)**는  
👉 **장애가 발생했을 때, 자동(또는 수동)으로 다른 서버/시스템으로 전환하는 것**을 의미해.

---

## 핵심 개념 (한 줄 정리)

> **Primary(주 시스템)가 죽으면 → Secondary(대기 시스템)가 대신 서비스하는 것**

---

## 어떻게 동작하냐

1. **Primary 서버가 정상 동작**
    
2. Secondary 서버는 대기 상태 (heartbeat 체크)
    
3. Primary 장애 발생
    
4. Secondary가 이를 감지하고 **즉시 역할을 가져감 (Failover)** ([druva.com](https://www.druva.com/learning-center/glossary/what-is-a-failover-definition-and-related-faqs?utm_source=chatgpt.com "Failover Meaning & Definition: How Failover Works in Servers & Networks | Druva"))
    

---

## 예시 (RDS / DB 기준)

Terraform + RDS 관점에서 보면:

- **Primary DB (writer)**
    
- **Replica DB (standby / reader)**
    

👉 Primary 장애 발생 시  
→ Replica가 **Primary로 승격 (promotion)**  
→ 서비스 계속 유지

---

## 종류 (실무 중요)

### 1. 자동 Failover

- 장애 발생 시 자동 전환
    
- 운영에서는 거의 필수
    
- 다운타임 최소화
    

### 2. 수동 Failover

- 사람이 직접 전환
    
- 유지보수 시 사용
    

### 3. 강제 Failover

- 데이터 손실 가능성 있음
    
- 긴급 상황 대응
    

---

## 아키텍처 패턴

### Active - Passive

- 하나만 동작, 하나는 대기
    
- RDS Multi-AZ 기본 구조
    

### Active - Active

- 둘 다 동작
    
- 장애 시 트래픽 분산 유지
    

---

## 왜 중요한가

- 서비스 다운 방지 (High Availability)
    
- 장애 대응 자동화
    
- SLA 보장
    

---

## Terraform 관점에서 연결

네가 지금 하는 RDS 기준으로 보면 핵심 옵션은 이거야:

```hcl
multi_az = true
```

👉 이거 켜면 AWS가 자동으로:

- standby 인스턴스 생성
    
- 장애 시 자동 failover 수행
    

---

## 한 줄 정리

> **Failover = 장애 → 자동으로 다른 인스턴스로 역할 전환**
