기능을 독립적인 작은 서비스 단위로 나누는 구조입니다.  
각 서비스는 독립적으로 개발, 배포, 확장이 가능합니다.

MSA가 적합한 경우

- 서비스 규모가 크고 트래픽이 많음
    
- 조직이 여러 팀으로 분리됨
    
- 서비스별 독립 배포가 중요

---
#### 구조 특징

- User Service
    
- Order Service
    
- Payment Service
    
- Product Service
    

각각이 별도의 애플리케이션  
각각이 별도의 DB를 가지는 경우가 일반적  
서비스 간 통신은 REST API, gRPC, 메시지 큐 등으로 수행

#### 예시 상황

쇼핑몰 시스템을 MSA로 구성하면:

- 주문 트래픽이 급증하면 Order Service만 확장
    
- 결제 시스템 수정 시 Payment Service만 재배포
    
- 서비스별로 서로 다른 기술 스택 사용 가능
    

#### 장점

- 서비스별 독립 배포 가능
    
- 부분 확장 가능 (유연한 스케일링)
    
- 장애 격리 가능
    
- 대규모 팀 협업에 유리
    

#### 단점

- 분산 시스템 복잡성 증가
    
- 네트워크 통신 비용 발생
    
- 데이터 일관성 관리 어려움
    
- DevOps, 모니터링, CI/CD 체계 필수
