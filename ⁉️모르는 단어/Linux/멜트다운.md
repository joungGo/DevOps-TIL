# Meltdown

**Meltdown**은 CPU의 **[[추측 실행(Speculative Execution)]]** 취약점을 이용해  
사용자 공간 프로그램이 **커널 메모리를 읽을 수 있게 만드는 보안 취약점**이다.

2018년에 공개되었으며, 주로 인텔 CPU에서 문제가 되었다.

---

# 1. 무엇이 문제인가?

운영체제는 보통:

- 사용자 영역(User space)
    
- 커널 영역(Kernel space)
    

을 **페이지 테이블 권한 비트**로 구분한다.

원칙적으로는:

> 사용자 프로그램은 커널 메모리를 읽을 수 없다.

하지만 Meltdown은 CPU 내부 동작의 허점을 이용한다.

---

# 2. 왜 발생하는가?

원인: **Out-of-Order 실행 + 추측 실행**

CPU는 성능 향상을 위해:

1. 먼저 실행해보고
    
2. 나중에 권한을 확인한다
    

권한이 없으면 결과는 "폐기"되지만  
문제는:

> 캐시에는 흔적이 남는다.

공격자는 이 캐시 타이밍 차이를 측정해  
커널 메모리 값을 유추할 수 있다.

즉,

```text
권한 오류는 나지만,
캐시를 통해 값이 새어나간다.
```

---

# 3. 어떤 정보가 유출될 수 있나?

- 커널 메모리
    
- 다른 프로세스의 메모리
    
- 암호 키
    
- 패스워드
    

특히 클라우드 환경에서 심각한 문제였다.

---

# 4. 왜 이름이 Meltdown인가?

> 커널과 사용자 공간 사이의 보호 장벽이 "녹아내린다"는 의미

---

# 5. 대응 방법

### 1. KPTI (Kernel Page Table Isolation)

- 사용자 모드에서는 커널 페이지 테이블 제거
    
- 커널 진입 시에만 매핑
    

Linux에서 적용된 대표 패치.

### 2. CPU 마이크로코드 업데이트

- 추측 실행 동작 제한
    

---

# 6. 성능 영향

KPTI 적용 후:

- 시스템 콜
    
- 인터럽트
    
- 컨텍스트 스위칭
    

에서 오버헤드 증가

특히 I/O 많은 서버에서 성능 저하 발생.

---

# 7. Spectre와 차이

|항목|Meltdown|Spectre|
|---|---|---|
|공격 대상|커널 메모리|다른 프로세스/브랜치 예측|
|난이도|비교적 쉬움|더 복잡|
|영향 CPU|주로 인텔|거의 모든 CPU|

---

# 핵심 한 줄

Meltdown은 CPU의 추측 실행 과정에서 발생한 취약점으로, 캐시 타이밍을 이용해 커널 메모리를 유출할 수 있게 만든 보안 문제다.
