**추측 실행**은 CPU가 성능을 높이기 위해  
**결과를 미리 예측하고 먼저 실행하는 기술**이다.

---

# 1. 왜 필요한가?

CPU는 파이프라인 구조로 동작한다.

문제는 이런 코드:

```c
if (x > 0) {
    A();
} else {
    B();
}
```

- 조건 결과가 나오기 전까지 기다리면
    
- 파이프라인이 멈춘다 (stall)
    

그래서 CPU는:

> "아마 이쪽일 거야" 하고 먼저 실행한다.

이게 추측 실행이다.

---

# 2. 어떻게 동작하나?

1. **분기 예측기 (Branch Predictor)** 가 방향을 예측
    
2. 해당 경로의 명령을 먼저 실행
    
3. 예측이 맞으면 그대로 커밋
    
4. 틀리면 결과를 버리고 되돌림 (rollback)
    

즉,

```text
예측 → 먼저 실행 → 맞으면 유지, 틀리면 폐기
```

---

# 3. 핵심 포인트

추측 실행은:

- 레지스터 결과는 되돌릴 수 있음
    
- 하지만 캐시 같은 마이크로아키텍처 상태는 완벽히 되돌리지 못함
    

이게 바로 Meltdown, Spectre 같은 취약점의 원인이다.

---

# 4. 함께 사용되는 기술

- Out-of-Order 실행
    
- 분기 예측
    
- 파이프라인 병렬 처리
    

모두 CPU 성능 향상을 위한 기술이다.

---

# 5. 장점

- 파이프라인 stall 감소
    
- IPC(Instruction Per Cycle) 증가
    
- 체감 성능 크게 향상
    

현대 CPU 성능의 핵심 요소다.

---

# 6. 단점

- 설계 복잡성 증가
    
- 전력 소모 증가
    
- 보안 취약점 가능성 (사이드 채널 공격)
    

---

# 한 줄 정리

추측 실행은 CPU가 분기 결과를 미리 예측해 먼저 실행함으로써 성능을 높이는 기술이지만, 잘못 설계되면 캐시를 통한 정보 유출 같은 보안 문제가 발생할 수 있다.
