인시던트(Incident)는 운영 중인 시스템에서 “정상 서비스에 영향을 주는 문제나 장애”를 의미해.

쉽게 말하면:

- 서비스 장애
    
- 성능 저하
    
- 에러 급증
    
- 응답 지연
    
- 일부 기능 불가
    

같이 사용자나 시스템에 영향을 주는 사건 자체를 인시던트라고 불러.

예시:

- API 응답이 5초 이상 걸림
    
- Kubernetes Node 하나가 다운됨
    
- DB 연결 실패 증가
    
- 로그인 기능 오류 발생
    
- CPU 사용률 100% 지속
    
- Prometheus Alert 발생
    

이런 것들이 전부 인시던트가 될 수 있어.

보통 흐름은 이렇게 진행돼:

1. 이상 징후 발생
    
2. 모니터링 시스템이 감지
    
3. Alert 발송
    
4. 운영자가 조사(RCA)
    
5. 원인 해결
    
6. 사후 분석(Postmortem)
    

예를 들어 Kubernetes에서는:

- `Pod CrashLoopBackOff`
    
- `OOMKilled`
    
- `Node NotReady`
    
- `Ingress 502`
    
- `etcd latency 증가`
    

등이 대표적인 인시던트야.

카오스 시나리오와 연결하면:

- 카오스 시나리오:  
    “의도적으로 장애를 발생시키는 실험”
    
- 인시던트:  
    “실제로 발생한 장애/문제 상황”
    

즉,  
카오스 시나리오를 실행하면 인위적인 인시던트가 만들어지는 구조라고 볼 수 있어.
