# 🔷 전체 시나리오 한 줄 요약

> **호스트 PC 브라우저 → (Host-only 네트워크) → k8s-master VM → Docker 컨테이너(Nginx)**

---

# 1️⃣ VM 네트워크 구조 먼저 이해하기 (핵심)

당신의 `k8s-master` VM에는 **네트워크 어댑터가 2개** 있습니다.

```
[ Host PC ]
    │
    ├─ NAT (10.x.x.x 계열, 인터넷용)
    │
    └─ Host-only (192.168.32.0/24)
            └─ k8s-master (192.168.32.10)
```

### ✔ Host-only 네트워크 의미

- **호스트 ↔ VM 직접 통신 가능** 
	- Host-Only 네트워크 덕분에 호스트와 VM이 같은 네트워크에 있게 되어 VM IP로 직접 접근이 가능하게 된다.
    
- 외부 인터넷에서는 접근 불가
    
- 실습/클러스터 통신에 최적
    

👉 그래서 **브라우저에서 `192.168.32.10` 접속이 가능**한 것

---

# 2️⃣ VM 안에서 Docker 설치 (개념적 동작)

### 🔹 무슨 일이 일어나는가?

1. `apt`가 **NAT 어댑터**를 통해 인터넷 접속
    
2. Docker 패키지를 다운로드
    
3. Docker daemon(`dockerd`) 실행
    

```text
k8s-master
 ├─ eth0 (NAT) → 인터넷
 └─ eth1 (192.168.32.10) → 호스트 통신
```

👉 Docker 자체는 **네트워크와 독립적**  
👉 컨테이너 네트워크는 Docker가 내부에서 관리

---

# 3️⃣ docker pull nginx 동작 과정

```bash
docker pull nginx
```

### 내부에서 일어나는 일

1. Docker daemon이 **Docker Hub**에 요청
    
2. nginx 이미지 레이어 다운로드
    
3. 로컬 이미지 캐시에 저장
    

```text
Docker Hub
   ↓
k8s-master:/var/lib/docker
```

📌 아직 **컨테이너는 없음**  
📌 그냥 실행 가능한 이미지 파일만 있는 상태

---

# 4️⃣ docker run 실행 시 실제로 벌어지는 일 (중요)

```bash
docker run --name mynginx -d -p 80:80 nginx
```

이 한 줄에서 **여러 일이 동시에 일어납니다.**

---

## 🔹 (1) 컨테이너 생성

- nginx 이미지 기반 컨테이너 생성
    
- 네임스페이스/CGroups 분리
    
- PID, FS, Network 독립
    

---

## 🔹 (2) Docker 브리지 네트워크 연결

Docker는 기본적으로:

```text
docker0 (172.17.0.1)
   └─ mynginx (172.17.0.2)
```

- 컨테이너는 **사설 IP**를 가짐
    
- 외부에서는 직접 접근 불가
    

---

## 🔹 (3) 포트 바인딩 `-p 80:80`의 진짜 의미 ⭐⭐⭐

```text
-p [HOST_PORT]:[CONTAINER_PORT]
```

여기서:

```text
HOST_PORT      = k8s-master VM의 80번 포트
CONTAINER_PORT = nginx 컨테이너의 80번 포트
```

### Docker가 내부적으로 하는 일

1. iptables 규칙 생성
    
2. VM의 `0.0.0.0:80` 리스닝
    
3. 들어온 트래픽을 컨테이너로 DNAT
    

```text
[192.168.32.10:80] // :80 포트는 VM의 호스트 포트번호
        ↓
[k8s-master:80]
        ↓ (iptables)
[mynginx:80]
```

---

# 5️⃣ 브라우저에서 접속할 때 패킷 흐름 (핵심)

## 🔥 여기 제일 중요합니다

### 브라우저에서 입력:

```
http://192.168.32.10
```

### 실제 흐름:

```text
[Host PC 브라우저]
        ↓
[Host-only 네트워크]
        ↓
[k8s-master eth1:192.168.32.10:80]
        ↓
[Docker iptables NAT]
        ↓
[mynginx 컨테이너:80]
        ↓
[Nginx index.html 응답]
        ↑
[같은 경로로 되돌아옴]
```

👉 **포트 포워딩(NAT 10080)** ❌ 사용 안 됨  
👉 **Host-only 네트워크 직접 통신** ⭕

---

# 6️⃣ 왜 이게 되는지 한 문장으로

> Docker는 **VM의 80번 포트를 점유**하고,  
> Vagrant는 **VM에 192.168.32.10 IP를 부여**했기 때문에  
> 호스트 브라우저가 바로 컨테이너에 접근할 수 있다.

---

## ✅ 최종 정리

- `192.168.32.10` 접속은 **Host-only 네트워크 덕분**
    
- `-p 80:80`은 **VM → 컨테이너 포트 연결**
    
- Docker는 **iptables NAT**로 트래픽 전달
    
- 포트포워딩 설정은 이 실습에 **필요 없음**
