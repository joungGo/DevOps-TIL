## ✅ **즉시 해결 방법**

### **1. SSH 호스트 키 초기화 (호스트 PC에서 실행)**

```bash
# Windows (PowerShell)
ssh-keygen -R 192.168.32.10

# macOS/Linux
ssh-keygen -R 192.168.32.10
```

이 명령어는 **저장된 SSH 호스트 키를 삭제**합니다.

---

### **2. Terminus에서 재연결**

위 명령어 실행 후:

1. Terminus에서 **k8s-master 연결 클릭**
2. "Host key verification failed" 경고가 뜨면 **"Yes" 또는 "Accept"** 클릭
3. 정상 연결됨

---

## 🔍 **왜 이런 문제가 발생했나?**

### **SSH 호스트 키 메커니즘:**

1. 첫 SSH 연결 시, 서버의 **호스트 키**(지문)가 클라이언트에 저장됨
2. `/etc/hostname` 변경 후 재부팅하면 SSH가 **새로운 호스트 키** 생성
3. 클라이언트(Terminus)가 저장된 키와 다른 키를 발견 → **보안 경고 발생**

---

## 1️⃣ SSH 호스트 키란?

**SSH 호스트 키(Host Key)**는  
👉 **“이 서버가 진짜 그 서버인지”를 증명하는 서버의 신분증**이야.

- 서버(= VM)가 **자기 자신을 증명**하기 위한 키
    
- **서버마다 고유**
    
- **클라이언트가 서버를 검증**할 때 사용
    

⚠️ 이건 **사용자(vagrant)의 키**가 아니라  
👉 **서버 자체의 키**라는 게 중요해.

---

## 2️⃣ SSH 연결에서 호스트 키는 언제 쓰일까?

### 최초 접속 시

```text
클라이언트 → 서버에 접속 시도
서버 → "이게 내 호스트 키야"
클라이언트 → "처음 보네? 저장할까?"
```

사용자가 **Yes**를 누르면:

- 서버의 호스트 키가
    
- 클라이언트 PC에 저장됨
    

📍 저장 위치 예:

```
~/.ssh/known_hosts
```

---

### 두 번째 접속부터

```text
클라이언트 → 서버 접속
클라이언트 → 저장된 호스트 키와 비교
```

- 같으면 → ✅ 정상 접속
    
- 다르면 → ❌ **보안 경고**
    

---

## 3️⃣ 왜 호스트 키가 바뀌면 큰 문제일까?

SSH는 이렇게 생각해:

> “예전에 만났던 192.168.32.10이랑  
> 지금 192.168.32.10은 **다른 놈인데?**  
> 중간에서 누가 가로챈 거 아냐?”

즉,  
👉 **중간자 공격(MITM)** 가능성을 의심하는 거야.

그래서 에러 메시지가 강함:

```
WARNING: REMOTE HOST IDENTIFICATION HAS CHANGED!
```

---

## 4️⃣ 네 환경에서 호스트 키가 바뀐 이유 (정확히)

### Vagrant + VM 환경에서는 이게 자주 발생함

- VM destroy 후 재생성
    
- 디스크 새로 생성
    
- `/etc/hostname` 변경
    
- `sshd_config.sh` 재적용
    
- OS 재설치
    

👉 이 순간 **SSH 서버가 새 키를 생성**

그런데:

- IP는 그대로 (`192.168.32.10`)
    
- 클라이언트는 예전 키를 기억 중
    

➡️ **충돌 발생**

---

## 5️⃣ `ssh-keygen -R`는 정확히 뭘 하나?

```bash
ssh-keygen -R 192.168.32.10
```

이 명령은:

- `known_hosts` 파일에서
    
- `192.168.32.10`에 해당하는 **기존 호스트 키 기록만 삭제**
    

❌ 서버에는 아무 영향 없음  
✅ **클라이언트 쪽 캐시만 정리**

---

## 6️⃣ Terminus에서도 같은 원리야

- Terminus = SSH 클라이언트
    
- 내부적으로 호스트 키 저장
    
- 키가 바뀌면 연결 차단
    

그래서:

1. 기존 키 삭제
    
2. 새 키 승인 (Accept)
    

하면 정상 연결됨

---

## 7️⃣ 헷갈리기 쉬운 키 2종류 정리

|구분|역할|저장 위치|
|---|---|---|
|**호스트 키**|서버 신원 증명|서버: `/etc/ssh/ssh_host_*`클라이언트: `known_hosts`|
|**사용자 키**|사용자 인증|`~/.ssh/id_rsa` 등|

👉 지금 문제는 **무조건 호스트 키 쪽**

---

## 8️⃣ 한 문장으로 요약

> **SSH 호스트 키는 “서버의 지문”이고,  
> VM을 새로 만들면 지문이 바뀌기 때문에  
> 클라이언트는 보안상 접속을 막는다.**

---

다음으로 이어가면 딱 좋은 주제는:

- 왜 **IP는 같은데 서버는 다른 걸로 인식되는지**
    
- k8s 클러스터에서 노드 재생성 시 SSH 키 전략
    
- known_hosts 관리 팁 (여러 VM 쓸 때)
