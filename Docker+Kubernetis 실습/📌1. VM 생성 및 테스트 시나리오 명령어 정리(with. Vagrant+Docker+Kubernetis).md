# 📘 Vagrant 기반 VM에서 Docker + Nginx 테스트 실습 설명서

_(Kubernetes 실습 확장 대비 버전)_

---

## 0️⃣ 실습 환경 전제

### 0-1. 호스트 환경

- Vagrant + VirtualBox 설치 완료
    
- OS: Ubuntu 기반
    
- `generic/ubuntu2004` box 사용
    

---

### 0-2. VM 구성 (Vagrantfile 기준)

|VM 이름|IP|역할|
|---|---|---|
|k8s-master|192.168.32.10|Master|
|k8s-node01|192.168.32.11|Worker|
|k8s-node02|192.168.32.12|Worker|

네트워크 구성:

- **NAT** : 인터넷 접근
    
- **Host-only** : 노드 간 통신 및 Host 접근
    

```ruby
cfg.vm.network "private_network", ip: "192.168.32.10"
cfg.vm.network "forwarded_port", guest: 80, host: 10080
```

📌 forwarded_port는 설정만 존재하며 **본 실습에서는 직접 사용하지 않음**

## 1️⃣ Vagrant 기반 VM 생성 및 접속

### 1-1. VM 생성 및 부팅

```bash
vagrant up
```

**설명**

- 포트 포워딩과 계정 정보를 자동 처리
    

📌 이후 설정은 **Master / Node 모두 동일하게 수행**

## 2️⃣ 사전 준비 (Master / Node 공통)

---

### 2-1. Root 계정 전환 및 비밀번호 설정

```bash
sudo su -
```

- root 계정으로 전환 (시스템 설정 작업을 위해 필요)
    

```bash
passwd root
```

- root 계정 비밀번호 설정
    

예시 비밀번호: `vagrant`

---

### 2-2. SWAP 비활성화

```bash
swapoff -a && sed -i '/swap/s/^/#/' /etc/fstab
```

**설명**

- 현재 활성화된 swap 즉시 비활성화
    
- 재부팅 후에도 swap이 켜지지 않도록 설정
    
- kubelet은 swap 활성화 상태에서 실행 불가
    

---

### 2-3. 브리지 네트워크 커널 옵션 활성화

```bash
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
br_netfilter
EOF
```

- 브리지 네트워크 트래픽을 커널에서 처리하도록 모듈 로드
    

```bash
cat <<EOF>>  /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-ip6tables = 1
net.bridge.bridge-nf-call-iptables = 1
EOF
```

- 브리지 트래픽이 iptables 규칙을 거치도록 설정
    

```bash
sysctl --system
```

- 커널 파라미터 즉시 적용
    

**설명**

- Kubernetes Pod 간 통신 시 네트워크 패킷이 정상적으로 필터링되도록 하기 위함

# Kubernetes 설치 및 설정 가이드

## 7. Kubernetes 설치 - Master, Node 모두

### Kubernetes 저장소 설정

```bash
# 1. 기존 저장소 파일 삭제 (이전 설정 제거)
rm -f /etc/apt/sources.list.d/kubernetes.list

# 2. 기존 키 제거 (이전 GPG 키 삭제)
rm -f /etc/apt/keyrings/kubernetes-apt-keyring.gpg

# 3. 필요한 패키지 설치 (HTTPS 저장소 사용을 위한 도구들)
apt-get update
apt-get install -y apt-transport-https ca-certificates curl gpg

# 4. 새로운 Kubernetes 저장소 GPG 키 추가 (패키지 검증을 위한 보안 키)
mkdir -p /etc/apt/keyrings
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.31/deb/Release.key | gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

# 5. 새로운 저장소 추가 (Kubernetes 공식 패키지 저장소 등록)
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.31/deb/ /' | tee /etc/apt/sources.list.d/kubernetes.list

# 6. apt 업데이트 (새 저장소 정보 반영)
apt-get update

# 7. Kubernetes 핵심 컴포넌트 설치
# - kubelet: 각 노드에서 Pod와 컨테이너를 관리하는 에이전트
# - kubeadm: 클러스터 초기화 및 관리 도구
# - kubectl: Kubernetes 클러스터 제어 CLI 도구
apt-get install -y kubelet kubeadm kubectl

# 8. 버전 고정 (자동 업데이트로 인한 버전 불일치 방지)
apt-mark hold kubelet kubeadm kubectl
```

### 버전 확인

```bash
# 설치된 버전 확인
kubeadm version
kubelet --version
kubectl version
```

### Docker와 systemd cgroup 드라이버 통합 설정

```bash
# Docker 설정 디렉토리 생성
sudo mkdir -p /etc/docker

# Docker daemon 설정 파일 생성
# - native.cgroupdriver=systemd: kubelet과 동일한 cgroup 드라이버 사용
# - log-driver: 로그 포맷 설정
# - max-size: 로그 파일 최대 크기 제한
# - storage-driver: Docker 스토리지 드라이버 설정
cat <<EOF | sudo tee /etc/docker/daemon.json
{
  "exec-opts": ["native.cgroupdriver=systemd"],
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m"
  },
  "storage-driver": "overlay2"
}
EOF

# Docker 서비스 활성화 및 재시작 (설정 적용)
sudo systemctl enable docker
sudo systemctl daemon-reload
sudo systemctl restart docker
```

### containerd 설정 및 이미지 다운로드

```bash
# containerd 기본 설정 파일 제거 (최신 기본값 사용)
rm /etc/containerd/config.toml

# containerd 재시작 (새 설정 적용)
systemctl restart containerd

# Kubernetes 구성 요소 이미지 미리 다운로드 (클러스터 초기화 시간 단축)
kubeadm config images pull
```

## 8. Kubernetes 설정 - Master

### conntrack 설치 (Master에서 실행)

`apt update apt install -y conntrack`

설치 확인:

`which conntrack conntrack -V`

### 클러스터 초기화

```bash
# 기존 클러스터 설정 초기화 (이전 설정 제거)
kubeadm reset

# 클러스터 초기화
# - --pod-network-cidr: Pod 네트워크 대역 설정
# - --apiserver-advertise-address: API 서버가 사용할 Master 노드 IP
kubeadm init --pod-network-cidr=10.96.0.0/16 --apiserver-advertise-address=192.168.32.10
```

### Worker Node 연결 명령어 저장

초기화 완료 후 출력되는 아래와 같은 명령어를 복사해두세요 (Worker Node에서 사용):

```bash
# 예시 (실제 값은 환경마다 다름)
kubeadm join 192.168.32.10:6443 --token x1qogf.3i1d8zc267sm4gq8 \
--discovery-token-ca-cert-hash sha256:1965b56832292d3de10fc95f92b8391334d9404c914d407baa2b6cec1dbe5322
```

### kubectl 명령어 사용 설정

```bash
# root 계정 없이 kubectl 사용하기 위한 설정
# - kubeconfig 파일을 사용자 홈 디렉토리에 복사
# - 파일 소유권을 현재 사용자로 변경
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

### Calico 네트워크 플러그인 설치

```bash
# Calico CNI(Container Network Interface) 다운로드
# - Pod 간 네트워크 통신을 위한 필수 플러그인
curl https://docs.projectcalico.org/archive/v3.25/manifests/calico.yaml -O --insecure

# Calico 배포
kubectl apply -f calico.yaml

# 모든 네임스페이스의 Pod 상태 확인
kubectl get pods --all-namespaces
```

## 10. 테스트

### Nginx Pod 배포 테스트

```bash
# nginx 이미지로 Pod 생성
kubectl run nginx-test --image=nginx --port 80

# Pod를 ClusterIP Service로 노출
kubectl expose pod nginx-test

# 생성된 Service 확인
kubectl get services
```

### Service를 외부 접속 가능하도록 변경

```bash
# Service 타입을 ClusterIP에서 NodePort로 변경
# - ClusterIP: 클러스터 내부에서만 접속 가능
# - NodePort: 외부에서 노드 IP:포트로 접속 가능
kubectl edit service nginx-test
# (편집기에서 type: ClusterIP -> type: NodePort로 변경)
```

### 웹 브라우저로 접속 확인

```bash
# Service에서 할당된 NodePort 확인 후 접속
# 예시: http://192.168.32.10:30039/  # Master 노드 IP
#      http://192.168.32.11:30039/  # Worker 노드 IP
# (실제 포트 번호는 kubectl get services로 확인)
```
