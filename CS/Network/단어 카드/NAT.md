> 사설 IP를 쓰는 여러 호스트가  
> 공인 IP가 하나뿐인 환경에서  
> 어떻게 동시에 외부와 통신할 수 있을까?

이를 해결하는 과정이 다음 순서로 정리

1. 사설 IP는 외부 인터넷에서 직접 식별 불가
    
2. NAT 장비가 사설 IP ↔ 공인 IP 변환
    
3. 단순 1:1 NAT는 공인 IP가 너무 많이 필요
    
4. 해결책으로 **NAPT(PAT)** 사용
    
5. 포트 번호를 함께 변환하여 다수의 사설 IP를 구분
    
6. 이를 관리하기 위해 **NAT 변환 테이블** 사용
    

---

## 1. NAT의 기본 개념

- NAT는 **IP 주소를 변환**하는 기능
    
- 외부에서는 내부 사설 IP를 직접 볼 수 없음
    
- 외부에서 보이는 것은 **공인 IP**
    
- 내부 호스트 구분은 NAT 장비가 담당
    

즉,  
외부 서버 입장에서는 “모든 요청이 하나의 공인 IP에서 오는 것처럼” 보인다.

---

## 2. 단순 NAT (1:1 매핑)의 한계

그림 중간에 이런 흐름이 있다.

- 사설 IP ↔ 공인 IP를 1:1로 매핑
    
- 사설 IP 수만큼 공인 IP 필요
    
- 현실적으로 공인 IP가 부족
    

### 예시 (단순 NAT)

|공인 IP|사설 IP|
|---|---|
|1.2.3.4|192.168.1.10|
|1.2.3.5|192.168.1.11|

이 방식은 구조는 단순하지만, **공인 IP 낭비가 심함**.

---

## 3. NAPT(PAT)의 등장 이유

그림 하단에서 NAT → NAPT(PAT)로 넘어간다.

핵심 아이디어는 다음과 같다.

- IP만으로는 내부 호스트를 구분할 수 없다
    
- **포트 번호까지 함께 변환**하면 구분 가능
    
- 하나의 공인 IP로 여러 내부 호스트 처리 가능
    

즉,

> 공인 IP + 포트 번호 = 내부 호스트 식별자

---

## 4. NAT 변환 테이블의 역할

NAT 장비는 변환 정보를 **NAT 변환 테이블**로 관리한다.

이 테이블이 없으면:

- 외부에서 들어온 응답 패킷을
    
- 어느 내부 호스트로 보내야 할지 알 수 없음
    

---

## 5. NAT 변환 테이블 변화 예시 (그림 기반)

### 5-1. 초기 상태 (통신 전)

```
NAT 변환 테이블: 비어 있음
```

---

### 5-2. 호스트 A가 외부로 통신 시작

- 호스트 A
    
    - 사설 IP: `192.168.1.10`
        
    - 출발 포트: `1025`
        
- NAT가 공인 IP `1.2.3.4`와 포트 `62000` 할당
    

```markdown
| 공인 IP:포트 | 사설 IP:포트 |
|--------------|--------------|
| 1.2.3.4:62000 | 192.168.1.10:1025 |
```

---

### 5-3. 호스트 B도 동시에 통신

- 호스트 B
    
    - 사설 IP: `192.168.1.11`
        
    - 출발 포트: `1026`
        
- 같은 공인 IP, 다른 포트 사용
    

```markdown
| 공인 IP:포트 | 사설 IP:포트 |
|--------------|--------------|
| 1.2.3.4:62000 | 192.168.1.10:1025 |
| 1.2.3.4:62001 | 192.168.1.11:1026 |
```

이제 외부 서버는:

- `1.2.3.4:62000` → 호스트 A
    
- `1.2.3.4:62001` → 호스트 B
    

로 응답을 보낼 수 있다.

---

## 6. 응답 패킷 처리 방식

1. 외부 서버 → `1.2.3.4:62000`
    
2. NAT 장비가 테이블 조회
    
3. 대응되는 사설 주소 확인
    
4. `192.168.1.10:1025`로 변환 후 전달
    

이 과정이 **투명하게 자동 처리**된다.

---

## 7. 그림에서 강조하는 핵심 포인트

- 외부에서는 내부 사설 IP를 알 수 없다
    
- NAT 장비만이 매핑 관계를 알고 있다
    
- NAPT는 IP 부족 문제의 현실적인 해결책이다
    
- NAT 변환 테이블이 통신의 핵심이다
    

---

## 한 줄 정리

> **NAPT(PAT)는 하나의 공인 IP에 포트 번호를 결합하여  
> 여러 사설 IP 호스트의 외부 통신을 가능하게 하고,  
> 그 중심에는 NAT 변환 테이블이 있다.**

원하면 다음으로

- 포트 포워딩과 NAPT 차이
    
- 서버 운영 시 NAT의 한계
    
- IPv6에서 NAT가 필요 없는 이유
