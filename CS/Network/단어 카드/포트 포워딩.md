## 1. 포트 포워딩이란?

**포트 포워딩**은  
외부에서 특정 **공인 IP:포트**로 들어온 요청을  
내부 네트워크의 **특정 사설 IP:포트**로 **고정적으로 전달**하는 기능이다.

즉,

> 외부 → 내부 서버로 들어오는 **길을 미리 열어두는 설정**

이다.

---

## 2. 왜 포트 포워딩이 필요한가?

NAT 환경에서는 기본적으로:

- 내부 → 외부 통신은 가능
    
- 외부 → 내부로의 **직접 접근은 불가능**
    

이유:

- NAT 변환 테이블은 **내부에서 먼저 통신을 시작해야** 생성됨
    
- 외부에서 먼저 오는 요청은 매핑 정보가 없어 폐기됨
    

따라서,  
외부에서 내부 서버에 접근하려면 **사전에 매핑을 만들어 둬야** 한다.  
이 역할을 하는 것이 포트 포워딩이다.

---

## 3. 포트 포워딩 동작 구조

### 기본 구조

```
[외부 클라이언트]
        |
        | 1.2.3.4:8080
        v
[공인 IP를 가진 NAT 라우터]
        |
        | 포트 포워딩 규칙
        v
[192.168.1.10:80]
```

---

### 포트 포워딩 규칙 예시

```
공인 IP 1.2.3.4:8080  →  192.168.1.10:80
```

의미:

- 외부에서 `1.2.3.4:8080`으로 들어오면
    
- 내부 서버 `192.168.1.10:80`으로 전달
    

---

## 4. NAT 변환 테이블과의 차이

### NAPT(PAT)

- 내부에서 통신을 시작해야 테이블 생성
    
- 매핑은 **동적**
    
- 외부에서 먼저 접근 불가
    

### 포트 포워딩

- 관리자가 **수동으로 규칙 설정**
    
- 매핑은 **고정**
    
- 외부에서 먼저 접근 가능
    

---

## 5. 포트 포워딩 vs NAPT 비교

|구분|NAPT (PAT)|포트 포워딩|
|---|---|---|
|목적|내부 → 외부 통신|외부 → 내부 접근|
|매핑 생성|자동|수동|
|매핑 방식|동적|고정|
|외부 접근|불가능|가능|
|대표 용도|웹 서핑, API 호출|서버 운영, 원격 접속|

---

## 6. 실제 사용 예시

### 1) 웹 서버 운영

```
1.2.3.4:80 → 192.168.1.10:80
```

외부에서 공인 IP로 웹 접속 가능

---

### 2) SSH 원격 접속

```
1.2.3.4:2222 → 192.168.1.20:22
```

포트 충돌 없이 내부 서버에 접근

---

### 3) 게임 서버 / 개인 서버

- 특정 포트를 내부 서버로 고정 연결
    
- 다수 서버 운영 시 포트 번호로 구분
    

---

## 7. 보안 관점 주의사항

- 포트 포워딩은 **내부 시스템을 외부에 노출**
    
- 반드시:
    
    - 필요한 포트만 개방
        
    - 방화벽 규칙 병행
        
    - 서비스 보안 설정 강화
        

---

## 8. 한 줄 요약

> **포트 포워딩은 NAT 환경에서  
> 외부의 요청을 내부 특정 서버로 전달하기 위해  
> 공인 IP의 포트를 사설 IP의 포트에 고정 매핑하는 기술이다.**

원하면 다음 주제로 이어서 설명할 수 있다.

- 포트 포워딩과 방화벽 차이
    
- 포트 포워딩이 있어도 외부 접속이 안 되는 이유
    
- IPv6 환경에서 포트 포워딩의 변화
