
## 요약

- DHCP는 **자동 IP 할당을 위한 프로토콜**
    
- IP는 **임대 개념**으로 관리됨
    
- 클라이언트와 서버는 **Discover → Offer → Request → ACK** 순서로 통신
    
- 네트워크 관리의 편의성과 IP 충돌 방지를 위해 필수적인 프로토콜
    

원하면 다음으로

- DHCP 릴레이
    
- DHCP가 브로드캐스트를 사용하는 이유
    
- 수동 IP 설정과 DHCP 비교  
    도 이어서 설명해 줄 수 있다.

---

## 1. DHCP 프로토콜이란?

**DHCP(Dynamic Host Configuration Protocol)** 는  
호스트가 네트워크에 접속할 때 **IP 주소와 네트워크 설정 정보를 자동으로 할당**해 주는 프로토콜이다.

DHCP를 통해 할당되는 정보:

- IP 주소
    
- 서브넷 마스크
    
- 기본 게이트웨이
    
- DNS 서버 주소
    
- 임대 기간(Lease Time)
    

IP 주소는 **영구 부여가 아니라 임대** 개념으로 관리된다.

---

## 2. DHCP 구성 요소

### 클라이언트

- IP 주소를 할당받으려는 호스트
    
- 네트워크에 처음 연결되었거나 기존 임대가 만료된 상태
    

### DHCP 서버

- IP 주소 풀(pool)을 관리하며 클라이언트에게 주소를 제공
    
- 일반적으로 **라우터**가 DHCP 서버 역할을 수행
    

---

## 3. DHCP 메시지 교환 과정 (DORA 과정)

DHCP는 총 **4단계 메시지 교환**을 통해 IP 주소를 할당한다.

---

### ① DHCP Discover

- 클라이언트 → 네트워크 전체(브로드캐스트)
    
- 목적: “DHCP 서버가 있는지 탐색”
    

특징:

- 클라이언트는 아직 IP가 없으므로 **출발지 IP = 0.0.0.0**
    
- 목적지 IP는 **255.255.255.255 (브로드캐스트)**
    

---

### ② DHCP Offer

- DHCP 서버 → 클라이언트
    
- 목적: “이 IP를 사용해도 된다”는 제안
    

포함 정보:

- 할당 가능한 IP 주소
    
- 서브넷 마스크
    
- 게이트웨이
    
- DNS 서버
    
- 임대 기간
    

---

### ③ DHCP Request

- 클라이언트 → 네트워크 전체(브로드캐스트)
    
- 목적: “이 서버의 제안을 사용하겠다”는 요청
    

의미:

- 여러 DHCP 서버가 있을 수 있으므로
    
- **선택한 서버의 Offer를 공식적으로 수락**
    

---

### ④ DHCP Acknowledge (ACK)

- DHCP 서버 → 클라이언트
    
- 목적: IP 주소 임대 확정
    

결과:

- 클라이언트는 IP 주소를 정식으로 사용 가능
    
- 임대 타이머 시작
    

---

## 4. DHCP 전체 흐름 요약

```
클라이언트        DHCP 서버
   |  Discover  →
   |            ←  Offer
   |  Request   →
   |            ←  ACK
```

---

## 5. 임대 갱신 과정 (간단 설명)

- 임대 기간의 **50% 경과 시점**: 기존 DHCP 서버에게 갱신 요청
    
- 성공 시: 동일 IP 유지
    
- 실패 시: 임대 종료 후 Discover 단계부터 재시작
