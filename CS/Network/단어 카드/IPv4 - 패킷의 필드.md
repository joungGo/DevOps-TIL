## IPv4 패킷 주요 필드 정리

| 필드명                       | 역할          | 동작 시점      | 핵심 포인트                    |
| ------------------------- | ----------- | ---------- | ------------------------- |
| 식별자 (Identification)      | 원본 패킷 식별    | 단편화 발생 시   | 같은 패킷에서 나온 조각들은 동일한 ID 사용 |
| 플래그 (Flags)               | 단편화 제어      | 전송 및 라우팅 중 | DF: 단편화 금지 / MF: 추가 조각 존재 |
| 단편화 오프셋 (Fragment Offset) | 조각의 위치 정보   | 재조립 시      | 8바이트 단위로 위치 표현            |
| TTL (Time To Live)        | 패킷 생존 시간 제한 | 라우터 통과 시   | 홉마다 1 감소, 0이면 폐기          |
| 프로토콜 (Protocol)           | 상위 계층 식별    | 수신 시       | TCP(6), UDP(17), ICMP(1)  |
| 송신 IP 주소                  | 출발지 식별      | 전송 전       | 응답 경로 판단 기준               |
| 수신 IP 주소                  | 목적지 식별      | 라우팅 판단 시   | 라우팅 테이블 조회 기준             |

## 단편화 관련 필드 묶음 요약

|구분|포함 필드|목적|
|---|---|---|
|단편화 관리|Identification, Flags, Fragment Offset|패킷 분할 및 재조립|
|생존 제어|TTL|루프 방지|
|상위 전달|Protocol|L4 프로토콜 선택|
|경로 판단|Destination IP|라우팅 결정|

## 한 줄 요약

IPv4 패킷 헤더는 단편화 제어, 생존 시간 관리, 상위 프로토콜 구분, 목적지 라우팅을 위해 각 필드가 명확히 분리되어 있다.

---

# 패킷의 필드 (IPv4 헤더 기준)

## 1. 식별자 (Identification)

### 의미

- 하나의 IP 패킷에 부여되는 **고유 번호**
    
- 단편화된 패킷들을 **다시 조립할 때 사용**
    

### 동작 방식

- 송신 호스트가 패킷 생성 시 설정
    
- 단편화가 발생하면 **모든 조각(fragment)에 동일한 식별자 사용**
    

### 왜 필요한가

- 여러 조각이 섞여 도착해도
    
- “같은 원본 패킷인지” 구분하기 위해
    

---

## 2. 플래그 (Flags)

### 구성

- 3비트로 구성
    
    - 예약 비트
        
    - **DF (Don’t Fragment)**
        
    - **MF (More Fragment)**
        

### 각 비트 의미

|비트|의미|
|---|---|
|DF|단편화 금지|
|MF|뒤에 더 많은 조각이 있음|

### 동작 예시

- DF = 1 → MTU 초과 시 폐기 + ICMP 오류
    
- MF = 1 → 아직 마지막 조각 아님
    

---

## 3. 단편화 오프셋 (Fragment Offset)

### 의미

- 해당 조각이 **원본 데이터에서 어디 위치하는지**를 나타냄
    
- 단위: **8바이트(64비트)**
    

### 역할

- 수신 측에서 조각을 **정확한 순서로 재조립**
    

### 관계

- 식별자 + 플래그 + 오프셋은 **항상 함께 동작**
    

---

## 4. TTL (Time To Live)

### 의미

- 패킷의 **생존 시간**
    
- 실제로는 “최대 라우터 통과 횟수”
    

### 동작 방식

- 라우터 하나 지날 때마다 1 감소
    
- TTL = 0 → 패킷 폐기 + ICMP Time Exceeded
    

### 목적

- 라우팅 루프 방지
    
- 네트워크 자원 보호
    

---

## 5. 프로토콜 (Protocol)

### 의미

- IP 패킷의 **상위 계층 프로토콜 종류**
    
- 수신 측에서 어느 프로토콜로 전달할지 결정
    

### 대표 값

|값|프로토콜|
|---|---|
|1|ICMP|
|6|TCP|
|17|UDP|

### 역할

- IP는 **택배 기사**
    
- 프로토콜 필드는 **수신 창구 번호**
    

---

## 6. 송수신 IP 주소 (Source / Destination IP)

### 송신 IP

- 패킷을 보낸 호스트의 IP
    
- 응답 경로 결정에 사용
    

### 수신 IP

- 패킷의 최종 목적지
    
- 라우팅 테이블 조회 기준
    

### 특징

- 라우터를 지나도 **변하지 않음**
    
- 단, NAT 환경에서는 변경 가능
    

---

## 필드 간 관계 요약

```text
[식별자]
   ├─ 플래그 (DF / MF)
   └─ 단편화 오프셋
        → 단편화 및 재조립 담당

[TTL]
   → 루프 방지

[프로토콜]
   → 상위 계층 식별

[송·수신 IP]
   → 라우팅 판단 기준
```
