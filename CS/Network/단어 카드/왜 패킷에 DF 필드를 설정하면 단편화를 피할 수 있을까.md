## IP 네트워크 단편화 피하기

### 1. 초기 전송

송신 호스트는 DF(Don’t Fragment) 비트를 1로 설정한 IP 패킷을 전송한다.  
이 패킷은 Total Length 정보로 자신의 크기가 설정되어 있다.  
이 단계의 목적은 해당 크기의 패킷이 전체 경로에서 전달 가능한지를 확인하는 것이다.

---

### 2. 중간 라우터에서 MTU 초과 발생

중간 라우터는 패킷을 다음 홉 링크로 전달하는 과정에서  
패킷 크기가 해당 링크의 MTU를 초과함을 확인한다.

그러나 DF 비트가 1로 설정되어 있으므로  
라우터는 단편화를 수행할 수 없다.  
이때 해당 IP 패킷은 폐기된다.

---

### 3. ICMP 오류 메시지 전송

패킷을 폐기한 라우터는 송신 호스트에게 ICMP 오류 메시지를 전송한다.

ICMP 메시지에는 다음 정보가 포함된다.

- ICMP Type: 3 (Destination Unreachable)
    
- ICMP Code: 4 (Fragmentation Needed and DF Set)
    

이 메시지에는 적용 가능한 Next-Hop MTU 값이 포함된다.  
즉, 폐기된 원본 IP 패킷의 헤더 일부와 함께  
해당 경로에서 허용되는 최대 패킷 크기 정보가 전달된다.

이는 해당 경로에서 현재 패킷 크기가 너무 크며,  
지정된 MTU 이하로 전송해야 함을 의미한다.

---

### 4. 송신 호스트의 MTU 조정

송신 호스트는 ICMP 오류 메시지를 수신한 후  
적용받은 MTU 값을 기반으로 Path MTU를 결정한다.

이후 전송하는 패킷의 크기를  
해당 MTU 이하로 감소시킨다.

---

### 5. 재전송 및 Path MTU 확정

조정된 크기의 패킷이 다시 전송되며,  
더 이상 MTU 초과로 인한 ICMP 오류 메시지가 발생하지 않으면  
이 시점에서 해당 크기를 경로 상 최소 MTU로 확정한다.

이를 Path MTU라고 한다.
