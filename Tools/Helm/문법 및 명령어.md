## 📁 Helm Chart 디렉토리 구조

```
mychart/
├── Chart.yaml          # 차트 메타정보 (이름, 버전, 설명 등)
├── values.yaml         # 기본 설정값 (사용자가 오버라이드 가능)
├── values.schema.json  # (선택) values.yaml 유효성 검사 JSON Schema
├── charts/             # 의존하는 Sub-Chart 디렉토리
├── crds/               # Custom Resource Definitions
├── templates/          # K8s 매니페스트 템플릿 파일들
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   ├── _helpers.tpl    # 재사용 가능한 템플릿 헬퍼 함수
│   └── NOTES.txt       # 설치 후 출력되는 안내 메시지
└── README.md           # (선택) 사용 가이드
```

## 🧩 Helm 템플릿 문법 (Template Syntax)

Helm 템플릿은 **Go Template 언어** 기반으로 `{{ }}` 구문을 사용합니다.

---

### 1️⃣ 기본 변수 출력

```yaml
# {{ }} 안에 변수 참조
metadata:
  name: {{ .Release.Name }}-app       # 릴리스 이름 + "-app" 문자열을 이어붙여 리소스 이름으로 사용
                                      # 예: helm install my-release → name: my-release-app
  namespace: {{ .Release.Namespace }} # helm install 시 -n 옵션으로 지정한 네임스페이스 자동 주입
                                      # 예: helm install ... -n production → namespace: production
```

**주요 내장 객체:**

|객체|설명|
|---|---|
|`.Release.Name`|현재 릴리스 이름|
|`.Release.Namespace`|설치 네임스페이스|
|`.Release.IsInstall`|최초 설치 여부 (bool)|
|`.Values.xxx`|values.yaml의 값 참조|
|`.Chart.Name`|Chart 이름|
|`.Chart.Version`|Chart 버전|

---

### 2️⃣ Values 참조

```yaml
# values.yaml
# ─────────────────────────────────────────────────────────
# Chart의 기본 설정값을 정의하는 파일
# helm install -f 또는 --set 으로 사용자가 이 값을 덮어쓸 수 있음
image:                     # 이미지 관련 설정을 그룹화한 맵(map) 블록
  repository: nginx        # 사용할 컨테이너 이미지 저장소 주소 (Docker Hub 기준)
  tag: "1.21"              # 이미지 태그 (버전); 문자열로 명시하여 숫자 파싱 오류 방지
replicaCount: 3            # 기본 Pod 복제본 수; 운영 환경에서 --set replicaCount=5 처럼 오버라이드 가능
```

```yaml
# templates/deployment.yaml
# ─────────────────────────────────────────────────────────
spec:
  replicas: {{ .Values.replicaCount }}          # values.yaml의 replicaCount 값을 주입
                                                # 예: 3 → replicas: 3
  containers:
    - image: {{ .Values.image.repository }}:{{ .Values.image.tag }}
      # values.yaml의 image.repository와 image.tag를 ":"로 이어붙여 최종 이미지 경로 생성
      # 예: nginx:1.21
      # --set image.tag=1.23 으로 배포 시 이미지만 손쉽게 교체 가능
```

---

### 3️⃣ 파이프라인(Pipeline) & 함수

Unix의 파이프(`|`)처럼 여러 함수를 체이닝할 수 있습니다.

```yaml
# quote: 문자열을 따옴표로 감쌈
drink: {{ .Values.favorite.drink | quote }}
# .Values.favorite.drink 값을 읽어 quote 함수로 전달
# 예: coffee → "coffee"  (YAML 파싱 오류 방지를 위해 문자열 값엔 quote 권장)

# upper: 대문자 변환 + quote
food: {{ .Values.favorite.food | upper | quote }}
# 파이프라인 체이닝: food 값 → 대문자로 변환(upper) → 따옴표로 감쌈(quote)
# 예: pizza → PIZZA → "PIZZA"

# default: 값이 없을 때 기본값 설정
port: {{ .Values.service.port | default 80 }}
# .Values.service.port 가 nil 또는 빈 값이면 80을 기본값으로 사용
# values.yaml에 port가 누락되어도 안전하게 동작

# indent: 들여쓰기
config: |
{{ .Values.configData | indent 2 }}
# .Values.configData 여러 줄 문자열을 2칸 들여쓰기하여 삽입
# YAML 멀티라인 블록(|) 아래에서 들여쓰기 맞출 때 사용
```

---

### 4️⃣ 조건문 (if / else)

```yaml
{{- if .Values.ingress.enabled }}
# ↑ .Values.ingress.enabled 가 true 이면 아래 블록을 렌더링
# {{- 의 "-" 는 이 줄 앞의 공백/빈 줄을 제거(trim)하여 깔끔한 YAML 출력
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: {{ .Release.Name }}-ingress   # 릴리스 이름 기반으로 Ingress 이름 동적 생성
{{- else }}
# ↑ .Values.ingress.enabled 가 false 이면 이 블록을 렌더링
# Ingress disabled
{{- end }}
# ↑ if 블록 종료; 반드시 end 로 닫아야 함
```

> 💡 `-`는 앞뒤 공백/줄바꿈을 제거하는 트림(trim) 연산자입니다.

---

### 5️⃣ 반복문 (range)

```yaml
# values.yaml
ports:          # 반복 순회할 리스트(배열) 정의
  - 8080        # 첫 번째 포트 값
  - 8443        # 두 번째 포트 값

# template
ports:
{{- range .Values.ports }}
# ↑ .Values.ports 리스트를 순회하며 아래 블록을 반복 렌더링
# "-" 로 range 줄 자체의 공백 제거
  - containerPort: {{ . }}
    # ↑ "." 은 현재 순회 중인 요소를 가리키는 참조자
    # 첫 번째 루프: containerPort: 8080
    # 두 번째 루프: containerPort: 8443
{{- end }}
# ↑ range 반복 블록 종료
```

---

### 6️⃣ with (스코프 변경)

```yaml
{{- with .Values.resources }}
# ↑ .Values.resources 가 존재(non-empty)할 때만 블록 실행
# 블록 안에서 "." 의 스코프가 .Values.resources 로 변경됨
# → 블록 내부에서 매번 .Values.resources.xxx 를 쓰지 않아도 됨
resources:
  limits:
    cpu: {{ .limits.cpu }}      # 스코프가 .Values.resources 이므로 .limits.cpu 로 간결하게 접근
                                # 원래 전체 경로: .Values.resources.limits.cpu
    memory: {{ .limits.memory }}# 마찬가지로 .Values.resources.limits.memory 를 짧게 표현
{{- end }}
# ↑ with 블록 종료; .Values.resources 가 nil/빈 값이면 이 블록 전체가 출력되지 않음
# → 불필요한 빈 resources: 블록이 매니페스트에 생성되는 것을 방지
```

---

### 7️⃣ 템플릿 정의 및 재사용 (`_helpers.tpl`)

```yaml
# _helpers.tpl 에서 정의
{{- define "mychart.fullname" -}}
# ↑ "mychart.fullname" 이라는 이름의 재사용 가능한 Named Template 정의 시작
# 양쪽 "-" 로 define 줄과 end 줄의 공백/줄바꿈을 모두 트림
{{ .Release.Name }}-{{ .Chart.Name }}
# ↑ 릴리스 이름과 Chart 이름을 "-" 로 연결한 문자열을 반환
# 예: helm install my-app ./mychart → "my-app-mychart"
{{- end }}
# ↑ Named Template 정의 종료

# 다른 템플릿에서 호출
metadata:
  name: {{ include "mychart.fullname" . }}
  # ↑ include 함수로 위에서 정의한 "mychart.fullname" 템플릿을 호출
  # "." 은 현재 최상위 컨텍스트(Root Scope)를 그대로 전달
  # 결과: name: my-app-mychart
  # ※ "template" 대신 "include" 를 사용하면 파이프라인(|)에 결과를 연결할 수 있어 권장
```

## ⚡ 실무에서 자주 쓰는 Helm 명령어 총정리

### 📦 Chart 관리

|명령어|설명|
|---|---|
|`helm create <name>`|새 Chart 디렉토리 구조 생성|
|`helm lint <chart>`|Chart 문법/구조 유효성 검사|
|`helm package <chart-path>`|Chart를 `.tgz` 아카이브로 패키징|
|`helm show values <chart>`|Chart의 기본 values.yaml 내용 출력|
|`helm show all <chart>`|Chart 전체 정보 출력|
|`helm dependency update <chart>`|Chart 의존성 업데이트 (`charts/` 폴더에 다운로드)|
|`helm template <name> <chart>`|실제 설치 없이 렌더링된 K8s 매니페스트 출력|

---

### 🚀 설치 / 삭제

|명령어|설명|
|---|---|
|`helm install <release> <chart>`|Chart 설치|
|`helm install <release> <chart> -n <namespace>`|특정 네임스페이스에 설치|
|`helm install <release> <chart> -f values.yaml`|사용자 정의 values 파일로 설치|
|`helm install <release> <chart> --set key=value`|인라인으로 값 설정하여 설치|
|`helm install <release> <chart> --dry-run --debug`|실제 설치 없이 시뮬레이션 (디버그 포함)|
|`helm uninstall <release>`|Release 삭제|
|`helm uninstall <release> --keep-history`|삭제 후에도 히스토리 보존|

---

### 🔄 업그레이드 / 롤백

|명령어|설명|
|---|---|
|`helm upgrade <release> <chart>`|Release 업그레이드|
|`helm upgrade <release> <chart> -f values.yaml`|사용자 values 파일로 업그레이드|
|`helm upgrade <release> <chart> --set key=value`|인라인 값으로 업그레이드|
|`helm upgrade --install <release> <chart>`|없으면 설치, 있으면 업그레이드 **(CI/CD 필수!)**|
|`helm upgrade <release> <chart> --rollback-on-failure`|실패 시 자동 롤백|
|`helm rollback <release> <revision>`|특정 Revision으로 롤백|
|`helm history <release>`|Release의 변경 이력 조회|

---

### 🔍 조회 / 모니터링

|명령어|설명|
|---|---|
|`helm list`|현재 네임스페이스의 Release 목록|
|`helm list -A`|전체 네임스페이스 Release 목록|
|`helm list --failed`|실패한 Release만 조회|
|`helm status <release>`|Release 상태 확인|
|`helm get all <release>`|Release의 전체 정보 출력 (notes, values, manifest 포함)|
|`helm get values <release>`|현재 적용된 values 확인|
|`helm get manifest <release>`|실제 배포된 K8s 매니페스트 확인|

---

### 🗂️ Repository 관리

|명령어|설명|
|---|---|
|`helm repo add <name> <url>`|원격 Chart 저장소 추가|
|`helm repo list`|등록된 저장소 목록 확인|
|`helm repo update`|저장소 캐시 최신화|
|`helm repo remove <name>`|저장소 제거|
|`helm search repo <keyword>`|등록된 저장소에서 Chart 검색|
|`helm search hub <keyword>`|ArtifactHub에서 Chart 검색|
|`helm pull <chart>`|Chart 다운로드 (`.tgz`)|
|`helm pull <chart> --untar`|Chart 다운로드 후 자동 압축 해제|

## 💡 실무 Tip: `--dry-run` vs `helm template`

|구분|`--dry-run --debug`|`helm template`|
|---|---|---|
|K8s 서버 접속|✅ 필요|❌ 불필요|
|렌더링 결과 출력|✅|✅|
|로컬 오프라인 사용|❌|✅|
|CI/CD 파이프라인 사용|제한적|**권장**|

## 🔁 실무 CI/CD 패턴 예시

```bash
# 저장소 추가 및 업데이트
helm repo add myrepo https://charts.example.com
helm repo update

# 없으면 설치, 있으면 업그레이드 (가장 많이 씀!)
helm upgrade --install my-app myrepo/my-chart \
  --namespace production \
  --create-namespace \
  -f values-prod.yaml \
  --set image.tag=v1.2.3 \
  --rollback-on-failure

# 배포 이력 확인
helm history my-app -n production

# 문제 발생 시 롤백
helm rollback my-app 2 -n production
```
