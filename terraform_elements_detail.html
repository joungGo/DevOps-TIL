Terraform 파일 구조 & 배포 흐름 상세

각 탭을 클릭해 파일별 역할, 속성, 실무 패턴을 확인하세요.

역할: 어떤 클라우드 프로바이더를 쓸지, 버전 제약을 선언
terraform { required_version = ">= 1.5.0" # Terraform CLI 최소 버전 required_providers { aws = { source = "hashicorp/aws" version = "~> 5.0" # 5.x만 허용, 6.0 차단 } } } provider "aws" { region = var.aws_region # ap-northeast-2 }
required_version
Terraform CLI 자체의 버전 하한선. 1.5.0에서 nullable 변수, moved 블록, check 블록이 안정화됨. 낮은 버전에서 실행 시 문법 오류 방지.
source
Terraform Registry 주소. hashicorp/aws = registry.terraform.io/hashicorp/aws. 커뮤니티 프로바이더는 다른 조직명 사용.
version = "~> 5.0"
페시미스틱 제약(Pessimistic Constraint). 5.x 범위만 허용, 6.0은 차단. Breaking Change 방어. ">= 5.0"은 6.0, 7.0도 허용돼 위험.
.terraform.lock.hcl
init 실행 시 자동 생성. ~> 5.0이라도 실제로는 5.31.0처럼 정확한 버전을 고정. Git 커밋 필수 — 팀원 모두 동일 버전 보장.
.terraform/ 폴더
프로바이더 바이너리 저장. OS별로 다르게 생성되므로 .gitignore 필수. terraform init 시 자동 재생성됨.
>= 1.5.01.5.0 이상 모든 버전 허용
Breaking Change 위험 존재
~> 5.05.x 마이너만 허용
메이저 업그레이드 차단 ✓
"이런 변수를 받겠다"는 인터페이스 선언 — 실제 값은 없음
variable "node_instance_type" { description = "EKS Worker Node 인스턴스 타입" type = string default = "t3.medium" } variable "availability_zones" { type = list(string) default = ["ap-northeast-2a", "ap-northeast-2c"] }
description
terraform plan 출력 시 표시. 팀원이 변수 의미를 코드만 보고 파악. 필수는 아니지만 협업 필수 요소.
type
string / number / bool / list(string) / map(string) / object({...}) 등. plan 단계에서 타입 불일치 즉시 검출. apply 전 안전망.
default 있음
apply 시 값 입력 생략 가능. tfvars에도 없으면 default 사용. 공통 환경 설정에 적합.
default 없음
apply 시 반드시 값 제공 필요. tfvars 또는 -var CLI 인자 또는 대화형 입력. 민감한 값(DB 패스워드 등)에 적합.
💡 variables.tf vs terraform.tfvars 비유: variables.tf는 함수 시그니처(매개변수 선언), terraform.tfvars는 함수 호출 시 전달하는 실제 인자값.
역할: 변수에 실제 값을 주입 — 환경마다 다른 파일로 분리 가능
aws_region = "ap-northeast-2" project_name = "url-shortener" vpc_cidr = "10.0.0.0/16" eks_cluster_version = "1.29" node_instance_type = "t3.medium" node_desired_size = 2
자동 인식
terraform.tfvars 파일명은 Terraform이 자동으로 로드. 다른 이름은 -var-file=prod.tfvars처럼 명시 필요.
환경 분리 패턴
terraform.tfvars(dev), prod.tfvars, staging.tfvars로 분리. CI/CD에서 terraform apply -var-file=prod.tfvars처럼 환경별 적용.
gitignore 권장
DB 패스워드, AWS 계정 ID 등 민감 정보 포함 가능. terraform.tfvars.example(안전한 예시값)은 커밋, terraform.tfvars(실제값)는 .gitignore.
terraform.tfvars자동 로드
파일명 고정
-var-file=xxx.tfvars명시적 지정
dev/prod 분리 시 유용
⚠️ *.tfvars를 git에 올리면 AWS 계정 ID, 민감 설정이 공개 저장소에 노출. terraform.tfvars는 반드시 .gitignore에 추가.
역할: 실제 AWS 리소스를 정의하는 핵심 파일 (18개 resource 블록)
① VPC + DNS 설정
enable_dns_hostnames
Node에 ec2.internal DNS 이름 부여. EKS Control Plane ↔ Worker Node 통신에 필수. 꺼두면 Node NotReady.
kubernetes.io/cluster 태그
EKS가 어느 VPC/Subnet에 리소스를 생성할지 태그로 식별. "shared"(공유) vs "owned"(단독) 구분.
② Subnet + cidrsubnet()
count 메타인수
length(var.availability_zones) = 2 → Subnet 2개 자동 생성. count.index(0,1)로 AZ와 CIDR 인덱싱.
cidrsubnet(cidr, 8, idx)
10.0.0.0/16을 8비트 더 나눠 /24 서브넷 생성. Public: 0,1 → 10.0.0.0/24, 10.0.1.0/24. Private: 10,11 → 10.0.10.0/24, 10.0.11.0/24 (+10으로 충돌 방지).
kubernetes.io/role/elb=1
ALB Ingress Controller가 Public Subnet에 ALB 자동 배치하는 데 필요한 태그. 없으면 Ingress 생성 실패.
③ NAT Gateway + depends_on
aws_eip
NAT GW에 고정 공인 IP 할당. IGW가 먼저 생성돼야 EIP 할당 가능 → depends_on 명시적 선언.
depends_on
Terraform이 자동 감지 못하는 암묵적 의존성 명시. IAM 정책 완전 적용 후 NodeGroup 생성도 동일 패턴.
④ EKS Cluster + IAM
eks_cluster IAM Role
Principal: eks.amazonaws.com. EKS Control Plane이 ALB, EC2, ENI 등 AWS 서비스를 제어할 때 사용.
eks_node IAM Role
Principal: ec2.amazonaws.com. 3개 정책 필수: EKSWorkerNodePolicy(API 등록), EKS_CNI_Policy(ENI 조작), ECRReadOnly(이미지 Pull). 하나라도 누락 시 NotReady.
jsonencode()
HCL 객체를 JSON으로 변환. IAM 정책은 AWS API가 JSON만 수신. 따옴표 이스케이프 없이 깔끔하게 작성 + plan 단계 문법 검증 가능.
⑤ Managed NodeGroup
scaling_config
desired=2, min=1, max=4. Cluster Autoscaler 또는 Karpenter가 이 범위 내에서 자동 스케일.
max_unavailable=1
Rolling Update 시 한 번에 1개 Node만 교체. Node 2개 중 1개 항상 Running 유지 → 무중단 업그레이드.
역할: apply 후 중요 정보 출력 + 다른 모듈/스크립트에서 참조
output "update_kubeconfig_command" { value = "aws eks update-kubeconfig --region ${var.aws_region} --name ${aws_eks_cluster.main.name}" } output "vpc_id" { value = aws_vpc.main.id }
참조 표현식 3단 구조
리소스타입.리소스이름.속성 → aws_vpc.main.id. Terraform이 이 참조로 의존성 그래프 자동 구성. VPC 생성 후 output 계산하는 순서 자동 결정.
terraform output -raw
따옴표/줄바꿈 없는 순수 문자열. $(terraform output -raw update_kubeconfig_command) 셸 치환으로 명령 직접 실행 가능.
sensitive = true
출력값을 콘솔/로그에서 마스킹. DB 패스워드, 토큰 같은 민감 output에 적용. terraform output은 여전히 조회 가능하지만 plan/apply 화면에선 숨김.
모듈 간 참조
Module 방식에서 module.vpc.vpc_id처럼 다른 모듈의 output을 input으로 연결. 이를 통해 VPC Module → EKS Module 의존성 체인 구성.
✓ outputs.tf는 "사람을 위한 대시보드" + "다른 모듈/CI-CD를 위한 API" 역할을 동시에 수행.
역할: Pod가 AWS 서비스를 직접 호출할 수 있도록 OIDC 신뢰 체인 구성 (IRSA)
resource "aws_iam_openid_connect_provider" "eks" { client_id_list = ["sts.amazonaws.com"] thumbprint_list = [data.tls_certificate.eks.certificates[0].sha1_fingerprint] url = aws_eks_cluster.main.identity[0].oidc[0].issuer }
IRSA 신뢰 체인 전체 흐름
① OIDC Provider 등록
EKS가 발급하는 JWT 토큰을 AWS IAM이 신뢰하도록 OIDC Provider 등록. thumbprint는 OIDC 서버 TLS 인증서의 SHA-1 지문 — 위변조 방지.
② K8s ServiceAccount 생성
Pod에 ServiceAccount 연결. annotations에 eks.amazonaws.com/role-arn 지정.
③ IAM Role 신뢰 정책
Condition에 oidc.eks.../sub: system:serviceaccount:namespace:sa-name 지정. 해당 SA를 가진 Pod만 이 Role Assume 가능.
④ Pod 실행 시
kubelet이 Pod에 JWT 토큰 마운트(/var/run/secrets/.../token). Pod가 AWS SDK 호출 시 토큰으로 STS AssumeRoleWithWebIdentity → 임시 자격증명 획득.
과거 방식 (Node IAM Role)같은 Node의 모든 Pod가 동일 권한 공유
S3 접근 필요한 1개 Pod 때문에 Node 전체에 S3 권한 → 보안 취약
IRSA (현재 Best Practice)Pod별 개별 IAM Role 할당
최소 권한 원칙 적용 가능
침해 시 영향 범위 최소화
💡 STEP 7-2에서 별도 파일로 분리한 이유: OIDC Provider는 클러스터 생성 후에만 URL을 알 수 있음. main.tf에서 클러스터 생성 → iam_oidc.tf에서 클러스터 output 참조하는 순서 의존성 명확화.
Terraform 배포 명령어 7단계 상세
terraform init
Provider 플러그인 다운로드 → .terraform/ 생성. Module 방식이면 .terraform/modules/ 에도 다운로드. lock.hcl 없으면 최신 버전 설치, 있으면 고정 버전 사용. CI/CD에서 매번 실행 필수.
terraform plan
현재 state vs 코드 차이 계산 후 + / ~ / - 로 표시. 실제 AWS에 아무것도 하지 않음. PR에 plan 결과를 댓글로 게시하는 패턴이 GitOps 표준 (atlantis, terraform-cloud).
terraform apply
"yes" 입력 후 실제 리소스 생성. EKS 15~20분 소요. State 파일(terraform.tfstate)에 모든 리소스 정보 저장. 팀 환경에선 S3 + DynamoDB로 원격 state 관리 필수 (동시 apply 방지).
-auto-approve 금지
로컬에서는 절대 사용 금지. plan 확인 없이 즉시 실행 → 실수로 운영 리소스 삭제 위험. CI/CD 파이프라인에서만 허용 (PR 리뷰가 인간 확인 대체).
aws eks update-kubeconfig
~/.kube/config에 EKS 컨텍스트 추가. --alias 옵션으로 ARN 대신 짧은 이름 사용 권장. CI/CD에서도 이 명령이 kubectl 사용의 전제 조건.
terraform show / output
show: state 파일 전체 내용(AWS 콘솔 대체). output: outputs.tf에 선언한 값만 출력. output -raw: 셸 스크립트에서 직접 활용.
terraform destroy
state 파일 기준으로 모든 리소스 역순 삭제. EKS + NAT GW 방치 시 하루 $7+. 실습 후 반드시 실행. 의존성 순서 자동 계산(NodeGroup → Cluster → IAM → Subnet → VPC 순).
Remote State 관리 (실무 필수)
terraform { backend "s3" { bucket = "my-tf-state" key = "prod/terraform.tfstate" region = "ap-northeast-2" dynamodb_table = "tf-lock" # 동시 apply 방지 Lock encrypt = true } }
💡 로컬 tfstate는 팀 협업 불가 + 분실 시 인프라 관리 불능. S3(versioning 활성화) + DynamoDB(LockID 기반 분산 락)가 팀 협업의 필수 패턴.
⚠️ Module 방식(terraform-aws-modules/vpc, eks)은 직접 작성 대비 코드량 80% 절감. 단, 내부 동작을 이해한 후 사용해야 디버깅 가능. 이 문서가 직접 작성부터 시작하는 이유.
